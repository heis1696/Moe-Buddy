# API 预设与桌宠对外交流入口：讨论整合

> 日期：2026-10-10。状态：讨论整合，不是已实现功能或施工授权。本轮只整理文档，不运行网关、不接真实模型或 QQ、不新增原文持久化，也不修改 Rust 功能代码。
> 当前记忆能力见 [记忆施工计划](AGENT-MEMORY-PLAN.md) 和 [上下文契约](MEMORY-CONTEXT.md)；会话时效、原文暂存及后台整理的专项规则以 [会话设计](GATEWAY-SESSION-DESIGN.md) 为准。

## 1. 产品定位

**对外地址是「桌宠的对外交流入口」，不是普通模型转发代理，也不是在模型回答后统一润色一次。**

用户在桌面聊天、QQ 艾特或其它支持相应协议的客户端里，选择同一个稳定桌宠，即进入同一个 Agent 运行层。桌宠根据自己的身份、人设、获准记忆、与说话者的关系、当前场景和能力处理请求；API 预设只是它使用的上游模型与服务。

更换模型、供应商或密钥不更换桌宠身份，不清空关系和经历；接入新渠道也不另造一只人格相似但记忆独立的机器人。共用 Agent 不等于所有渠道拥有相同读取或工具权限。

## 3. 三类配置分开

| 配置 | 负责什么 | 不负责什么 |
| --- | --- | --- |
| API 预设 | 上游协议、Base URL、凭据、模型及供应商扩展参数。 | 桌宠身份、关系、记忆归属、入口授权。 |
| 桌宠 Agent 配置 | 稳定实例、人设、记忆访问、获准工具、表达策略与用途绑定。 | 向所有调用方公开供应商密钥，或把模型文本当运行权限。 |
| 网关与渠道配置 | 本地服务入口、调用方凭证、允许的桌宠别名、渠道身份、会话映射、输入输出契约。 | 由外部请求自填主人身份、越权读取记忆或开启工具。 |

### 3.1 API 预设保留的功能

- 预设的稳定 ID、显示名称、协议、端点、凭据与默认模型。
- 多预设管理，以及聊天、生图、人设访谈、视觉、语音等不同用途的绑定。
- 供应商特有请求参数的配置与合法性校验；不能让扩展参数绕过宿主控制的身份、上下文和工具边界。
- 可用性检查、错误与实际生效预设的说明。缺失、悬空引用及失败回退的逐用途规则，需要在实现规格中列清，不能将所有功能统一成隐式跨供应商切换。

这是保留产品能力，不是照搬旧 TypeScript 配置结构或历史实现。新的凭据保存/导出方式、协议识别与参数合并优先级仍需定案；预设切换不能默默扩大数据发送范围。

### 3.2 入口示例

以下只是地址和桌宠选择的拟定形态，不表示本机已有监听端口：

```text
Base URL: http://127.0.0.1:17860/v1
API Key: <Moe-Buddy 签发的调用凭证>
Model: buddy/xiaomeng
```

`buddy/xiaomeng` 是入口公开的桌宠路由别名，不是上游模型名称，也不构成授权。调用凭证决定允许访问哪些别名和能力；桌宠内部再选择获准用途对应的 API 预设。

建议首版仅提供本机入口；局域网或公网暴露另定认证、加密和运维范围。本机入口也不能以「仅 localhost」代替鉴权。入口凭证与供应商 API 密钥分开，真实上游密钥不交给外部调用方。

## 4. 协议适配不等于 Agent 本身

内部先定义统一 Agent 对话入口，再在外围适配 OpenAI 风格请求、QQ 事件和桌面交互。不能把内部能力全部压进某一种外部协议。

建议的兼容接口包括 Chat Completions 请求入口，以及供客户端选择获准桌宠别名的模型列表；Responses、其它供应商协议、多模态、结构化输出和工具调用的具体覆盖按目标客户端定案。不支持的能力必须明确拒绝，不静默忽略后宣称兼容；不能承诺任何工具都能接入。

外部请求经过身份、桌宠、会话和输入校验后才成为受信运行请求。客户端传入的 system/developer 文本、模型别名、自定义参数、工具列表和用户标识都不直接成为宿主人设或授权。

会话必须有明确绑定。客户端能否传递会话标识需要适配验证；缺少可靠标识时默认请求隔离，不根据文本相似或最近使用的桌宠猜测合并。完整历史重传与本轮新增事件必须区分，文本相同本身不能证明是重试。

## 5. 一次请求的统一链路

```text
桌面聊天 / QQ 艾特 / 外部 API 客户端
                  ↓
入口鉴权、桌宠绑定、说话者验证与会话隔离
                  ↓
原文暂存登记 + 即时会话状态更新（不做模型提炼）
                  ↓
人设 + 获准记忆 + 近期原文 + 当前任务与能力
                  ↓
API 预设 → 模型推理 / 经授权的工具流程
                  ↓
任务结果返回原渠道 + 按策略发出桌宠表现事件
                  ↓
登记实际回复、回执与完成 / 失败 / 取消状态
                  ↓
闲时固定批次 → 提炼候选 → 服务校验 → 记忆提交
```

桌宠身份、人设和相关记忆从请求开始参与处理，不默认先生成裸模型答案再额外调用一次模型「扮演桌宠」。复杂任务可另议分工，但不能以二次润色替代真实 Agent 运行与记忆治理。

## 6. 结果与表现双通道

| 通道 | 输出职责 |
| --- | --- |
| 任务结果 | 按调用方契约返回聊天文本、代码、JSON、工具调用或结构化错误。 |
| 桌宠表现 | 台词、表情、动作、语音、进度和完成反馈；由桌宠宿主或原生客户端消费。 |

普通聊天时两者可以自然合并；程序要求严格 JSON 或代码时，不因人设在结果前后添加台词。兼容响应不擅自夹入动作字段或破坏流式格式，表现事件走独立通道。

同一个 Agent 不意味着所有后台请求都让桌宠发声。建议按调用方配置静默、完成后汇报或完整互动，并服从全局勿扰及表现预算；具体动作/语音协议仍未实现。

工具说明不等于工具执行许可。调用方声明的工具默认不能变成本机可执行工具，执行归属与权限必须明确；模型提出调用、应用执行及收到结果是不同阶段。只有真实成功回执才能支持「已经完成」，失败、取消或未知结果不能伪造成功或盲目重发。

## 7. 短期记忆：暂存与会话工作状态

归属仍是 private / shared，生命周期仍是 short / long；暂存区不是第三种一级归属。

| 职责 | 保存或引用什么 | 是否需要模型提炼 |
| --- | --- | --- |
| 原文暂存区 | 收到的消息、实际发出的回复、必要回执、发言者/渠道/会话/事件元数据与终态。 | 不需要；正文不改写、不摘要，不每轮拆解。 |
| 会话工作区 | 近期原文引用、当前话题/任务的获准上下文、确定性的渠道与活跃状态。 | 渠道和活跃状态不需要；不能把模型推断冒充已确认状态。 |
| 治理后的长期记忆 | 经候选审查、来源/版本/权限校验的事实、关系、经历或知识。 | 可使用模型提议，但实际提交由受信服务裁决。 |

「原封不动」只针对交互正文，不包括密钥、鉴权头和未展示的内部推理。原始历史、注入的记忆、模型回复、引用他人发言和真实用户新输入必须保留不同来源，不能循环提炼出自我证明的事实。

### 7.1 会话时效

- 默认从最后一次有效用户交互起保留 30 分钟连续会话状态，新有效交互滑动续期。
- 桌宠发言、工具回调、摘要、整理、检索命中、心跳、重试及历史重传均不续期。
- 截止时间到即失效；之后的新消息开启新片段，不自动注入旧片段原文。到期不等于删除原文或取消已经获准的在途任务。
- 活跃状态按桌宠、渠道、群/私聊和读取主体等会话维度隔离；不存在唯一的「用户目前只能在 QQ 聊天」全局开关。
- 当前请求的渠道由可信接入事件确定，回复始终返回该请求目标，不因其它会话更活跃而改投。
- 重启不直接恢复旧活跃判断；原文是否恢复另按留存授权处理。撤权、删除和会话撤销立即生效，不等待 TTL。

30 分钟是可调整的产品默认值，不是平台限制。精确时间边界、单调时钟与多渠道规则见 [会话设计 §3](GATEWAY-SESSION-DESIGN.md#3-会话时效默认规则)。

## 8. 闲时批处理，不按问答次数提炼

默认会话至少安静 3 分钟、相关交互已终结且前台资源/整理预算允许时才可调度。不必等待 30 分钟活跃窗口到期，也不承诺第 3 分钟准点执行。高负载时排队与背压，不能为每轮回复启动一次提炼。

同一会话串行整理，不同会话受全局并发约束。每个任务固定已完成事件区间、实际来源与版本水位；新消息继续追加，不进入在途批次。实际提交得到确认后才推进处理水位，部分成功的重试按逐候选幂等收口。

原文纠正、删除、撤权或任务取消后，迟到整理结果不得写回。处理成功不自动清空原文；活跃到期、原文留存到期、整理确认和物理清理分别管理。具体容量、留存时间和失败重试预算仍需定案。

提炼输出先成为候选：私密事实/经历进入受控私密提交；可复用知识也不能因为「看起来通用」就自动共享，仍走独立发布审查。模型说过某事只能证明它说过，工具成功必须有真实回执。

## 9. 权限与隐私底线

- 共用桌宠不等于共享全部私事；同一用户跨渠道必须有可信身份绑定，其他 QQ 用户和群成员不能自动成为主人。
- 入口调用权、记忆读取权、模型传输权、共享发布权和工具执行权分别校验，不互相推导。
- 当前读取仍只放行离线用途；接真实模型前必须定义哪些来源可发送至哪个预设，不能将 OfflineReasoning 当作 ModelTransmission 授权。后台提炼如调用外部模型也受同样边界约束。
- 外部提示词、扩展参数和模型输出不能更改受保护身份、正式协议或宿主权限。
- 临时原文与上下文不自动长期保留；现行明文日志、备份和已交付快照边界不因新入口而扩大。

## 10. 已有能力、缺口与待定项

**已有底座**：Rust 记忆门面、私密/共享隔离、ShortTerm/LongTerm 生命周期、会话工作上下文、来源与精确版本、取消栅栏、持久化回执、受控共享及请求上下文投影。它们不是已经交付网关或后台学习的证明。

**尚缺运行模块**：新 API 预设管理与供应商适配、入口认证和会话适配、统一 Agent 运行层、原文暂存与可恢复证据契约、闲时整理协调、QQ 接入及表现事件接线。保持封装和单向依赖，网络/渠道/存储实现不能反向进入纯记忆核心；是否拆新 crate 另按实际施工范围决定。

当前含工作上下文的任务禁止持久化派生。实现整理前必须明确可持久化交互证据及生命周期转换，不能通过删除保护判断把临时上下文直接写成长久事实。

需要后续定案：

1. 首批接入哪些客户端，以及 Chat Completions/Responses 等协议的具体覆盖、会话标识传递方式和不支持能力的错误契约。
2. 预设的字段/凭据保存、用途绑定、缺失回退、扩展参数边界与模型传输授权。
3. 原文暂存的恢复方式、保留期限、容量、备份/清理政策及故障/满额行为。
4. QQ 接入方式、跨渠道身份绑定，以及群聊/私聊的披露与执行权限。
5. 服务随应用运行还是独立常驻，是否允许远程访问；后者不能默认开启。
6. 模型/工具循环、流式取消、结果未知、费用/并发限制及表现事件协议。

本次完成的是讨论整合，没有已批准的下一施工阶段，不自动启动接线、后台学习或新增留存。
