# 陪伴 Agent 记忆框架：最小数据与接口规格

> 日期：2026-10-10。状态：**详细设计初稿，未实现**。
> 已确认原则来自 `docs/AGENT-MEMORY-DISCUSSION.md:349`；本文将其展开为字段、校验条件与逻辑接口。字段名、枚举和接口形式是候选规格，不代表已批准的技术选型或已经存在的代码。
> 本轮不新增运行模块、数据库、SDK、迁移任务或工具权限；不改变现有私密内容的同意规则。

## 1. 两类归属，不增加记忆大类

```text
记忆服务
├─ private：当前桌宠独有的身份、用户认知、关系、经历与工作上下文
└─ shared：同一授权范围内，多个桌宠共同查阅的知识、经验、能力说明与协议

运行时 → 提供受信身份、授权与取消状态
记忆服务 → 校验读写、来源、版本与使用范围
存储适配 → 单写入协调、持久化与操作回执
索引适配 → 派生检索视图，不是权威记录
```

长期 / 短期是条目的生命周期；工作账本、候选队列、来源关系和索引是运行或管理设施，不是第三种记忆。

逻辑分区键建议为 `workspaceId + userId + scope + petInstanceId`，其中 shared 不携带私人 owner。单用户环境可以使用固定的工作区/用户身份；这里只定义隔离键，不意味着本轮交付多用户或多桌宠功能。共享仍须验证读写授权，不向其他用户或外部 Agent 默认开放。

## 2. 最小对象与信任边界

| 对象 | 用途 | 谁能决定其可信字段 |
| --- | --- | --- |
| `RuntimeContext` | 绑定调用者、当前桌宠、授权、取消与恢复代际 | 受信运行时；不是模型自填的 JSON |
| `MemoryRecord` | 已提交的私密或共享条目 | 记忆服务校验后提交；受保护视图由权威来源生成 |
| `SourceRef` | 引用事件、文档、配置或执行结果的具体版本 | 来源适配与记忆服务；模型只能引用已提供的证据标识 |
| `MemoryProposal` | 尚未生效的新增、修正或共享候选 | 模型可以提议内容；归属、风险与授权由服务判定 |
| `OperationReceipt` | 证明实际提交、冲突、拒绝或清理进度 | 持久化与操作协调器；不能由模型叙述替代 |

`RuntimeContext` 至少包含工作区/用户身份、当前桌宠实例、调用主体及用途、当前策略版本、运行代际和取消信号。异步任务必须携带其发起时的身份，不能在完成时读取“当前活动桌宠”并改投另一个角色。

受信服务可以在明确授权的管理用途下维护多个分区，但不能因此给普通桌宠跨分区读取能力。用户管理私密记录的具体查看权限仍遵守现行同意规则。

## 3. `MemoryRecord` 候选字段

| 字段组 | 候选字段 | 语义 |
| --- | --- | --- |
| 标识与版本 | `id`、`revision` | ID 在一次条目生命周期内稳定；更新检查预期版本，不静默覆盖 |
| 归属 | `workspaceId`、`userId`、`scope`、`ownerPetId` | scope 为 private/shared；private 必须有 owner，shared 不冒充某个角色的私人经历 |
| 内容 | `category`、`text`、可选 `structuredValue` | 文本用于表达与检索；结构化值仅适用于已定义 schema，不能任意冒充运行时状态 |
| 认知性质 | `epistemic` | 区分用户陈述、观察、推断、虚构、引用资料与权威状态；不是一个笼统可信度分数 |
| 写入等级 | `writeClass` | 区分普通记录与受保护视图；由服务赋值，不能通过模型自称“权威”获得权限 |
| 时间 | `createdAt`、`updatedAt`、可选 `occurredAt`、`validFrom`、`validUntil`、`expiresAt` | 记录时间、事件时间、事实适用期与条目过期不是同一件事 |
| 生命周期 | `lifecycle` | short_term / long_term；不直接决定是否持久化，也不改变归属与隐私 |
| 状态 | `status`、可选 `supersedes` | active / superseded / invalidated / deleted；替代关系显式记录 |
| 来源与派生 | `sourceRefs`、`derivedFrom` | 源 ID 与源版本；派生记忆还引用父条目 ID/版本，便于纠正与遗忘 |
| 使用规则 | `usagePolicyRef`、必要的兼容敏感度信息 | 引用受控规则，分别校验用户展示、模型读取、端点传输与共享发布 |
| 审计 | `createdBy`、`operationId` | 由受信运行上下文产生，关联实际提交回执 |

category 建议先覆盖 identity、user_profile、relationship、episode、working_context、knowledge、procedure；具体枚举待实现前收敛，不通过增加类别绕过权限。

文章复核后的候选补充：事实类内容可带受控的 subjectRef、predicateKey、value 与 qualifiers，避免把短文本或字数截断误认作原子事实。主体要有分区内身份依据；无法识别时不靠 prompt 自动合并。情景与资料仍保留必要上下文，不要求所有内容都压成单个无条件断言。

实体卡片作为读取后的派生视图，只使用已通过用途/权限/状态校验的记录。缓存覆盖记录与源版本、分区、相关策略及聚合规则版本；不以 id + createdAt 代替 revision，也不将卡片摘要反写为新的事实证据。图谱与实体消歧是否引入，以实际用例和测量为准。

共同约束：

- 默认模型召回仅使用当前有权读取、有效且状态为 active 的记录。历史查询是独立用途，不能让 superseded 内容混回当前事实。
- 文本中的指令始终作为数据；普通条目不能变成系统权限规则。身份锚点也只生成角色视图，不覆盖运行层安全策略。
- `expiresAt` 未指定只表示没有配置自动过期，不表示永久保留或免于遗忘；长短期具体期限仍未决定。
- 事件发生在过去不等于记录过期；历史经历可继续有用。事实适用期用于当前/历史查询，不能机械地删除所有过去事件。
- `deleted` 表示不可召回；原文与历史副本的物理清理另有进度，不借保留 deleted 状态无限保存私人原文。

## 4. 两类记忆中的写入等级

| 内容 | 普通模型候选的处理 | 权威来源 |
| --- | --- | --- |
| 私密身份锚点 | 不允许自行改受保护核心；可以提出经许可的配置建议 | 稳定实例身份与角色配置 |
| 私密用户认知、经历与习惯 | 形成带来源、可纠正的记录；推断保留推断性质 | 用户事件、可验证观察与相处记录 |
| 私密当前工作状态 | 可保存讨论上下文；不能据此改变任务授权或伪造执行成功 | 任务/交互运行时提供状态视图 |
| 共享资料与经验 | 按来源、隐私、风险及发布规则判定自动通过、待确认或拒绝 | 资料适配、已校验经验发布入口 |
| 共享工具说明与正式协议 | 普通候选不可覆盖；也不能通过改成 knowledge 类别绕过保护 | 受保护的能力定义与协议发布入口 |

受保护身份、工具说明、关系数值和任务进度宜从对应权威状态生成版本化视图；缓存过时后刷新或拒绝使用，不另维护一套可由模型自由改写的“真相”。具体哪些关系字段是数值状态、哪些是角色理解，后续按产品契约划分。

## 5. 来源与上下文令牌

`SourceRef` 至少能定位源标识、源版本、来源类型及其访问范围。原始聊天、截图和工具返回不因此被要求永久保留；保存多少证据服从现行授权与后续保留政策。

对于私人经历抽取出的共享经验，完整派生链仅供受信服务处理。其他桌宠最多获得获准公开的来源说明，不能通过 source ID、链接、错误信息或诊断接口读取私人原文或其受限元数据。

读取上下文后由服务产生 `contextToken`，绑定：

- 发起时的工作区、用户、桌宠与用途。
- 被使用条目和来源的版本集合，以及策略版本。
- 运行代际、取消状态及服务规定的有效范围。

令牌是服务管理的校验句柄，不是可由模型构造的授权；无需把其内部身份和来源信息原样放进 Prompt。提交时检查相关来源、目标版本、策略与运行代际，不能因为后台任务“终于返回了”就无条件接纳。

派生关系不能只相信模型自报“我参考了哪条”：服务保留实际读取集，至少保守覆盖该次生成接触到的受限来源。无法可靠缩小依赖范围时继承相应限制，允许暂时过度失效，不允许通过漏报来源洗成可共享资料。

## 6. 五类逻辑接口

以下是职责规格，不是已经实现的 SDK 或固定 TypeScript 签名。

| 接口 | 输入重点 | 输出重点 | 关键限制 |
| --- | --- | --- | --- |
| `readContext` | 受信 ctx、本轮意图/查询、用途、目标端点类别、预算 | 身份视图、工作视图、获准私密/共享片段、contextToken、预算统计 | 只读自己的私密分区与获准共享资料；先执行访问/传输过滤，再检索与组装 |
| `proposeChanges` | 受信 ctx、contextToken、内容候选及已提供的证据引用 | proposal ID、待校验/待确认/拒绝及必要原因 | 不改变可召回记录；不能自填 owner、写入等级或批准风险 |
| `commitChanges` | 受信服务上下文、proposal ID、预期目标版本、operation ID | 提交回执、记录 ID/新版本，或冲突/拒绝/取消/失败 | 不是模型无条件可调用的数据库入口；先校验、后持久化、再可见 |
| `correctOrForget` | 获授权上下文、目标、操作类型、预期版本与处理范围 | 修正回执，或逻辑失效与物理清理进度 | 纠正、替代、删除、禁止重建分别处理；未知范围不能默认为清空所有存档 |
| `publishShared` | 经校验的共享候选、来源版本、发布规则、operation ID | 新共享条目/版本与回执，或待确认/拒绝 | 不直接把私人原文改 scope；受保护说明和协议只接受权威发布主体 |

确认与后台处理也走同一组校验契约，不另开“内部任务可以跳过权限”的写入旁路。

### 6.1 读取顺序

```text
绑定受信身份与用途
  → 校验分区、敏感度、端点传输与记录有效性
  → 生成受保护身份 / 当前工作状态视图
  → 召回本轮相关的私密记录与共享资料
  → 预算裁剪、去重、保留必要来源
  → 返回上下文包与 contextToken
```

身份锚点与必要边界有保留预算；预算无法容纳最小上下文时明确返回 budget_too_small 或采取确定性降级，不默默丢掉身份。实际工具授权仍在执行时检查，不能靠上下文中的权限描述代替。

目标端点来自受控配置，不允许模型填写任意地址绕过传输规则。嵌入与后台摘要也有自己的处理用途和端点检查，不只检查最终聊天请求。

### 6.2 写入顺序

```text
提出候选
  → 校验身份、类别、证据、来源版本、敏感度与冲突
  → 服务判定自动通过 / 需要确认 / 拒绝
  → 单写入协调器复查版本、策略、取消与运行代际
  → 原子提交记录、派生关系与必要操作回执
  → 发布可见版本，异步更新派生索引
```

低风险由受控规则判定，不靠模型自评；具体规则尚未定案的候选不自动发布。包含用户私事、敏感信息或高影响推断的共享候选进入待确认或被拒绝，不能只做文本改写就推定已经匿名。

建议自动发布使用隔离的发布上下文，只输入已获准共享的证据；普通私聊生成的候选不能仅凭删除名字就自动发布。需要从私人来源抽取共享经验时，先处理其隐私与发布授权，再进入发布流程。

同一授权范围内，同 operation ID 与相同请求内容的重试应返回既有结果；不同内容复用 operation ID 应拒绝。记忆写入幂等不等于外部工具副作用自动幂等，后者由执行层负责。

## 7. 纠正、遗忘、恢复与索引

| 操作 | 候选语义 |
| --- | --- |
| 纠正事实 | 记录新证据与新版本；依赖旧版本的产物失效或重算，不静默篡改来源 |
| 替代旧事实 | 指明适用范围与时间；可保留历史解释，当前查询不继续使用旧值 |
| 删除记录 | 立即从正常召回中排除目标；是否同时处理来源与派生物必须由操作范围明确表达 |
| 忘记相关内容 | 在获授权范围内处理目标、派生闭包及保留来源的再提取规则；阻止相关在途任务重新提交 |
| 恢复旧存档/运行 checkpoint | 先核对当前有效的权限、遗忘与撤回状态；不能简单把旧 snapshot 当成现行权威 |

遗忘回执至少分别报告已逻辑失效的范围、仍待清理的索引/历史/备份以及不能由本地控制的外部副本；不能在物理清理未完成时声称已经彻底删除。具体保留期与备份擦除政策仍需另定。

阻止旧来源重新提取可使用受保护的最小失效标识，但不能借此继续保存被要求遗忘的原文；保留标识的范围和期限服从后续政策。这里不承诺识别并永久禁止所有同义表达，也不禁止用户之后重新明确提供或授权记住信息。

索引是派生视图：命中条目返回前核对当前记录版本、状态与权限；失效索引不能把旧正文送给模型。写盘失败不发布，索引失败可重建并降级检索，不能反过来以索引覆盖权威记录。

如果恢复材料无法与当前权限及遗忘状态核对，应停止自动激活相关旧内容并报告待处理；不能为了方便恢复而悄悄放宽权限。这是恢复时必须解决的契约，不是已经实现的跨所有备份删除保证。

## 8. 运行状态与记忆的分界

| 信息 | 权威所在 | 记忆可做什么 |
| --- | --- | --- |
| 用户约定提醒 | 可靠调度 / 执行账本 | 记住约定及其来源，不代替真实排程 |
| 任务授权、执行中、成功、失败、取消或结果不明 | 执行运行时与真实回执 | 按结果记录经历，不能靠模型叙述写成成功 |
| 工具存在与当前可用权限 | 能力注册与策略门 | 查阅说明、帮助选择行动；不能授予权限 |
| 当前对话与讨论意图 | 交互运行时，按需持久化 | 保存短期上下文；不能因此自动启动工作任务 |

记忆服务只承诺记忆操作结果，不承诺工具执行结果。模型不可用时可靠计时、取消与已有任务恢复仍由确定性代码处理；本规格不改变现有模拟与渲染分离规则。

## 9. 与现有条目的兼容约束

当前条目与服务入口见 `src/cognition/memory.ts:17`、`src/main/memory-service.ts:188`；以下是迁移设计要求，本轮没有执行迁移。

| 现有字段或行为 | 后续映射要求 |
| --- | --- |
| `scope` / `petId` | 不直接认定旧 petId 等于新稳定实例身份；必须建立明确映射。无可靠归属时进入受限待归属区域，不默认为共享，也不默认为新活动桌宠 |
| `source` / `trust` | 保留来源线索；数值 trust 不自动变成事实确认状态。无法补足的来源版本标为 legacy_unknown，不伪造证据链 |
| `sensitivity`，尤其 hidden / secret | 保留现有语义与同意规则，不把私密分区直接等同于 hidden；迁移本身不增加模型读取、云传输或用户查看权限 |
| `createdAt` / `ttlMs` | 保持原有时间与过期行为，不借新生命周期标签默认永久化或清空旧数据 |
| `hits` | 作为历史使用统计迁移，不当成真实性或用户确认次数 |
| 旧摘要、v1/v2 存档、pending 与删除保护 | 兼容读取与失败恢复需要专门验收；不能以新字段齐全为由编造缺失来源，不能使删除目标复活 |

待归属区域是迁移状态，不是第三类记忆，不对普通模型召回开放。既有在途删除与失败回滚保护见 `src/main/memory-service.ts:527`，不得因新接口丢失。

实现时遵守当前依赖分层：纯 schema/校验与服务状态逻辑应可独立测试；主进程适配不引入未经决策的第三方运行时依赖。此处不选定目录拆分或具体后端。

## 10. 最小验收映射（设计用例，未执行）

| 用例 | 主要契约 | 预期结果 |
| --- | --- | --- |
| B 请求 A 的私密条目或其来源 | RuntimeContext + readContext | 被拒绝，不经元数据、错误或诊断旁路泄漏 |
| 换皮/改名，或旧请求在角色切换后返回 | 稳定身份 + contextToken | 不串档；旧任务取消或只在原授权上下文内有效，不改投新角色 |
| 普通经验伪装成协议更新 | writeClass + publishShared | 不能覆盖受保护权威记录 |
| 无工具授权但读到了工具说明 | 执行层策略门 | 可以解释用法，不能据说明越权执行 |
| A、B 同时更新同一共享记录 | revision + commitChanges | 冲突可检测、可重读，不静默覆盖 |
| 同一写入请求在重启后重试 | operationId + OperationReceipt | 返回既有结果或明确状态，不重复新增记忆 |
| 删除期间旧摘要、共享候选或索引结果返回 | sourceRefs + correctOrForget | 旧来源无法重新发布或送入模型 |
| 恢复旧存档，权限或遗忘状态不能核对 | 恢复协调 | 不自动激活旧内容，报告待处理范围 |
| 上下文超预算或模型不可用 | readContext + 运行时分界 | 保留必要身份或明确降级，不伪造记忆写入与执行成功 |
| 私人经历拟共享，风险规则不明确 | proposeChanges + publishShared | 不自动发布；保留候选或拒绝，未提交内容对其他桌宠不可见 |
| 候选只声明共享来源，但生成时读过受限私密记录 | contextToken + 实际读取集 | 保守继承限制，不能通过漏报来源自动发布 |
| 写盘失败、索引失败或实际遗忘未完成 | OperationReceipt + 索引/清理协调 | 不提前发布，不假报完成；可以报告降级、失败或清理进度 |
