## 2. 首版交付与非目标

首版目标：

- 按稳定桌宠实例身份读写私密记忆，查阅获准的共享资料；用两个逻辑实例验证，不要求先上线多宠窗口。
- 模型只产生候选，服务完成证据、归属、权限、版本、取消和持久化校验。
- 身份锚点、事实/推断与情景分开；可以按本轮意图读取有界上下文，而非无条件堆历史。
- 纠正、遗忘、卡片/索引失效与迟到写入防护形成闭环。
- 兼容旧档与现有记忆入口，逐步替换，不一次拆掉聊天、养成或表现层。

非目标：开放任意工具、引入多 Agent 调度平台、自动训练人格、全量关系图、云端记忆 SaaS、全新记忆 UI 或动画重构。记忆底座完成不等于完整自主 Agent 已交付；持续意图与受限行动循环另定实现范围。

## 3. 初始技术建议与安全默认

1. **先做自己的薄契约，不绑定 LangChain/Letta/Mem0。** 它们提供机制参照，后续若引入也只能作为适配，不能反过来决定归属和隐私。
2. **首个后端建议使用 Node 内置文件适配。** 复用现有原子写风格，将记录、来源依赖、必要候选/回执与失效状态放进可原子提交的版本化 envelope；文件名和格式最终在对应批次定稿。首次实现不引入数据库或主进程第三方运行时依赖。
3. **先分区过滤与简单检索，再看是否需要向量。** 索引失败可以条目级降级，不能回滚已提交权威记录或回灌旧正文。
4. **未定政策不阻塞离线施工，也不默认放行。** 不新增模型端点、上传路径或自动清理期限；低风险规则不明确的共享候选保持待确认/拒绝。通过规则的低风险自动发布链仍需实现与测试。
5. **初期不生产双写。** 对照仅使用测试夹具或已授权样本；旧、新存储不能同时独立接受生产修改，以免形成两套真相。
6. **身份不是素材包名。** 先定义实例身份创建、持久化与恢复，再迁移归属；不能把不明旧记录默认绑定给当前活动宠。

本地文件适配是本计划的建议，不是承诺所有私密内容永不上云；现有同意制不变。未来云端策略、加密及备份政策另定，不能据文章直接开启。

## 4. 施工批次与验收门

所有批次当前均未开工；每批过门后才进入下一批。文件名为建议写入范围，不代表已经创建。

### M0：契约、身份与回归基线

- 启动施工时先运行现有 `npm run check`，记录基线结果；不把未运行写成通过，不修无关故障。
- 拟新增 `src/shared/agent-memory.ts`：纯类型、解析/校验、分区键、受保护字段、版本与操作结果。
- 拟新增 `src/cognition/agent-memory-policy.ts`：纯读写策略，不依赖 DOM、Node 或 Electron；受信运行身份与模型候选参数分开。
- 建立 A/B 两个实例、同名同文、不同敏感度与来源性质的夹具；为事实定义受控主体、谓词、值和条件，情景保留必要上下文。
- 新 smoke 使用现有 esbuild 临时目录模式并挂入 `check`。

验收：伪造 owner/authority 被拒，私密和共享形状不能混淆；未经明确验证的旧 source 不能自动升级成用户事实。生产入口仍不改动。

### M1：持久化、来源与受控提交

- 拟新增 `src/main/agent-memory-persist.ts` 与 `src/main/agent-memory-service.ts`：本地适配、单写入协调、候选、来源依赖、revision/CAS、operationId 回执。
- 同授权范围同 operationId 的相同请求幂等，变更 payload 的复用拒绝；源版本、目标版本与运行代际复查。
- 写盘成功后再发布可见状态；容量与坏档错误明确报告，不静默删旧记录或当作新空档。
- 来源可能受限时保守记录实际读取集，不让模型漏报来源成为共享旁路。

验收：并发乱序、重复提交、写盘失败、提交前后重启均不丢旧数据、不假报成功；不同分区的同文记录不互相覆盖。暂不接生产模型和自动分享。

### M2：读取、身份视图与实体卡片

- 拟新增 `src/cognition/agent-memory-context.ts`，必要时拆出 `src/cognition/agent-memory-entities.ts`：按用途/端点过滤、有效性、预算、相关性组装。
- 受保护身份与实时权威状态以视图进入上下文；普通资料不能成为系统权限。只记录可观察结果与必要决策摘要，不要求保存模型隐藏思维链。
- 卡片先聚合受控实体与明确主体；未知别名不自动合并，冲突连同条件/时间保留。卡片不反写为独立事实。
- 缓存绑定分区、记录/来源版本及策略和聚合规则版本，不能只用 id + createdAt；召回前复核有效性，失败退回条目。

验收：A 不能读 B；同名角色不被合并；同 ID/创建时间但不同 revision 的修正会失效旧卡片；预算有界，身份不足明确降级。此时仍使用夹具验证。

### M3：纠正、遗忘、取消与恢复

- 拟新增纯生命周期模块，定义事实替代、有效期、源失效、派生闭包和遗忘范围；模型不能直接执行无限范围删除。
- 已失效内容先从读取中排除，再报告物理清理进度；旧摘要、卡片、索引、候选与在途任务同步处理。
- 延续隐藏/热更/退出取消、重启 pending 终结、删除不复活与失败回滚；具体状态兼容现行契约。
- 恢复旧 checkpoint/备份先核对现行权限与失效状态；无法核对不自动激活，不声称能够追回外部副本。

验收：源被删除或纠正后，乱序返回结果不能重建旧内容；TTL、归档和用户删除行为不同；归档持久化失败不删除原件。保留期与备份期限未定的部分明确标待处理，不假报彻底清理。

### M4：共享发布与旧档迁移适配

- 实现受保护资料同步、共享候选发布与隔离的发布上下文；正式工具说明/协议不可经普通经验覆盖。
- `canPromoteToShared` 只能是旧资格参考，不替代发布授权。来源无法证明可共享，或风险规则不明确时不自动发布。
- 拟新增 `src/main/agent-memory-migration.ts`：显式实例归属映射、旧敏感度/TTL 保留、缺证据标 legacy_unknown，未知归属隔离。
- 新格式与旧 `memory.json` 分开管理迁移状态；新库存在却损坏时不得偷偷回退旧档、复活删除内容。保留可核验回执和受限恢复路径。
- 不从 source='chat' 直接推定用户发言；旧摘要缺来源时不能伪造派生链。涉及无法追溯的遗忘范围需保守失效/隔离并说明限制。

验收：共享读写分级、正式协议保护、敏感候选拦截、迁移幂等、坏档保护和授权不扩张。未经迁移策略确认，不激活真实旧档迁移。

### M5：生产接线、管理与全链验收

- 以 `src/main/memory-service.ts` 为兼容入口逐步接新服务；旧 `src/main/memory-persist.ts` 保留受控读兼容，不整体删库重写。
- 接线核查覆盖聊天、事件、视觉/宿主来源、内心/摘要、回忆模板、设置管理及重置，不只替换聊天 Prompt。
- `src/cognition/brain.ts` 只处理获准上下文，不反向 import main；`src/main/index.ts` 负责注入受信身份和适配。后台任务仍走同一校验门。
- 回忆模板也执行展示策略，不能绕过 hidden 同意制；面板不扩大用户可见范围，日志不默认输出私人正文。
- 仅在迁移与回滚前提可验证时切换生产权威写入；回滚不能绕过新权限或重新开放旧删除记录，必要时保持只读恢复而非继续双写。

验收：下节全部用例与现有回归通过，`npm run check` 通过；有可用 GUI 环境再执行 `npm run e2e:memory`。未验证的真机行为单列，不能用静态源码断言替代。

## 6. 验证与回归要求

- 每个新增运行模块自带 smoke，并按 `scripts/boot-check.mjs` / 现有 smoke harness 的 esbuild 临时目录模式挂入 `package.json` 的 check。
- 先跑新增针对性 smoke，再跑相关既有测试：`smoke:memory`、`smoke:memory-service`、`smoke:memory-sources`、`smoke:life`、`smoke:inner-mind`、`smoke:cognition`、`smoke:scene-source`、`smoke:chat` 与交互/取消相关 smoke。
- 每批结束运行 `npm run check`，不省略类型、分层、主进程依赖纯度、构建与 boot 门；不将缺 GUI 的 E2E 写成通过。
- 不执行文章安装脚本、不新增云凭据、不读取个人生产聊天作为默认夹具，不扩大截图、模型传输或记忆权限。

## 7. 建议的第一单与后续边界

**首单只做 M0：纯类型、校验、策略与双实例夹具 smoke。** 不改生产 memory-service，不迁移用户数据，不接模型、不新增数据库。验收后再接 M1 本地持久化，避免先接生成再补权限与遗忘。

已确认的两类归属与受控写入原则不再重复讨论；存储建议、具体类型、低风险规则、迁移交互及实施启动仍需按本计划确认范围。当前只完成研究与施工规划，不自动接力开工，也不把后续 Agent 行动循环纳入本单。
