# 记忆、人设与 Agent：设计接管重点拆解（2026-10-09）

> 当前工作区基线 `9ae5bb7`。本轮只做源码分析与设计汇报，不修改功能、存档、AGENTS.md 或 PLAN 决策。
> 外部机制依据已有固定版本拆解，并只读复核主检出中的 AAAAGENT、Cyrene、Cortico 部分关键源码；不是上游最新版本普查，也没有运行参考应用。旧报告里的“本项目缺失”不直接沿用。
> 本文“建议”均供用户重新设计时选择，不构成新增路线图或重构开工令。

## 0. 总判断：这三件事必须连起来，但不能混成一个 Prompt

| 系统 | 应负责的事 | 不应被误认为 |
| --- | --- | --- |
| 记忆 | 区分事实/推断/角色设定，留下来源、时间、归属，决定存什么、取什么、何时失效 | 把聊天变短、把所有文本放进向量库 |
| 人设 | 定义“它是谁”、哪些性格稳定、如何表达、如何对待用户和选择行为 | 一段越长越好的性格描述，或赋予工具权限的许可证 |
| Agent | 观察事件、判断是否行动、选择受限动作、执行/等待确认、根据结果更新状态 | 定时调用模型，或让多个模型互相聊天 |

理想闭环是：**事件 → 识别与判断 → 根据身份/关系选择行动 → 权限检查 → 执行与回执 → 只把合格结果沉淀为记忆**。记忆影响后续选择，人设约束长期倾向，但两者都不能绕过权限闸门。

## 1. 记忆：重点参考六种不同解法

### 1.1 横向拆分

| 参考 | 真正解决的问题 | 关键机制 | 借鉴与代价 |
| --- | --- | --- | --- |
| AAAAGENT | 聊天、陪伴事实、工作记录如何不串；后台处理如何不写入过期结论 | 三类记录分离；来源版本校验；后台按角色串行；上下文逐候选计算预算，返回选入/遗漏 ID | 先学“边界和有效性”，而非 SQLite 本身。其产品仍硬编码单角色，按角色设计的接口不等于已支持多宠 |
| Akane | 一轮对话包含工具调用、观察、回复，如何完整记录并可追溯 | 统一时间线；turn 生命周期；工具 correlation_id；完成轮次才提交可见投影/元数据；保留真实 provider 输出 | 最适合未来工具型 Agent 的事实账本。MemCore 内核不在源码快照，不能把宿主门面研究当成完整可移植内核 |
| Cyrene | 怎样长期认识用户，而不是只背诵近期聊天 | L0 稳定画像、L1 近期目标/偏好/项目、L2 事件；Memory Judge 保守写入；证据引用、冲突与替代状态 | 最适合用户画像与“少记错”。其完整检索/激活系统复杂，不必同时搬入 BM25、向量、实体图和全部衰减公式 |
| Alife | 超长历史如何逐级压缩，还能找回原始信息 | 分级压缩；Analyze/Apply 两阶段与锚点校验；存档文件 + 索引；按需读取/搜索旧档 | 适合长期规模化存档，不等于懂得区分用户事实、短期状态与角色内心。摘要层级和记忆语义类别是两个维度 |
| Cortico | Agent 如何有可维护的认知工作区，在线行为与后台整理如何分权 | 常驻/活跃/归档 memo；人物/世界观/人格文件；main/dream 权限矩阵；种子只初始化一次 | 适合持续人格与可编辑认知。具体 persona 的 dream 能改人格内容；是否允许模型改核心性格，不能直接照搬 |
| Miru | 长期知识、人格与聊天后台整理如何分工，删除如何终结在途写入 | human/persona 核心记忆、归档槽、日记；Sleep Agent 批处理；Persona Writer；删除终结未整理账目 | 适合用户可控记忆和后台任务生命周期。多个 Writer 是职责分工，不要求每个都成为常驻独立 Agent |

### 1.2 最值得采用的不是某个库，而是四条规则

**第一，事实必须有身份和证据。**

- “用户明确说自己是设计师”“模型猜测用户可能是设计师”“桌宠角色设定里它自己是设计师”是三种不同信息，不能合并为一个文本条目。
- Cyrene 对 L0 的写入不是只相信 Prompt：候选后过滤要求 explicit + user_explicit，并拒绝证据未支持的绝对化表达。
- Akane 的工具记录通过 correlation_id 配对；工具请求、工具结果与最终语言不能只靠消息物理相邻猜归属。

**第二，稳定事实、近期状态、共同经历应有不同寿命。**

- “希望叫我小林”适合稳定档案；“这周在准备面试”适合阶段状态；“昨天一起完成了报告”适合情景记忆。
- 情绪/关系评估应允许时间衰减与不确定，不应直接升格为“用户就是这样的人”。
- 过期、归档、遗忘是不同动作：暂时不注入不等于删除数据；压缩不等于确认事实。

**第三，纠正与遗忘要追到派生产物。**

- 删除一条记录、纠正一个事实、要求“彻底忘掉这件事”不能默默使用同一个语义。
- 旧事实可能已进入摘要、画像、关系日志或在途任务；真正的事实纠正需要替代链/来源关系，遗忘还需要防止从保留历史重新提取。
- AAAAGENT 的来源版本、Miru 的终结账本、Akane 的时间线来源覆盖，分别提供不同层面的参照。

**第四，召回要解释“为什么这轮需要它”。**

- AAAAGENT 会记录 selected/omitted ID；Cyrene 保留证据和冲突状态，均比“取最热的几条”更便于审计。
- 注入次数、相关性、重要性、真实性不是同一个指标。常被塞进 Prompt 的内容不因此更真实，也不一定与本轮有关。
- 可以先保留简单关键词检索，但应先定义对象归属、证据与状态，再决定是否需要语义向量。

### 1.3 本项目当前已经有什么

- 分段记忆有 source、trust、sensitivity、createdAt、ttlMs、hits、scope、petId；每条最多 300 码点；不是原始的一大段字符串。见 `src/cognition/memory.ts:17`。
- 召回按 hits + 新近度 + 关键词加成；每库最新条目保底，按预算装填。命中数统计的是“被注入”，不是用户确认或实际使用成功。见 `src/cognition/memory.ts:220`、`src/cognition/memory.ts:243`。
- 支持聊天/事件/视觉/内心等来源，以及摘要、管理面板、私密条目与删除；删除会处理包含该条或使用该条上下文的在途摘要，写盘失败也会回滚。见 `src/main/memory-service.ts:527`。
- secret 不进入模型上下文；hidden 则可以进入并影响言行，面板默认不显示原文。这两种隐私语义已经不同，不能统一叫“私密记忆”。见 `src/cognition/memory.ts:11`、`src/cognition/memory.ts:286`。
- 由上面的注入和请求链可推导：若使用云端模型，选中的 hidden 内容也会随请求发给该端点；面板锁定不是“不上传”或加密承诺。这是当前调用链的条件性结论，不是对所有部署的外传事故认定。

### 1.4 当前不足在哪里

1. **语义类型不够清楚**：source='inner' 可以标出生成来源，但 schema 没有独立的“用户事实/模型推断/角色虚构/共同经历”类别与证据引用。
2. **归属尚非严格隔离**：petId 字段已存在，但当前注入筛选没有按活动 petId 做身份过滤；scope 分库不等于多角色隔离。见 `src/cognition/memory.ts:286`。
3. **摘要来源没有在产物中显式保存**：当前摘要成功后 append 的主要是 text + source='summary'，没有把该批源 ID/源版本存入条目。因此“在途删除不复活”已处理，不等于“已生成摘要能按来源级联纠正”。见 `src/main/memory-service.ts:386`。
4. **热度有反馈偏置风险**：hits 不按时间衰减，反复选入会持续增大分数；关键词加成是固定增量。这里是从计分公式推导出的设计风险，不是已量化的用户效果。见 `src/cognition/memory.ts:220`。
5. **私密展示出口并未只经过模型**：回忆选片允许 hidden，模板模式能直接拼片段，存在与“由模型决定分享”规则冲突的源码路径；本轮未做真实气泡复现。见 `src/cognition/memory.ts:310`、`src/main/intent-runtime.ts:83`。

## 2. 人设：身份、性格、关系与当下状态要分开

### 2.1 不同参考的人设，其实不是同一种对象

| 参考 | 人设形态 | 最值得参考 | 不应混淆 |
| --- | --- | --- | --- |
| Cortico | 模板、机制说明、运行时人格/认知工作区分离；种子只在缺档时创建 | 包升级不覆盖相处形成的运行数据；谁能修改哪些人格区域有机械权限 | 这是特定 persona 的可变人格策略，不是必须把核心性格交给后台模型改写 |
| Akane | 各流水线的 Prompt 配置 + 可演化人格卡 + 素材/台词角色包 | 人格卡字段化；活动卡、熟悉的其他模样与切换日志；表达与资源清单一致 | Prompt variant 是 router/final 等职责配置，不是不同角色；人格侧面也不等于多个独立角色身份 |
| Miru | 核心记忆分 human/persona；后台 Persona Writer 整理 | “如何认识用户”和“它如何理解自己”分开 | 模型总结用户与模型修改自身性格都需要边界，不能因为自动化就算真实成长 |
| Alife | 角色 Prompt + 模块能力集合，热切换原地替换 system 人设 | 角色切换不重复堆 system；能力目录可组合 | 人设包指定 Modules 不应自动获得执行权限；角色描述与真实授权必须分开 |
| AAAAGENT | 固定产品角色身份、角色 Prompt、表现预设与工作边界 | 角色/轮次身份携带进异步处理；虚构开场不当真实记忆来源 | 重点是身份与来源纪律，不是已经实现丰富的动态人格卡系统 |

证据入口：`docs/research/COGNITION-DESIGN.md:89`、`docs/research/COGNITION-DESIGN.md:95`、`docs/research/COGNITION-DESIGN.md:99`、`docs/research/REFERENCE-AKANE.md:74`、`docs/research/MEMORY-AUTONOMY.md:181`。

### 2.2 本项目不是“只有一个人设文本框”

当前已有五种实际载体：

1. **人设文本**：cognition.config.persona，作为模型提示词的稳定前部。
2. **人设采访**：六维访谈、例句、身份与关系/说话风格/互动倾向/边界，明确不让人设夹带宿主输出格式或虚报能力。见 `src/shared/persona-interview.ts:38`。
3. **个性化本地台词**：根据人设生成台词集，落盘成功才更新，模型不可用时继续本地表达。见 `src/main/persona-lines-service.ts:49`。
4. **自拟内心**：口癖、小习惯、第一印象/期待、小秘密，写为 inner + hidden；这是角色生成内容，不是关于现实用户的已证实事实。见 `src/shared/pet-inner-mind.ts:55`、`src/main/memory-service.ts:488`。
5. **行为气质参数**：素材包 temperament 控制互动敏感度、烦阈值、忽略率、回复延迟、关系门槛等；这是真正影响模型之外行为的性格面。见 `src/shared/pet-temperament.ts:13`。

问题在于它们尚不是一个完整的“角色身份档案”：文本人设来自全局配置，行为参数随素材包，内心在记忆服务，关系又是运行态。换包时可能更换行为气质，但不能由此推导已创建新角色、换了人设文本或开了独立记忆档案。

### 2.3 建议采用的四层人设（待决策）

| 层 | 例子 | 建议的修改权 |
| --- | --- | --- |
| 稳定身份与核心边界 | 它是谁、自称、与用户的基本关系、不接受的互动 | 用户明确修改；模型只能提议，默认不自动覆盖 |
| 持续气质与表达习惯 | 慢热/主动、句长、口癖、喜欢的互动、冷却偏好 | 用户设定；允许有边界的适应，但可查看、撤销、锁定 |
| 关系与共同经历 | 从相识到熟悉、共同玩笑、下次想问的事 | 从合格事件更新，保留来源与时间，不能只靠模型随口自评 |
| 当下状态与任务模式 | 今天困、刚被抛起、用户在专注、正在守护 | 运行时短期状态，不回写为永久人格 |

**“高冷但相处久了更愿意关心”是关系变化；“相处久了变成另一种完全相反的角色”是核心人格改写。两者的产品许可不同。**

身份也应与外观分开讨论：换外观可以仍是同一个它，创建另一个角色才开新身份；或者由你定义其他规则。素材包可以携带默认人格种子，但包更新不应默认覆盖用户已形成的角色档案。

### 2.4 人设必须约束行为，不能只修饰台词

如果文本写“安静、不主动打扰”，实际意图池仍按原有规则频繁邀聊，最后一句再写得高冷，不会产生一致人格。

建议让同一份角色档案分别生成“模型表达约束”与“可测的行为偏置”，本地台词、模型台词、动作选择都共享该身份版本；权限与经济副作用仍由硬规则控制，不由人设决定。

此外，当前人设宏支持把时段展开进 persona；若使用 `{time_of_day}`，它就不是完全稳定的 system 前缀。聊天易变信息后置的优化仍有价值，但不能仅凭段序声称缓存永远稳定或已节省特定费用。见 `src/main/scene-source.ts:88`、`src/cognition/brain.ts:106`。

## 3. Agent：先区分陪伴自主性、工具行动与外部代理协作

### 3.1 四类能力不能用一个“Agent”词包办

| 类型 | 核心问题 | 参考 |
| --- | --- | --- |
| 对话反应 | 用户说话后如何记得、表达、取消、恢复 | AIRI/Open-LLM-VTuber；本项目 chat 通道 |
| 自主陪伴 | 此刻是否值得主动行动、该做什么、不回应时如何收手 | Cortico、Miru、Alife、Cyrene |
| 工具型行动 | 如何提出计划、调用获授权工具、读取真实结果、据结果继续或停止 | Akane；Cortico 的受限工具循环 |
| 外部工作代理协作 | 只观察状态，还是能创建草稿、确认发送、接收结果 | clawd-on-desk、AAAAGENT、openpets |

ZZZ 的多宠场景协调可参考超时、代次、回执，但它不是多个 LLM Agent；多个角色窗口、多个模型请求通道也不自动构成多 Agent 系统。

### 3.2 自主性最值得拆的三个机制

**Cortico：被唤醒不等于必须说话。** 外部事件合批、心跳退避、计划唤醒和显式静默共同组成节奏；Agent 可以处理输入后结束而不打扰用户。其价值是“观察与输出解耦”，不是把定时器换个名字。

**Miru：注意力判断与最终表达分开。** AttentionEngine 产出 topic/why_now/care_motive 等 speak_intent，不直接发消息；去重、优先级、过期之后再交主 Agent 表达，并在交付前后重检抑制条件。重要的是“为什么现在值得关心”，以及用户开始聊天后旧主动消息要失效。见 `docs/research/MEMORY-AUTONOMY.md:53`、`docs/research/MEMORY-AUTONOMY.md:72`。

**Alife：用户输入与系统自触发分开。** 阶梯随空闲变稀，只有真人输入重置；自己发消息不能给自己续命。采样还区分冷却、防抖、过期，避免同一画面重复触发。见 `docs/research/COGNITION-DESIGN.md:132`。

Cortico 证据见 `docs/research/COGNITION-DESIGN.md:140`。以上都不意味着每次判断都要调用一个新模型；是否拆模型角色应由实际质量、成本、延迟决定。

### 3.3 工具与工作代理：最重要的是权责，不是“会调很多工具”

**Akane** 的关键是统一回合引擎、显式工具轨迹与结果配对，Skills 按需加载，发布成功后后续调用看到新目录。Skill 是操作知识，不因此授予权限；可执行能力是否启用仍由宿主控制。见 `docs/research/REFERENCE-AKANE.md:86`、`docs/research/REFERENCE-AKANE.md:123`。

**AAAAGENT** 把链路拆成：输入路由 → 工作卡计划 → 用户确认 → 抢占发送资格 → 发送/查询回执。Router 明确不是 executor，任务规划不执行任务；unknown 不自动重发，较迟的 unknown 不能覆盖已完成结果。它不会代用户审批工作代理的系统操作。见 `docs/research/REFERENCE-AAAAGENT.md:165`、`docs/research/REFERENCE-AAAAGENT.md:170`、`docs/research/REFERENCE-AAAAGENT.md:177`。

**clawd-on-desk** 最适合“桌宠陪着你工作”：hooks/日志补充 → 会话身份与事件归一 → 状态仲裁 → 可见反应。看见 IDE 打开不能当成 Agent 正在执行，观察任务也不等于拥有执行权。见 `docs/research/REFERENCE-NEW-AGENTS.md:41`。

**openpets** 主要提供平台/插件/MCP 能力合同和受控宿主副作用，不是自动获得陪伴人格与长期关系。见 `docs/research/REFERENCE-NEW-AGENTS.md:120`。

### 3.4 当前本项目处于什么位置

- 对话脑有 autonomous/event/greet/chat 四类输入通道；一次 speak 组装上下文、请求模型、解析结构化表达，允许自主轮沉默。见 `src/cognition/brain.ts:22`、`src/cognition/brain.ts:252`。
- 主动意图先做资格、冷却、权重与额度判断，再选择模板或 LLM 现编；当前计划的动作/意图主要由程序侧决定，模型侧侧重表达。见 `src/main/intent-runtime.ts:72`。
- 内心生成、台词生成、摘要、静默结算等是辅助模型职责；不能把若干通道当成已交付可独立规划、持有工具和长期目标的多 Agent 系统。
- 外部宿主契约与 mock 在 test/，不参与生产构建；不能把契约测试当成真实 AgentDeck 工作转交已接通。见 `test/README.md:1`。

因此，当前更准确的描述是：**受规则仲裁的单宠陪伴系统，包含模型表达和若干后台认知任务；不是完整的通用工具执行 Agent，也不是多角色独立认知系统。** 这不是否定已有能力，而是明确后续改造起点。

## 4. 我建议的组合方向（候选，不按项目整体搬家）

| 设计域 | 首先借的思想 | 保留本项目什么 | 不默认引入什么 |
| --- | --- | --- | --- |
| 记忆建模 | Cyrene 的保守画像/状态；AAAAGENT 的边界与版本；Akane 的来源账本 | 现有分段、删除在途失效、原子落盘、用户管理 | 向量数据库、授权内核或另一套完整后端 |
| 人设与角色档案 | Cortico 的种子/运行数据分离；Akane 的字段化侧面；Miru 的 human/persona 区分 | 采访、个性台词、内心、temperament、关系状态 | 模型任意改核心人格；换素材自动新建或抹掉身份 |
| 自主陪伴 | Miru 的 why_now/去重/交付重检；Cortico 的合法沉默；Alife 的输入来源区分 | 可测意图仲裁、免打扰、低成本模板回退 | 每拍都调 LLM，或每种职责一个常驻 Agent |
| 工作协作 | 先 clawd 的真实事件因果；需要发送时再用 AAAAGENT 的草稿/确认/回执边界 | D3 草稿与执行权限分离、主进程安全边界 | 自动批准命令、任意插件执行、把工作正文全塞进陪伴记忆 |

逻辑上可拆成四个责任域：**身份档案、记忆与证据、注意力/行为决策、动作执行与权限**。这是职责边界建议，不等于要立即创建四套进程或四个 Agent；现有 Electron/Pixi 与纯函数分层约束不因此失效。

## 5. 设计接管时最先拍板的七个问题

1. **它长期记住什么？** 用户事实、共同经历、情绪判断、任务资料分别到哪层；是否允许永久记住模型推断？
2. **谁是谁？** 外观包、角色身份、人设版本、用户与记忆归属如何区分；换包是换装还是换一个它？
3. **哪些性格能成长？** 核心人格是否锁定；关系、口癖、偏好由谁改，是否可审阅/撤销？
4. **“秘密”究竟是什么权限？** UI 不展示、模型可用、可自主分享、不可上传、不可进入工作工具，应分开定义。
5. **它能自主到哪一步？** 自己挑小动作、自己选择关心话题、提出提醒，还是能够制定并执行多步工作计划？
6. **用户的忽略/拒绝意味着什么？** 只增加冷却，还是记成偏好？哪些反馈可以形成长期关系判断，如何避免一次不回复就贴标签？
7. **工作助手占多大权重？** 只看任务状态，能整理草稿，还是确认后能交给执行 Agent；结果如何回到陪伴表达而不污染事实库？

建议先定第 1、3、5 题，即“记什么、什么会成长、能自主做什么”；角色身份规则必须在引入多角色前定下。答案确定后才评估是否需要大重构，不以某个参考的复杂度倒推本项目必须照搬。

## 6. 后续方案的验收例子（不是本轮已执行的测试）

- 用户说“假如我是医生”：不得写成用户职业；用户明确说“我在做设计”才进入有来源的事实候选。
- 用户先喝咖啡，后说“这段时间不能喝”：短期禁忌覆盖当前建议，不粗暴删除历史偏好，更不把临时限制写成永远不喝。
- 用户纠正或要求忘记一事：在途摘要不复活，既有画像/摘要按已定义的纠正或遗忘合同处理；普通单条删除与全局遗忘分别验收。
- 更新素材/模板：用户已有角色档案不被种子覆盖；换角色按明确定义的身份与隔离规则取记忆。
- 模型生成一个角色小秘密：不得成为真实用户事实，不经许可进入共享库或工作任务正文；每种展示出口都遵守同一权限。
- 宠物刚想主动邀聊，用户开始聊天/免打扰/隐藏：旧主动意图和迟到文案作废，不抢话，也不因自己发言重置空闲阶梯。
- 人设写“慢热安静”：本地行为频率、模板台词和模型表达都能呈现一致倾向，不只把固定高频邀聊改成冷淡语气。
- 工作发送超时：显示未知并允许核对真实任务，不自动重发；计划卡、权限确认、真实执行状态与陪伴回复各有边界。
