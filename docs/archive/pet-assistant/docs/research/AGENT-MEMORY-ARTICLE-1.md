## 0. 摘要

文章《AI Agent 记忆系统工程：四层架构、Mem0/Zep/Letta/LangMem 生产选型与 2026 最新进展》试图同时解释记忆分类、框架选择、遗忘、安全和上线节奏。可借其问题清单，不能将产品宣传、示例或研究存在本身视为适合桌宠的证据。

保留四条机制：有来源的受控写入、事实变化可追溯、检索与执行授权分离、即时形成与后台整理分工。工作/情景/语义/程序性可以作为用途或内部表示，不改变 private/shared 两类归属；长短期也不直接决定存储方式。

领队修正五处：CAMS 原论文列五层而非博客三条概括；Letta blocks 示例属于 V1，不能据此概括当前全部 SDK；KV/文件也能是权威后端；追加写入本身不保证权限、幂等或原子性；既定设计没有“全部私密绝不上云”的禁令，不能据此否定所有网络适配。

建议先做版本化本地记录、来源链、授权读取与纠正遗忘，再做实体卡片；复杂图谱和外部记忆服务不作为首版前置条件。营销收益、价格、榜单和四阶段工期不进入本项目验收标准。后台模型先提出候选，服务通过明确规则才提交；不是每条候选都必须弹窗，也不是模型自称低风险就可共享。

## 2. 框架与论文：借机制，不绑定产品

| 对照 | 一手资料支持的机制 | 本项目的取舍 |
| --- | --- | --- |
| LangGraph | 会话 State/checkpointer 与跨会话 Store 分工；Store 用可自定义 namespace 组织记录 | 可借运行状态与长期记录分离。namespace 是组织原语，不自动构成每桌宠权限门；不能把跨会话读误当跨宠共享 |
| LangMem | 语义/情景/程序性用途，热路径与后台两条形成路径 | 用途分类与归属正交；生成候选和校验提交分开，后台同样受版本与权限约束 |
| Graphiti/Zep | 时间相关事实、关系与来源 episode，支持失效和历史变化 | 可借来源版本、事实有效期、保留变更历史；不因能查历史就忽略删除义务，也不将其图结构变成首版依赖 |
| Letta | V1 提供 human/persona memory blocks；官方 V1/V2 对照区分 blocks 与 MemFS 等机制 | 借稳定身份与按需上下文分工，不照搬可自由改写全部人设或权限的做法；不能拿 V1 示例代表全部现行 SDK |
| Mem0 等记忆产品 | 产品接口、提取算法、计费与开源/托管边界需按具体版本核对 | 原文的选型表不是我们的依赖授权；不据历史文章直接接入服务或承诺效果 |
| CAMS | 论文公开摘要明确提出五层，并在临床场景评估 | 借写入门控、来源和审计的工程方向，不把博客三条概括等同论文原架构，也不外推临床数字到陪伴场景 |

CAMS 的五层按公开摘要为：来源驱动的信任评分、信念一致性检查、重验证闸门、显式衰减/保留策略、跨会话边界执行。它不是我们数据模型的规范来源；不能把自动遗忘公式直接当作用户删除或保留政策。

## 4. 应改造后采纳的工程规则

1. **追加不等于可信。** 新记录和替代关系都要校验证据、分区、版本、取消与幂等；权威写入成功后才发布回执。旧版本不能静默覆盖新版本。
2. **存储与索引分工。** 文件/KV 可承载权威记录，向量或关系索引可以是派生视图。索引失败则降级或重建，不回滚已提交权威数据；权威持久化失败才不发布。
3. **状态不是遗忘公式。** 事实替代、过期、归档和用户删除分开；排除检索不代表物理销毁。源失效要联动摘要、卡片、候选和在途任务。
4. **后台不是第二写入口。** 后台先生成候选，提交仍过统一服务门；明确规则下的低风险写入可自动完成，不明规则不默认放行。
5. **共享不等于搬运私密。** 服务依据实际读取集、来源许可与风险判断发布。普通程序性经验可走发布门；正式工具说明与协议走受保护权威入口，不必为此强制分表。
6. **召回不是新证据。** 读取旧记忆、生成卡片或重复摘要不能提高真实性、续期或洗掉来源；工具执行成功只能由运行时回执证明。
7. **网络与本地依赖是两件事。** 不引入第三方主进程运行时依赖，不等于所有 HTTP 适配被禁止。当前不新增上传去向；私密内容沿用现有同意制，未来策略另定。
