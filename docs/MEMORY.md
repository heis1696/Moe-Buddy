## 生命周期与取消

### M3.1 状态与范围

| 操作/状态 | 生效行为 | 恢复/保留边界 |
| --- | --- | --- |
| 纠正 `update` | 同 ID、CAS 升版，保留归属/创建时间，旧版本边失效 | 仅 Active 且未过期；不得丢失已有依赖、降低敏感度或取得受保护身份 |
| 替代 `replace` | 同一命令原子创建新 ID，旧 ID 升版为 Superseded(new_id) | 独立验证新来源/敏感度；旧记录不能更新/解归档；到期事实可在此显式换证据重建 |
| 有效期/Expired | 宿主时间达到 expires_at_ms 即失效，逐次读/任务交付复验 | 不自动执行清理或写盘；注入过去时间不是可信当前时间，宿主负责时钟真实性 |
| 归档 Archived | 升版、保留正文、排除读取 | 只准显式 restore_archive 升版，来源/依赖/期限仍须有效；不复活旧版本派生 |
| 删除 Deleted | 删除指定 ID 的当前核心正文，留下本宠 ID/版本元数据墓碑 | 无还原入口，不复用 ID；日志明文仍保留，不递归物理删除后代或其他范围 |

status 仅返回本宠的存储元数据，不扩展用户查看权限。Active 但来源/依赖无效的记录仍被保留，is_available 为 false；它不是已删除。状态报告始终不声称物理擦除。普通管理不获得跨宠、共享或 Restricted/受保护内容删除权。活跃/保留记录上限 10,000，删除墓碑上限 100,000，覆盖旧日志成功操作上限；拒绝超限，不丢弃历史。

敏感度按 Normal → Private → Restricted 只允许保持或收紧；长期记录更新、工作上下文更新及依赖继承共用转换校验。工作上下文允许 Restricted 同级更新，但仍不可检索；长期 Restricted 记录仍拒绝普通管理，也不能作为派生证据。工作上下文降级被拒绝时不改正文、版本、时间水位、配置或缓存，不取消已有任务；合法收紧会使旧任务失效，后续检索及实体视图不得返回被收紧为 Restricted 的正文。该修复不新增解除限制或共享发布权限。

### M3.2 证据与派生闭包

- RecordVersion 为精确 ID + 版本。候选的 with_dependencies 最多 32 个不重复边，来源必须包含每个父记录全部来源，不能降低敏感度；仅依赖获准范围内可用普通长期记录，拒绝循环、跨归属、隐藏共享、短期/工作类别或受保护父项。
- 迭代遍历传递闭包，逐个检查版本、状态、期限、来源撤权及性质；祖先纠正、替代、归档、删除、到期、源升版或撤权后，后代记录和声明这些边的会话上下文不可读，实体缓存重建/降级。仅逻辑失效，不扩大删除范围。重建需显式新版本/新条目，旧边不能自行恢复。
- 原始会话陈述可以仅绑定原始来源；复制/提炼记录必须由受信宿主记录实际依赖，不能冒充原始证据。身份视图仍只用本宠私密权威来源，不从普通记录生成或升权；撤权/源升版后需重新安装当前权威视图和策略。
- 当前不实现任意会话到会话、会话到长期的自动提炼。含工作条目的任务允许离线读取/取消，持久化派生明确拒绝，避免日志恢复不存在的运行时证据。以后必须先定义可持久化证据及生命周期转换。

### M3.3 撤权与显式恢复

来源撤权针对完整分区/来源 ID/当前版本，读、写、上下文、身份、派生和旧任务一并封闭。来源登记不准绕过撤权；restore_source 必须匹配撤权版本并严格升版，性质不变。旧来源引用、白名单和视图不自动复活；内容重新核验与新精确授权由宿主明确提交。

revoke_access 安装更高版本拒绝策略，并清除该身份上下文、身份视图及缓存，保留本次运行的版本水位。上下文/身份显式 remove 还会升版留运行时墓碑。重新许可需要更高版本配置；不能复用旧配置快照。这些配置和水位不写日志，重开后默认拒绝，宿主必须重新认证，而非从历史命令恢复许可。

### M3.4 在途任务

begin_task 在授权之后捕获实际选中读取集、可用身份锚点、完整身份/会话/用途、策略和配置版本、全库存储代际、不透明运行实例标记及发行时间。宿主使用迟到结果前 validate_task；派生新条目 create_from_task 在提交点再次复验，强制所有实际来源并自动加入记录边。

每个成功存储/来源/管理命令推进全库代际，cancel_tasks 用预期代际 CAS 显式取消。任意运行配置改变也取消旧任务；保守全库栅栏允许无关写入造成额外取消。校验失败不推进，同请求幂等重试不推进。无写入的期限变化通过重新检索比较捕获。重开有新不透明运行实例标记，重装同版本策略也不能让旧任务新提交。

提议命令包含查询、范围/层、条数/字符预算、会话、代际、策略/配置版本、发行时间、身份版本、实际条目版本和自动补边前的原始候选依赖列表，供完整请求幂等比较。propose_create 不是批准；execute 保留不透明实时任务证明并复验运行实例、实际授权/读取集和配置栅栏。解码不恢复实时证明，即使存储/配置计数相同也不能跨实例执行。命令相等性只比较 wire 请求，不表示实时权限相等。宿主不能把序列化命令当作可跨重启恢复的新在途任务，恢复命令仅限日志里已提交的状态。

成功请求的完全相同 operationId/payload 可确认历史回执，即使后来删除/撤权/重开也不重做操作；异 payload 明确冲突。未成功的新请求必须通过当前运行标记及栅栏。取消仅表示不接受后续受保护交付/提交，不表示停止线程、网络请求、远程服务或已交付副本。

### M3.5 命令与持久化

日志外层保持 v1，排他文件锁、来源版本/CAS、完整请求 operationId、追加日志、文件同步后发布/回执不变。原命令 v1 的字节/tag 0–3 保持不变；有依赖的 create/update 和新管理命令使用 v2。v2 draft 在来源表后追加 u64 依赖数及 ID/版本对，上限 32；tag 4–10 为归档、解归档、替代、来源撤权、来源恢复、取消、栅栏新建。未知版本/tag、截断、尾字节或长度越界拒绝，解码保留原版本。

受信 replay 仍校验归属、来源、CAS、依赖、管理状态及存储代际，但不安装读取许可或恢复旧运行标记。历史 v1 曾合法接受到期后的纠正，这类已提交帧保留原语义；实时更新不能通过此路径续命。坏档不自动修复，完整不确定帧重新验证并同步后可确认，半帧保档拒绝。任何写盘不确定失败封闭所有 M3 入口，不能继续用旧内存提供读取、撤权或管理结果。

### M3.6 清理声明

deletion_boundary 报告：物理擦除 NotPerformed；日志 HistoryRetained；备份 PolicyUndetermined；外部副本 Unmanaged；已交付快照 NotRecallable。失效缓存、堆内存及历史快照可能残留正文；不零化、不压缩/覆盖日志、不扫描备份、不自动扩大清理范围。查看和传输政策未定也不因管理功能而放行。

FileSynced 仍仅表示文件同步屏障通过。Windows 新文件名突然断电的目录耐久性、防恶意完整旧日志替换/回滚、备份治理及物理擦除不作保证。完整当前日志的恢复闭环不能被表述成上述安全保证。



## 共享发布

### M4.1 两种独立入口

| 路径 | 输入与权限 | 结果 |
| --- | --- | --- |
| 普通共享经验 | `MemoryTask::propose_shared` 产生不可变 `SharedCandidate`；宿主逐候选审查，再用 `prepare_shared_publication(candidate, now_ms)` 批准 | shared / Normal / LongTerm 的 Knowledge 或 Procedure，非权威、非虚构、非受保护记录 |
| 正式能力/协议资料 | 宿主 `prepare_formal_publication`，修订用 `prepare_formal_revision` 与预期记录版本 | shared / Normal / LongTerm 的受保护 ToolDefinition 或 Protocol，性质仅 Reference |

`PublicationPolicy::allow_sources(version, sources)` 是精确共享来源版本白名单，不是批准每个模型候选。普通发布许可按稳定 `PetIdentity` 安装；正式资料许可按 `Namespace` 单独安装，互不继承。读许可、另一宠或另一分区的发布许可均不能代替写许可。缺省及 `deny_all` 均拒绝；政策版本必须严格推进，失败不改配置或代际。

批准是宿主对这一份不可变候选的显式动作，不代表交付审批 GUI、自动事实核验或模型批准权。根、身份/会话/用途绑定、来源登记、配置、命令编解码/执行/重放、CRUD 和批准接口全部仅属于受信宿主，不能注册为模型工具。候选仅提供只读正文、来源、依赖、任务和提议时间访问器；Debug 不输出正文或查询。

低风险自动发布规则仍未定。`prepare_automatic_publication` 始终返回 `AutomaticPublicationDisabled`，没有打开自动发布的配置；安装来源白名单也不改变它。

### M4.2 实际读取集与防洗白

候选绑定 M3 的不透明实时 `MemoryTask`，不是模型自报的引用清单。每条实际读入的持久化记录都自动补精确 ID/版本依赖，全部实际来源必须已在候选中；漏报任一来源直接拒绝，不能通过登记新的共享来源洗白。依赖继续校验完整祖先闭包、精确来源版本、生命周期与敏感度。

本阶段不提供私密到共享的解密级/脱敏升级通道：实际读取集中只要有 private 记录（即使 Normal 且引用共享来源）、会话工作条目、受保护正式资料或可用的私密身份锚点，就拒绝普通共享候选。候选也不得声明私密/跨用户/跨工作区来源、私密依赖、Private/Restricted 敏感度、短期生命周期、人设/用户档案等私事分类或权威状态。宿主审查不能绕过这些硬边界。

任务只证明该次宿主发出的读取结果及捕获的身份视图，不能观察宿主在库外另外塞给模型的文本、其他检索结果或外部 I/O。宿主必须把一次候选计算隔离到对应完整任务输入，不得用“干净空任务”替换已读入私密资料的真实任务。来源登记和 Normal 分类也必须由宿主真实核验；本库不是语义敏感信息检测器，不能保证恶意宿主或虚假源登记下的保密。

提议时间和批准/提交时间由宿主注入：批准接受独立 `now_ms`，不得倒退，按当前时间重新读取与比较实际集合，迟到审批遇到到期同样拒绝。批准后宿主应在该注入提交时间立即执行/提交，不能排队后把旧时间谎报为当前时间；核心没有系统时钟或外部 I/O。若需延迟，按实际提交时间重新审批。原提议时间、原始候选依赖和最终提交时间均保留在完整 wire 请求中。

### M4.3 正式资料不是运行权威

正式入口仅接受宿主登记的本分区共享 Reference 来源，禁止普通记录依赖、短期/私密候选或 AuthoritativeState。它用于导入宿主审核过的能力说明、协议文档，不是把普通提炼输出换标签提升为权威。受保护标记由服务生成；普通 CRUD/归档/替代/删除不能修改共享正式资料。

修订同 ID 必须匹配分区、原分类与预期版本，时间不倒退，不能为已到期文档清除期限续命；来源必须重新核验。每次成功发布或修订推进持久化全库代际。普通经验当前仅追加发布，不新增共享编辑、删除、查看或传输权限。

正式资料通过 `RetrievalLayer::FormalMaterial` 显式检索；默认 All/LongTerm 仍仅返回普通记忆，不混入正式文档。正式层沿用相同用途、分区、全来源白名单、有效性和字符/条数预算。它不混入会话工作上下文，实体接口只降级为原条目，不生成或缓存普通实体卡片。正式层 `begin_task` 仍捕获实际读取版本；这样的任务不能持久化成普通记录或普通共享经验。

文档不授予工具执行权、不改受保护人设、不安装正式运行协议、不证明动作已执行。身份视图仍只依赖本宠私密权威来源。Unknown、UserInspection、ModelTransmission 在两个读取层都拒绝；宿主存储检查用的 `get/search` 不是查看/传输绕过入口。

### M4.4 实时批准与版本化命令

M4 在原命令 v2 中追加 tag 11（普通共享发布）、12（正式资料新建）、13（正式资料 CAS 修订）；原 v1 字节/tag 0–3、M3 tag 4–10 与日志外层 v1 均不改变。

- tag 11 包含身份、最终 draft、提交时间、M3 TaskStamp 和发布策略版本；stamp 请求追加自动补边前的原始候选依赖及共享提议时间。查询、范围/层/预算、会话、实际读取版本、身份版本和发行时间仍属于完整请求。
- tag 12/13 包含分区、可选精确修订目标、draft、提交时间和存储代际/配置/正式策略版本。未知版本/tag、零策略版本、截断、尾字节及长度/数量越界均拒绝。
- 活体命令另持有不透明运行实例/配置批准证明，普通发布还保留实时任务。最终 execute 再验当前授权、来源、代际、实际读取集合和配置栅栏；所有运行配置修改及存储变化都会取消旧任务或批准。
- 解码不恢复活体任务或批准证明。`Eq` 只比较 wire 请求，同字节不代表同实时权限；跨服务 epoch 的 prepared 命令也拒绝。私有内存副本只用于本地同步提交，不是模型状态导入通道。

发布/正式许可及版本水位都是运行时配置，重启清空并默认拒绝，宿主必须重新认证。来源撤权持久化，恢复必须严格升版；旧引用、读白名单、发布白名单或记录不会自动复活。新精确来源和更高版本许可必须显式提交。

### M4.5 持久化与失败恢复

本地宿主先 prepare，再 `commit_publication(operation_id, command)`；新入口只接受 M4 发布类命令，不能执行普通 CRUD。仍采用排他文件锁、私有候选副本、追加帧、文件同步、再发布状态与回执。批准和配置不追加日志；只有成功提交返回 `Committed<WriteReceipt>`。

相同 operationId/完整 payload 可在撤权或重启后确认历史成功回执，包括解码得到的原请求；这不执行、不返回正文、不改代际或恢复许可。异 payload 冲突，原始候选依赖/提议时间/查询差异不能被自动补边消掉。没有成功日志的新 decoded 请求始终拒绝。

`replay` 仅给受信适配恢复成功日志使用，复验归属、来源、依赖、正式分类/状态、CAS 和代际，不恢复旧授权、任务或批准。历史 v1 到期纠正及超过 10,000 次删除的合法日志语义不变；墓碑上限仍为 100,000。

写前、半帧或同步不确定失败不发布候选内存，并封闭全部 M4 入口（包括 prepare、自动拒绝入口、配置、提交、正式层读取）。半帧保档拒绝，不自动截尾或修复；完整不确定帧必须重开验证及成功同步，之后才能幂等确认。

## 离线对话

### M5.1 身份与输入边界

`LocalMemory::offline_dialogue(identity, session, purpose)` 由已认证的宿主绑定稳定 PetIdentity 和 SessionId，只接受 OfflineReasoning。Unknown、UserInspection、ModelTransmission 仍拒绝；OfflineReasoning 仅允许此离线夹具，绝不是模型传输许可。本阶段没有端点、HTTP、SDK、网络回调或“启用模型传输”开关，也没有把 get/search 当传输绕过入口。

`OfflineDialogue`、原始 CRUD、来源登记、配置、审查回调、命令编解码及回执确认全部是受信宿主 API，不能注册为模型工具。模型输出的唯一槽位是 `OfflineFixture::Candidate(MemoryDraft)`，不含 owner、session、operationId、批准、正式资料写入或工具执行字段。MemoryDraft 新增完整只读审查访问器，不暴露可变记录或原始映射。

`begin_turn(query, preference, now_ms)` 使用 M3 begin_task 捕获实际授权读取集及可用身份锚点；先许可再检索/预算，分区、宠身份、会话、层和用途仍由服务控制。OfflineTurn 与 OfflineProposal 的身份/会话绑定和任务证明不透明，不允许宿主换另一宠/会话接收它们；重开也不能恢复任务 epoch。

本阶段只消费隔离的、合成的注入输出，没有用户聊天字符串/自由提示词的附加入口，也没有跨回合的模型隐式历史。宿主若日后接入真实模型，必须重新明确端点、传输用途及所有实际输入，不能换一个空任务隐藏既往私密上下文、额外检索、库外文本或模型会话历史。核心不能发现恶意宿主隐瞒输入或谎报来源；合成夹具不是语义脱敏器或生产来源认证。

### M5.2 候选、审查与即时提交

| 入口 | 含义 | 不承诺的事情 |
| --- | --- | --- |
| begin_turn | 获准条目快照与身份锚点、上下文报告 | 不授予用户查看或网络传输 |
| generate(turn, fixture, now_ms) | 复验任务，接收离线候选或报告夹具失败 | 不调用真实模型、不写盘、不证明推理正确 |
| review_and_commit(proposal, operationId, reviewer) | 宿主逐候选审查，注入实际时间并立即复验/提交 | 不提供排队批准、不代替真实宿主审查 |
| correct_original | 宿主核验新的原始证据并同 ID CAS 纠正 | 不允许将模型派生伪装成无依赖原始事实 |
| confirm_dialogue(request) | 仅确认已经成功同步并写入日志的完整历史请求 | 不执行、重放、补提交或恢复授权 |

审查回调取得不可变候选正文/所有元数据、实际上下文、可用身份锚点及降级报告。HostDecision 仅有 Reject、CreatePrivate 和 PublishShared；时间必须由宿主在真实审查结束后采样，不能取提议时刻或预先取时后排队。同步方法随即验证生成时间、任务代际/配置/epoch、全部读取项与到期，再 prepare/commit；不向外返回可延迟执行的批准。

私密新建复用 M3 栅栏命令 tag 10：实际记录边自动补齐、所有来源必须保留、敏感度不能降低，原始候选依赖与完整读取请求仍保留在 wire。普通共享复用 M4 tag 11：使用原始生成时间和真实提交时间，独立发布许可且按真实输入硬拒绝 private（包括 Normal）、身份锚点、工作上下文、正式资料和漏源。读许可不是发布许可；自动发布仍恒拒绝。正式文档不从对话候选授予权限，也不能混入默认普通记忆。

候选仅是待审查数据，非法正文、分类、证据或越权请求在提交门明确拒绝，不能把“生成了候选”报告成成功写入。只有文件同步和内存发布成功才返回 DialogueReceipt 中的 Committed&lt;WriteReceipt&gt;，FileSynced 的含义不扩大。

### M5.3 原始证据纠正

correct_original 是独立的受信宿主纠正入口，不直接接受 OfflineProposal。宿主取得本宠当前记录并核对精确 CAS；当前与新稿必须无记录依赖、性质为 UserStatement/Observation、分类相同。派生记录与模型推断不能经此去掉证据边；一般派生更新仍由既有 M3 宿主管理接口明确维护全部来源与依赖，不新增自动纠正或工作上下文提炼。

CorrectionReview 提供旧记录和新原始稿，宿主完成事实/来源审查后返回当前提交时间；立即复用原有 update 命令和持久化流程。到期、归档、删除、保护、敏感度降级、源版本和时间倒退等仍按 M3 拒绝。成功纠正推进全库代际，旧 turn/proposal 取消；下次读取仅取得新版本，有旧边的派生项失效，不扩大删除或恢复范围。这个宿主存储检查不是 UserInspection 或 ModelTransmission 许可。

### M5.4 可解释降级

ContextReport 明确报告条目数、身份锚点是否可用和 ContextPath。PreferEntity 的缓存命中/构建保留相应状态；关闭、满额、正式资料层不建卡片或空实体标签时，退回同一获准查询的原条目，报告 EntriesFallback。任务始终以实际条目读取集为权威，降级不能丢掉私密来源或改成空任务。无获准条目和无有效身份锚点也明确报告，不合成身份/证据。

DialogueError 区分 Binding/Context/Generation/Review/Commit/Correction/Confirmation 阶段及结构化原因：用途拒绝、绑定错误、ModelUnavailable、InvalidModelOutput、HostRejected、TaskCancelled、证据/权限/CAS 拒绝、OperationConflict、RecoveryRequired、CommitIndeterminate 等。模型夹具失败不产生候选、不写盘，也不声称回答或工具执行成功；宿主可以重新进行获准条目读取，但不能伪造模型回复或无授权回退。

Debug/Display 不输出候选正文、查询或身份锚点正文。错误状态是没有新的成功回执，不是“绝对未写盘”：CommitIndeterminate 可能已落入完整帧，必须关闭重开验证及成功同步；全部新旧 M5 入口在不确定失败后均封闭。半帧保留原档并拒绝，不截尾或自动修复。

### M5.5 历史回执与恢复

DialogueCommit 是不可变完整请求句柄，成功回执和实际提交失败都可保留它；失败不能把它当已提交结果。to_bytes/from_bytes 只委托原有 MemoryCommand 编解码，operationId 单独保存，不增加日志封装或命令 tag。字节可能含正文，不能默认打印、传输或另建备份；解码不恢复实时任务/批准。

confirm_dialogue 只查已验证且同步恢复的成功账本，按 operationId 和完整命令字节比对。无历史成功即 NotFound，异请求即 OperationConflict，非写入回执类型明确拒绝；即使传入可由宿主执行的普通 CRUD 解码命令，也绝不执行它。旧成功的确认不返回正文、不改代际、不复活已删除内容、不恢复读/发布许可，不重新取一个旧提交时刻执行。重新审批是新真实请求，不能冒充历史请求。

日志外层 v1、命令 v1 和现有 v2 tag 4–13 完全不变。排他锁、私有候选副本、完整请求幂等、同步后发布及成功重放保持原语义；历史 v1 到期纠正、20,003 帧/10,001 次删除恢复和 100,000 墓碑上限仍有回归。运行策略/会话/身份/缓存/许可/水位重启清空，来源恢复仍要求显式升版。取消不等于停止外部 I/O，保留/备份/外部副本政策未定；日志/缓存/已持有快照可能留正文。Windows 仅文件同步，不保证目录断电耐久、防恶意有效旧日志回滚或物理擦除。

## 上下文与压缩

### C.1 三个对象各司其职

- `MemoryTask` 是经过授权的实际读取快照及提交栅栏，仍保留完整读取集、身份、来源和精确版本；不能由模型构造。
- `RequestContext` 是该快照的一次请求投影，内部状态封装；只能通过服务读取、准备压缩和应用压缩，不提供集合可变引用、反序列化或任意导入入口。
- `CompactionTask` 是一次压缩的不可伪造票据，绑定具体投影、投影版本、输入区间和准备时间。`inputs()` 返回当时已交付的只读输入，不授予新读取权限。

事实记忆维护与请求压缩互不替代。压缩不会修改原记录、补充新证据、提升可信度、更新人设或产生持久化命令；也不是已经实现了长期学习或技能自进化。

### C.2 外部接口

`MemoryService` 与 `LocalMemory` 提供同名接口；本地适配只增加健康门和错误映射：

| 接口 | 职责 |
| --- | --- |
| `assemble_context(task, budget_chars, now_ms)` | 复验任务，生成有界投影。 |
| `context_view(context, now_ms)` | 再次复验任务和投影时间门，返回只读 `ContextView`。 |
| `begin_compaction(context, range, now_ms)` | 对非空、连续、合法的普通条目区间生成票据。 |
| `apply_compaction(context, ticket, summary, now_ms)` | 复验任务、投影身份/版本、时间和摘要大小，成功后原子替换该区间。 |

宿主仍使用既有 `for_session(...).begin_task(...)` 产生输入快照；新接口不接受模型自填 owner、scope、来源或授权。未知用途、用户查看和模型传输不因此获准。M5 的 `OfflineDialogue` 保持原有行为，本批新接口由宿主显式调用，不自动启动整理任务或模型调用。

`ContextView` 只公开身份、块切片和 `ContextUsage` 值副本。块的 `ContextEvidence` 保留原条目或会话条目的精确引用、原来源列表、内容类别、事实性质、生命周期和敏感度；调用方修改 DTO 副本不能改变服务状态。

### C.3 预算与保护

先预留可用身份视图和已检索出的 Identity / ToolDefinition / Protocol 原文，再按原检索顺序装入普通条目。普通条目仅整条保留或跳过，不切断句子，不将低预算解释为遗忘。

受保护内容放不下时返回 `ContextBudgetExceeded { required, available }`，不静默裁剪人设或协议。身份若原本未配置或不获准，不新增默认身份。新接口只保护输入快照里已有的正式资料，不绕过检索范围、条数或上游预算加载额外协议。

预算只计算身份及可见块正文的 Unicode 字符数，不是字节或 token；不包含结构标记、来源元数据、宿主系统提示、工具定义和输出预留，也不保证模型上下文窗口一定够用。真实模型接线时需另做实际消息/token 计量。

`ContextUsage` 返回总预算、已用字符数、原检索条目数、最初因投影预算省略的条目数及投影版本。压缩把多个块变成一个块时，不把它们误报为遗漏；上游检索没有选入的条目不计入这个遗漏数。压缩释放的空间不会自动填回原先省略的内容，需要宿主显式重装配。

### C.4 摘要不是事实

本批不调用摘要模型，`summary` 是宿主传入的候选。只校验非空、无 NUL、至多 4096 字符且严格小于原区间正文总字符数；无法保证语义忠实，也不把压缩率当质量证据。

成功摘要标记为 `UnverifiedSummary`，携带全部原始输入的证据元数据，不因为短了就变成事实、用户陈述或正式协议。身份与正式资料不能压缩；本批也拒绝对摘要再次压缩，避免把注入内容循环当成新观察。调用方须保留类型边界，将摘要作为不可信参考而非系统指令。

真实任务快照保持不变。后续提议仍由原任务补齐全部来源及记录依赖，即使某条私密输入已在投影中被省略，也不能借摘要或空投影洗成可共享数据。含会话工作条目的任务仍拒绝自动持久化提炼，不借本批扩大长期保留范围。

### C.5 失效与失败

- 原记录被纠正、归档、删除、替代或到期，来源被撤权，授权/身份/会话配置变化，显式取消或运行实例更换时，沿用 `MemoryTask` 的保守失效机制，拒绝新交付和迟到压缩结果；全库无关写入也可能使旧投影失效。
- 同一投影上竞争的压缩票据使用版本 CAS，只有当前版本可应用；第二份、重复票据或另一个投影的票据不能覆盖已有结果。区间不合法、摘要无效或不变小均保持原投影不变，可继续使用原文。
- 不接受早于投影建立/上次成功压缩的使用时间，也不接受早于票据准备时间的结果；时间仍由受信宿主注入，不读取系统时钟。
- 本地适配发生写入/同步不确定故障后，四个新接口一律 `RecoveryRequired`，不以“只是缓存”绕过健康门。
- 投影、摘要、票据和运行时身份不进持久化日志，不增加原文留存，不改变日志/命令版本；重启后旧对象仍因运行证明失效，重新安装相同读取策略也不能复活。

已经返回的视图克隆、票据输入和外部快照无法追回，失效不等于物理擦除；应用仍需遵守既有明文日志、备份和外部副本边界。Debug 隐藏正文与会话条目标识，但不代替宿主日志脱敏。

## RAG 检索扩展（分批施工）

> 方案日期：2026-10-12；状态更新：2026-10-13。归属：**记忆系统内部扩展**。R0–R4 离线工程已实施：授权票据、在线协议适配、混合索引、持久化健康门与离线 Agent 最小注入，以及 R4 安全回归、冻结标签、独立校准、真实校验入口和合成基准；真实模型门仍未完成。真实非子串 Embedding、真实 rerank 效果与 tokenizer 门仍未验证，缺真实环境的推进例外按 R.8 执行，不能据协议夹具宣布真实门通过。可选在线 Embedding/rerank 不代表已批准真实数据外传；本地模型未接。R 阶段独立于暂停的 G6–G8，不启动对外 HTTP 网关、真实对话模型、渠道、自动提炼或工具执行。

### R.1 目标、非目标与现状

目标是把已经获准保存的长期记忆和共享资料找回来，接入已有 `MemoryTask → RequestContext → ContextView`，而不是另造存储、学习流水线或通用 Agent 平台。归属仍为 private/shared，长短期仍是生命周期；向量、分块和关键词倒排均为派生索引。

| 内容 | 本轮方案 |
| --- | --- |
| 私密长期事实、画像、关系、经历 | 在绑定桌宠身份和来源许可后，关键词与真实向量混合召回。 |
| 普通共享知识、经验 | 在获准共享命名空间内检索；共读不授予共写，不从私密内容自动生成共享向量。 |
| 正式能力与协议资料 | 仅在显式 `FormalMaterial` 请求中检索；命中仍是参考资料，不授予工具执行权。 |
| 人设锚点、必要运行规则 | 延续可信配置和受保护装配，不以 top-k 检索替代。不能因检索失败失去身份。 |
| 短期工作上下文 | 保留现有会话路径，不建立持久化向量索引。混合请求在核心合并获准工作条目，纳入同一预算和证据集。 |
| 原文暂存、回收区、未审查候选、摘要 | 不自动索引或晋升长期/共享；不启动闲时提炼。 |

既有关键词入口：核心 `MemoryReader::retrieve` 先调用 `authorized_candidates`，`select` 保持大小写归一后的子串匹配、命中次数及更新时间排序。关键词 `MemoryTask` 仍重跑原查询；R0 混合任务改为按实际交付/发送输入及人设完整快照复验。R1 的在线编码与精确扫描在独立适配层，不自动改变默认入口；本地 reader 仍经健康门转发核心；R3 后 AgentServices 通过核心窄契约接入内存、持久化及显式混合检索门面。该同步离线接线不代表本地模型、异步在线 Agent 或真实渠道已实现。

本轮不引入 LangChain/LangGraph 运行依赖、远程向量数据库、图谱、自动扩写查询或多轮检索 Agent。先做一次可控检索，可选 rerank 后装配上下文；不宣称“有 RAG 就完成自主 Agent”。在线模型只承担编码或排序，原记录和向量索引仍在本地，不顺带选用云端记忆 SaaS。

### R.2 模块边界与依赖

```text
moe-memory-core
  授权候选、密封读取票据、来源/版本复验、MemoryTask、上下文窄契约
       ↑                      ↑
moe-memory-local       moe-agent-runtime
  日志与健康门           仅依赖核心窄契约，不加载模型或索引
       ↑
moe-memory-search（R1 已新增，唯一适配 crate）
  R1 在线 Embedding/可选 rerank/精确扫描；R2 分块/混合索引/显式缓存
       ↑
受信宿主：组合持久化记忆、检索适配和 Agent，提供路径、时间及许可
```

- 核心保持零第三方依赖、无文件/网络/时钟 I/O；memory-local 保留既有日志和唯一权威写入路径，不在两者塞入 ONNX 或数据库。
- 新适配 crate 仍属于记忆子系统，不开服务端口、不提供新的账号/租户体系、不复制 CRUD 或私有正文库。宿主继续使用原有 CRUD；检索适配只暴露绑定后的检索、上下文操作和受信维护入口。
- Embedding 和索引实现藏在模块内；对外是记忆检索门面，不返回内部可变集合、裸向量库、可变 LocalMemory 或可伪造的 MemoryTask。
- 网络客户端和厂商协议只放 I/O 适配层，依赖按需评审；核心、memory-local 和 Agent 运行层不直接发 HTTP。宿主将既有 API 预设解析为受信模型配置，不让记忆核心反向依赖网关预设管理。
- 为 Agent 抽取一次最小的“授权建任务、装配上下文、复验上下文”契约，放在核心；MemoryService、LocalMemory 和检索门面按需实现。Agent 不反向依赖检索适配，不把所有 CRUD、存储管理和共享发布塞入万能 trait。
- 保留既有调用方式和默认关键词语义；混合检索由宿主显式选择并注入。只做为本批接线必要的 AgentServices 改造，不顺便重写会话、Hooks、原文存储或取消体系。

### R.3 授权召回与任务闭环

```text
可信宿主绑定实例 / 会话 / 用途 / 检索配置
  → 核心准备获准候选与不可伪造票据
  → 仅在候选集合内计算关键词、余弦相似度并融合
  → 可选：获准候选小集合交给本地/在线 rerank，再复验
  → 适配返回候选引用及排序，不提交正文或权限声明
  → 核心复验票据、当前权限、有效性、版本和预算
  → 核心从权威记录取正文，生成 MemoryTask
  → 既有受保护上下文装配、交付复验与派生证据链
```

1. 准备阶段复用现有 `readable`、`matches_scope`、全来源白名单、依赖、敏感度、生命周期和 `RetrievalLayer` 校验。先限定完整获准候选集合，再执行词项统计、相似度排序、融合与 top-k；不能全库搜索后过滤，也不能先用现有最多 100 条的空查询代替完整候选扫描。
2. 票据绑定本次运行证明、稳定桌宠/命名空间、会话、用途、原查询、层/范围、候选版本、配置/策略版本及内核现有代际。句柄由服务创建，内部字段封闭；模型输入的 owner、scope、来源、分数或“已授权”声明不能制造票据。
3. 后端只提交候选引用。核心拒绝外来/重复/失效引用、非有限分数、超过额度和不属于票据的结果，并重新取正文。相关分数只表达排序，不改变事实性质、信任、敏感度或共享权限。
4. 评分到装配之间发生纠正、撤权、归档、删除、到期、来源变更、配置变化或取消，按既有栅栏拒绝旧票据。索引成功不等于正文当前可读；不能因缓存命中跳过内核健康门。
5. **必须同步修正任务验证假设。** 旧关键词任务继续保留原验证语义；新增混合任务不能再用旧 `select` 重跑查询来比较，否则合法语义命中会在 `assemble_context` 时被取消。混合任务密封本次实际交付的条目/版本/来源/顺序及检索配置，后续按这些引用逐项复验，再复验身份、运行证明、权限、代际和有效期；验证过程不重新调用模型或依赖可变索引排名。
6. 本次实际交付的完整读取集进入 MemoryTask。上下文裁剪、压缩和卡片不能减少提议的来源依赖，不能借只保留共享片段洗掉私密输入。仅扫描向量或用于纯本地评分的未交付候选不作为模型新证据；发送给在线 rerank 的查询和全部候选另绑定实际传输集及来源，涉及私密候选的任务不能只按最终 top-k 冒充纯共享读取。
7. `Unknown`、`UserInspection` 和既有普通 `ModelTransmission` 的拒绝不被一键放开。在线 Embedding/rerank 使用宿主显式配置的用途、目的端点、允许范围及来源许可；查询编码、条目编码、重排分别核验，不借离线许可外传，也不因此授权对话模型。云调用发出前和返回后均检查当前许可/版本；请求已发出的内容不能因后续取消而保证被远端撤回。
8. 新检索选择/票据放在运行期证明中，不为索引升级现有 journal、命令或 TaskStamp 的磁盘布局。现有命令只序列化戳记、不序列化 LiveProof；如需绑定混合配置，可在新任务的有界 request 字节中加入明确区分，但旧命令字节、幂等结果和重放保持兼容。解码的命令不能因此获得新的现场执行证明。

### R.4 检索与分块算法

第一版使用**关键词 + 精确向量检索 + RRF 融合 + 可选 rerank**，不部署独立向量服务。语义路径必须能命中与查询没有相同子串的条目，不能只对原关键词结果重排。rerank 只重排已获准的小候选集，不能代替全量召回。

- 词项路径：保留完整精确子串命中信号，增加确定性的轻量 BM25；中文使用字符二元组、拉丁文字使用连续词项。大小写、边界、标点和词项版本写成明确规则及测试，不先引入分词模型。词项统计仅在本次获准集合内完成，不使用其他桌宠语料计算本次排名。
- 向量路径：对获准候选执行精确余弦扫描；向量归一化，拒绝维度不符、NaN/Inf 和零范数。第一版以确定性和过滤正确为先，不做 ANN/HNSW；规模与性能实测后再决定，不能以任意条数阈值宣称必须换数据库。
- 融合：对两路有资格的结果使用 `sum(1 / (60 + rank))`，rank 从 1 开始，缺席一路贡献 0；按融合分数、已声明的精确命中信号和稳定引用打破平局。不能直接把 BM25 与余弦数值相加。
- 相关性门：向量最小相关阈值由固定中文标注集校准并绑定模型配置，不拍定通用 0.5。关键词无命中且向量低于门槛时允许返回空集，不为凑齐 k 填入无关经历。空查询保留既有列表语义，不生成空查询向量。
- 收口：完整候选快照和全部排名合法性先复验，再以一次引用建表查找实际交付项；只克隆预算内正文，不按全量排名反复线性查找。尾部重复/外来/非有限项不能因 top-k 或预算已满而免检。
- 预算：使用现有条数及 Unicode 字符预算，短期条目与长期命中合并后只计算一次；必要身份/资料预算仍由现有上下文规则保护。不把字符预算冒称 token 预算。

| 对象 | 向量切片与正文交付 |
| --- | --- |
| 私密短事实/经历 | 一事一条，能放入模型输入时整条编码；过长时仅对嵌入视图按句边界切片，不拆改权威事实或丢失后半段。 |
| 已入库共享资料 | 先尊重标题、段落和列表边界，再按模型 tokenizer 限长；建议初始正文目标 384 tokens、相邻重叠 48 tokens，硬上限扣除前缀及特殊 token 后不得超过模型窗口。参数属于分块配置，实际值由 R1 验证。 |
| 同记录多切片 | 切片携带父 RecordVersion、稳定顺序、字符区间和分块配置；语义记录分数取有效切片最高分，再参加记录级融合，不能因一篇长资料切片多而挤占全部名额。 |

第一版最终按**记录级**返回完整获准正文和原证据，不把裸片段塞进 ContextBlock 冒充完整原记录。这保留现有 `ContextOrigin`、整条预算及来源契约；分块用于突破 Embedding 输入长度限制并改善召回。记录放不下时按既有规则省略并计数，不静默截断。

当前单条正文上限为 4096 Unicode 字符，本方案不顺带放宽存储格式。几十页长文尚需受信导入为带相同文档来源/版本和章节位置的有序记录；本批只索引已获准入库内容，不增加文件爬取、网页抓取或文档导入器。精确片段级上下文留待有需要时单独扩展证据契约。

### R.5 真实 Embedding 与依赖选择

**本地和在线是可替换后端，不强制本地部署。** 第一版可以优先接在线 Embedding；本地 CPU 模型是可选方案，不以安装 ONNX/ORT 为所有用户的前置条件。首发真实后端由施工任务明确，其他未测后端如实标记，不能拿适配桩代替实现。

### R.5.1 在线模型与 API 预设

- 复用既有 API 预设管理，拟增加独立 Embedding、Rerank 用途绑定；R1 已新增 PresetPurpose::Embedding/Rerank，旧六项槽位不变，新两项分别追加为 6/7，独立绑定及配置失效已有针对性测试。宿主解析 base URL、凭据引用、模型、协议、超时和有限重试后注入适配层，不另建记忆专用凭据库，也不默认复制 Chat 预设权限。
- Embedding 可首先实现 OpenAI-compatible `/embeddings` 适配；rerank 单独实现一种明确厂商协议，不能假定其兼容 `/chat/completions` 或所有供应商字段一致。厂商差异仅在适配器内，业务调用不拼接 HTTP/JSON。
- Embedding 请求会发送查询或待索引文本；rerank 会发送查询和候选正文。共享资料可共读不代表公开、可外传；查询本身也可能私密，不能因为只搜共享库就跳过查询授权。允许本地读取不等于允许模型传输，拥有 API Key 也不是用户同意。
- 外传许可由宿主按用途、端点、范围和来源显式提供。仅允许共享资料外传时，不得发送私密查询/候选；可以使用已配置且获准的本地后端或关键词路径，否则明确返回传输不可用。禁止自动换到其他供应商或端点，也不为提高召回向云端上传整库。
- HTTP 只在明确调用在线后端时发生；普通初始化、重开、默认测试不得请求外部模型。采用有界批次/响应、超时、有限重试与取消，校验返回数量、索引映射、维度及数值。不重试无效凭据/输入；429/暂时故障的重试不越过当前额度、截止时间或撤权。
- 在线 Embedding 返回的向量由本地索引保存；rerank 只返回候选引用与分数，不能改正文、归属或可信度。远端的数据保留/区域/费用按选定服务另行确认，不承诺已发文本可撤回或因本地遗忘而远端同步删除。

### R.5.2 本地候选与向量空间

- 本地候选仍为 `BAAI/bge-small-zh-v1.5`（512 维、512-token 窗口）及 fastembed ONNX CPU 路径。采用时锁定能在本仓库 Rust/Windows 环境工作的 fastembed/ORT 版本，禁用隐式下载；模型/tokenizer/ORT 由宿主显式准备。
- 本地权重和 ONNX 转换件分别记录出处、revision、SHA-256 及许可；资产不进入普通源码/真实用户夹具。在线模型则记录供应商、端点、模型标识、可获得的服务版本/配置版本，不能假装拥有远端权重指纹。供应商不能固定模型版本的限制须记录。
- EmbeddingProfile 固定后端身份、模型配置、维度、最大输入、池化/归一化和查询处理规则；本地再绑定权重/tokenizer 指纹。查询/文档各按厂商或模型要求处理前缀。相同维度不代表同一向量空间，不混用不同后端/配置生成的查询与记录向量。
- 长输入按所选模型的 tokenizer/官方计量规则预切片，不接受默认静默截断。未知 tokenizer 时必须采用明确的保守分块/长度拒绝策略并实测，不能套用本地候选的 512-token 上限。
- 第一版只支持一个活动 EmbeddingProfile；更换后端/模型/维度或兼容性配置时重建索引。不能把失败的在线查询临时换成另一个本地模型后，继续搜索原在线模型向量；若无对应本地索引，应降级关键词。
- 模型未配置、加载/调用失败或索引不可用时可按明确策略降级关键词，并返回原因；显式严格向量模式则报错。字符串 hash、随机向量、关键词编码及预制结果只准出现在测试夹具。

### R.5.3 可选 rerank

混合召回 → 相关性门 → 候选记录去重 → 可选 rerank → 最终 top-k/预算 → 核心复验与装配。初始重排上限建议 20 条，可由宿主在有界范围配置；长记录只提交获准命中切片，记录其父版本和区间，不为排序把全部长期记忆交给模型。

- RerankerProvider 与 EmbeddingProvider 独立，可以选不同供应商；同一组 API 配置也须分别通过用途和数据传输许可。重排模型不参与向量空间，更换它不重建向量索引。
- 仅重排本轮已经获准且过相关性门的候选，拒绝外来/重复引用、非法索引与分数。换模型时重新校准必要的分数门，不能把不同厂商分值视为同一标尺；rerank 不得补回原本无关或被权限过滤的内容。
- 重排关闭时直接使用 RRF 顺序；超时/故障时，若配置允许，可保留 RRF 顺序并返回 RerankUnavailable 等原因。权限/任务失效仍报错，不能仅降级排名后交付过期正文。
- 重排发出前复验查询与全部候选的外传许可，返回后复验票据/来源/版本。实际传输集绑定任务来源和共享审查，不能通过丢弃最终未入选的私密候选来洗成纯共享任务；不默认持久化请求正文。
- 第一版实现一条明确的在线 rerank 适配并可关闭，不强制每轮调用，不要求下载本地重排模型；具体上线配置按质量、时延和费用实测选择。

在线档案的向量空间身份包含端点、模型、维度和输入/归一化规则，不包含请求超时、尝试次数或退避；传输参数仍有界验证且不能改变用途/范围/来源许可。本次修正需一次淘汰旧指纹缓存，之后单改传输参数不要求重建。

### R.6 索引生命周期与缓存

权威记忆提交与索引更新不做跨库事务。既有 journal 同步成功后，宿主可按写入回执通知检索适配；通知仅是加速提示，不是权限、正文或提交成功证明。查询准备时用核心当前获准候选清单核对缺项/旧版本；漏通知不能让旧内容返回，也不能被解释为无相关记忆。清理只作用于本票身份/搜索范围及检索层共同覆盖的集合：WorkingContext 不清长期向量，FormalMaterial 与普通 LongTerm/All 不互清；未包含不等于失效。未覆盖的缓存不得参与本票评分，真正更新/删除/撤权项仍由覆盖该层的当前授权复验清理。

- 索引键至少绑定宿主存储域、完整 private 身份或 shared 命名空间、父 RecordVersion、切片区间/分块配置、正文摘要指纹及 EmbeddingProfile。相同文字、同名宠或另一记忆根下相同 MemoryId 不得合并。存储域由受信宿主绑定，不能由外部请求自报。
- 索引正文必须来自密封票据和当前授权记录，不接受调用方“这个 ID 对应这段正文”的任意覆盖。正文摘要指纹用于缓存一致性，不是身份或授权证明。
- 后台任务只处理已批准长期内容的嵌入，不负责摘要、事实抽取或共享审查。首版一个有界工作队列，按分区/记录合并重复任务，限制批量和并行；时间/取消由宿主注入，不新增事件总线、通用调度平台或逐请求永久额度账本。
- 缺失向量可排队补建；本次词项路径仍覆盖完整获准候选集，返回 PartialIndex 等可见原因。正文更新使用新版本键，旧向量不参与新版本评分。迟到嵌入提交必须复验运行证明、当前来源、记录版本及索引配置，不能覆盖新版本或复活删除项。
- 删除、替代、归档、到期、收紧敏感度或撤销来源后，先保证查询不可用，再移除活动索引/缓存中的对应向量。恢复必须按当前授权、版本和配置重新建索引，不能直接恢复旧票据。普通索引失败不回滚已成功的权威写入。
- 第一版内存中做精确扫描；本地文件只保存可丢弃缓存，不另存原文、查询、会话或人设正文。向量本身也按敏感派生数据处理，不因不是明文而宣称匿名、公开或不可反推。落盘由宿主明确启用并放在同一受保护存储域；未启用也必须能完成真实语义检索。
- 缓存保存格式版本、模型/分块配置、域/分区和条目版本清单；装载时校验后再与当前获准候选相交，不能从文件恢复授权。模型配置不符、损坏、缺失或旧版本缓存均可丢弃重建；不得因此删除/覆盖原记忆，亦不得悄悄创建空 journal。
- 文件缓存以完整快照替换，不再建立一套追加式向量日志。失败时保留旧的可验证快照或不使用缓存，关键词继续可用；平台原子替换/同步边界写清楚，不冒称跨平台绝对耐久。
- 缓存移除不等于物理擦除；历史 journal、备份、已交付视图和外部副本保持既有删除边界，不借 RAG 擅自扩大清理范围。管理型清缓存/重建只能触及索引域，不能递归删除权威记忆根。

### R.7 外部接口与降级契约

以下是职责约束；R3 已落实 `SearchMemory`、核心 `MemoryContextAccess` 与受健康门保护的检索授权桥。具体签名以 Rustdoc 和 crate README 为准，不把拟定提供者当作已实现的本地模型。

| 门面/扩展点 | 职责和限制 |
| --- | --- |
| SearchMemory 的构造 | `new(local)` 保留关键词；`with_ranked(local, ranked)` 接收宿主已完成的密封混合排名，按完整身份/会话/用途/查询匹配，一次性交付。只组合/适配，不复制权威库或暴露可变内核；本地模型资产未接。 |

### R.9 验收清单与真实模型门

**安全和一致性（必须全部通过，测试向量可以人工构造）：**

1. A/B 桌宠存在同文、同名、最高相似度及互斥来源条目，私密命中仍互不可见；另一存储域的相同 ID 也不能污染。共享只读许可不能生成发布/写入权。
2. 非获准条目不得参与本次候选、BM25 词项统计、向量排序、融合、预算或诊断。用后端探针验证不是全库 top-k 后过滤；获准目标在第 100 条之后仍可被召回。
3. 新身份/协议/工具权限不由相关分数或向量内容决定。FormalMaterial 不混入默认 All/LongTerm；受保护内容不足预算仍明确失败。
4. 已选原记录、源版本、依赖、有效期或用途变化后，旧任务和索引结果不能再次装配/交付。边界等号到期也要覆盖；无关写入仍遵守现有保守代际，不顺便放宽取消。
5. Embedding 计算返回前发生纠正、删除、撤权、切换实例/模型、重开或取消，迟到结果不能写入活动索引、覆盖新向量或令内容复活。
6. 配置、维度、NaN/Inf、零向量、重复/外来候选和超大缓存输入均被有界拒绝。空查询、空集、阈值以下、并列分数和预算裁剪可重复。
7. 模型缺失、半文件/坏索引、缓存写入失败、重开重建和清缓存不改变权威日志；真正的 journal/授权故障不能被 KeywordOnly 掩盖。旧库不迁移、不放宽授权、不因错误变空库。
8. 短期/暂存/回收原文不进入持久化向量，反复读取/检索不新增事实、不自动共享、不续期。本地模式、普通初始化和默认测试不外连；在线模式只有明确许可才发送已核验的查询/正文，未许可端点及来源的网络请求数为 0。使用回环协议桩检查请求体、凭据脱敏、超时/有限重试、取消和拒绝重定向到未批准端点。
9. LocalMemory 的健康门覆盖新门面；没有可变根对象/集合泄露。实际交付的语义命中进入 MemoryTask 和 ContextEvidence，压缩或只保留共享输出不能洗掉私密读取证据。
10. rerank 仅见获准候选，外来索引、重复引用、非有限分数和过期返回被拒绝；关闭/调用失败的可见回退不改变权限。包含私密查询/候选的实际发送集不能因最终只选共享结果而丢失来源污点；读许可、条目编码、查询编码、重排和聊天许可互不自动替代。

**真实 Embedding 质量门（不能由人工向量或 hash 编码替代）：**

- 使用无真实聊天/凭据的人工中文语料；冻结 40 条评测查询及人工相关记录标签：16 私密、16 共享（含显式正式资料），8 无相关内容。32 条有答案查询中至少 16 条是无完整查询子串的释义表达。另用不重叠的校准查询选阈值，不拿评测集调参。
- 初始验收目标：有答案查询 Hit@5 至少 28/32；其中释义子集至少 12/16；无相关内容至少 7/8 返回空集。所有越权/失效命中为 0。这是本项目首版验收目标，不是论文效果承诺；不得在交付时静默改标签/删困难样本/降阈值过门。
- 同一语料、权限、预算和标签同时运行 KeywordOnly 与 Hybrid，报告命中差异、空结果、噪声和实际例子；释义子集的 Hybrid 命中数必须优于新关键词路径。旧关键词 API 的兼容性由独立回归保证，不为抬高收益故意削弱基线。
- 提供显式真实模型入口，例如拟新增 `embedding_check` 示例，明确 local/online 后端及启用的 rerank。local 从宿主本地资产清单运行；online 从受信环境取得凭据引用、固定端点/模型/维度和用途许可，用人工语料实测。缺资产/凭据/许可、配置不符或质量不达标均非零退出，不 skip 后打印通过。标准单元测试不请求外部服务，真实门独立执行并记录确切命令和配置摘要，不记录 API Key。
- 同一人工标注集对照 Hybrid 与 Hybrid+Rerank，报告 Hit@5、NDCG@5、无关输入拒绝率、附加延迟和用量。rerank 不是固定收益保证；无提升时可保留关闭，不调低权限/相关性门来制造提升。没有真实调用就明确标记重排协议已测、模型效果未测。
- 报告本地冷加载或在线请求、首次建索引和热查询的端到端延迟，区分 tokenizer/Embedding、召回、rerank 和装配；在线另记调用量、重试及可取得的用量/费用估计。另用 1,000/10,000 条无敏感合成记录测扫描/内存/索引大小。合成向量只证明扫描成本，不能证明语义质量。不预先宣称固定毫秒性能或节省比例。
- 离线 Agent 测试至少覆盖“相同意思换措辞仍取回偏好”“纠正后只使用新版本”“缺向量但关键词仍可用且原因可见”“不相关问题不硬塞经历”。生成回复仍可使用明确标注的离线夹具，不能把它写成真实对话模型效果。

**工程与交付门：**

- 新模块先做针对性测试，再执行 PLAN 的 fmt、Clippy、workspace test/build/doc、文档检查及 diff 检查。原有测试数可能变化，但原权限/格式/取消用例不得为过门随意删除或降低预期。
- 生产依赖中不含测试夹具默认导出；提供者桩和人工向量仅放测试或显式非默认测试特性，不能变成生产后端。真实验证缺失必须记为未完成。
- 在 REVIEW 同一入口记录版本、实际命令、质量/延迟摘要和未验证边界；不复制模型、聊天、凭据或全文评测日志到现行文档。源码格式、授权/取消、持久化格式不相关的改动另开任务。
- 最终审查确认：业务调用仅接触记忆门面；新增最多一个适配 crate；无通用数据库/插件框架；无双份权威正文；无为缓存重做事务日志；无隐式网络或权限放宽；G6–G8 仍暂停。

### DSH.2 可以借鉴的机制

#### DSH.2.1 事件是历史，模型上下文是投影

`Session.append` 先快照与冻结数据，校验 surface，再追加到内存 log 并通知观察者；`deriveMessages` 只遍历当前 surface，按新节点增量投影，surface 被替换时重建。压缩替换的是模型可见节点，不是覆写原始事件。证据：`DSH/packages/core/session/src/index.ts:627`、`DSH/packages/core/session/src/index.ts:643`、`DSH/packages/core/session/src/index.ts:709`。

对 Moe-Buddy 的启发是明确分开三种记录：交互事件、治理后的长期记忆、一次模型请求的上下文视图。事件不能因为“曾发生过”就被当作真实事实；模型输出、工具回执、用户纠正仍保留不同性质。

必须区分内存追加与耐久提交。DSH 的 append 是同步内存操作，外围持久化有 write-behind 与 flush；不能把“已记事件”直接翻译成“已同步落盘”。证据：`DSH/packages/session/session-persistence/src/write-behind.ts:12`、`DSH/packages/session/session-persistence/src/write-behind.ts:59`。我们的权威记忆继续保持同步落盘后才发布：`crates/moe-memory-local/src/api.rs:458`。

#### DSH.2.2 先做便宜的裁剪，再决定是否调用模型摘要

工具结果 pruner 保留有界头尾和省略标记，其他结果字段不变；追加新 `tool/result` 替换可见节点，并指向原事件。原完整结果留在事件记录中。二次裁剪不应不断制造更小副本。证据：`DSH/packages/compaction/compaction-tool-result-pruner/src/index.ts:83`、`DSH/packages/compaction/compaction-tool-result-pruner/src/index.ts:136`、`DSH/packages/compaction/compaction-tool-result-pruner/src/index.ts:167`。

自动 compaction 在步进前检查压力，在规范化的上下文溢出错误后有限重试；已取消的请求不因裁剪进展而复活。证据：`DSH/packages/compaction/compaction-basic/src/index.ts:147`、`DSH/packages/compaction/compaction-basic/src/index.ts:179`。

借鉴方向：先按权限和有效性过滤，再去重、限量、截断可截断的大块工具结果，最后才考虑模型摘要。用户原话、身份锚点和关键工具错误不能无差别套用头尾裁剪；省略必须可见，必要时按授权回取原证据。

#### DSH.2.3 摘要是一份带版本和来源的派生结果

压缩准备阶段捕获选区及计量节点；摘要返回后重新校验整份 surface 或选中片段，拒绝已变更的输入。连同包装文本计算出的摘要若不比被替代内容更小，就拒绝提交。证据：`DSH/packages/compaction/compaction-basic/src/region.ts:339`、`DSH/packages/compaction/compaction-basic/src/region.ts:368`、`DSH/packages/compaction/compaction-basic/src/region.ts:387`、`DSH/packages/compaction/compaction-basic/src/region.ts:403`。

提交会记录摘要、输入事件序号、provider/model、usage 等，并另追加带精确来源序号的替换消息。手动事务在闭合后执行 durability checkpoint；失败与取消不是成功。证据：`DSH/packages/compaction/compaction-basic/src/region.ts:189`、`DSH/packages/compaction/compaction-basic/src/region.ts:231`、`DSH/packages/compaction/compaction-basic/src/region.ts:447`、`DSH/packages/compaction/compaction-basic/src/region.ts:462`。

借鉴方向：整理任务也绑定真实输入集、实例代际、配置、权限及版本，提交时复查。摘要不能因为被反复读取或摘要而获得新的用户证据，更不能丢掉父来源后晋升共享。已有 `MemoryTask` 和派生依赖机制继续复用：`crates/moe-memory-core/src/management.rs:158`。

#### DSH.2.4 缓存友好的压缩不等于免费记忆

摘要调用保留原 system、tools 与会话前缀，把压缩指令追加在末尾，意图复用 provider 的前缀 KV cache；代码仍然执行一次 `ctx.llm.stream` 并记录 usage。证据：`DSH/packages/compaction/compaction-basic/src/summarizer.ts:24`、`DSH/packages/compaction/compaction-basic/src/summarizer.ts:145`。

这是请求布局的优化思路，不是实测成本保证。能否命中缓存取决于端点、路由和前缀一致性；仍有读取上下文与生成摘要的成本。当前 Moe-Buddy 尚未接真实端点，不预先承诺节省比例，也不为了缓存扩大传输范围。

#### DSH.2.5 先给能力目录，再按需取正文

skill 工具先确认当前作用域内存在且可由模型调用的技能，再加载正文。pre-step 获取带完整性标记的目录快照；不完整快照不覆盖旧目录。目录变化才发布替换，正文由工具结果交付，不再次复制进上下文。证据：`DSH/packages/skill/tool-skill/src/index.ts:127`、`DSH/packages/skill/tool-skill/src/index.ts:213`；说明见 `DSH/packages/skill/tool-skill/README.md:11`。

借鉴方向：共享资料可以提供轻量目录及按需授权查询，不默认全文注入。目录不能泄露本来无权知道的私密标题或实体存在性；目录可见不代表正文可读，正文可读也不代表工具可执行。

#### DSH.2.6 能力可变，要有可撤销的运行生命周期

动态 Plugin 可以定义不可变 Package 版本，分别运行或切换版本；撤销时释放 handler 和 fiber。归属检查按定义它的 session 做，而运行效果可能影响共同进程。证据：`DSH/packages/extensions/cordis-host-runner/src/index.ts:768`、`DSH/packages/extensions/cordis-host-runner/src/index.ts:1219`、`DSH/packages/extensions/cordis-host-runner/src/index.ts:1232`；生命周期说明见 `DSH/packages/extensions/tool-cordis/README.md:19`。

重要限制：host-only 分支可直接进入 activate；Client 分支另有审批与版本授权规则，不能笼统说每次执行都有人确认。`node:vm` 限制环境不等于恶意代码安全隔离。证据：`DSH/packages/extensions/cordis-host-runner/src/index.ts:270`、`DSH/packages/extensions/cordis-host-runner/src/index.ts:277`、`DSH/packages/extensions/cordis-host-runner/src/sandbox.ts:229`、`DSH/packages/extensions/tool-cordis/src/prompt.ts:8`。

对我们只借鉴“候选版本、受控启用、失败撤销”的机制，不引入让桌宠运行模型生成任意代码的能力。受保护人设、工具授权和正式协议仍属于受信控制面，不能因“自我进化”而放开。

#### DSH.2.7 不依赖无限长会话维持连续性

Ralph 每轮交给不继承旧会话的新 worker，传递固定目标与有界结构化报告，并明确要求以工作树确认报告。达到轮数上限返回 budget-limited，不把无限循环当完成。证据：`DSH/packages/workflow/tool-ralph/src/index.ts:153`、`DSH/packages/workflow/tool-ralph/src/index.ts:171`。

借鉴的是“任务恢复依赖可验证产物，不依赖无限历史”。桌宠不能照搬共同文件夹为共同记忆：不同桌宠的私人经历仍隔离，共享产物仍需发布许可。完成声明也需实际回执或评测，不以模型自报作独立认证。

### DSH.4 建议讨论的最小框架

下面是讨论方案，不是已批准的新阶段或待自动执行的计划。先不改记忆大类，不引入图数据库、模型 SDK、通用插件运行时，也不承诺新的 crate 数量。

```text
可信交互与工具回执
        ↓
会话事件记录 ──→ 获准上下文视图 ──→ 模型/离线夹具
        ↓                               ↓
可核验原始证据                    学习候选，不直接写库
        └──────────→ 宿主校验 ←─────────┘
                         ↓
                  已有私密记忆接口
                         ↓
              独立共享审查 / 技能候选
                         ↓
                离线评测、受控启用、回退
```

- **会话记录适配**：记录稳定宠身份、会话/事件 ID、输入性质和必要回执；与现有记忆命令日志分开，不默认长期保留原始聊天、屏幕内容或凭据。留存、备份及删除政策待确认。
- **上下文组装器**：保留受保护身份与必要约束的预算，按权限、有效性和任务选片，返回真实输入引用、预算与降级原因。若要复现模型请求，需要定义受控快照或引用保留策略，不能借审计复制更多私人正文。
- **学习协调器**：以用户明确纠正、独立工具回执或经过审查的交互作为候选证据；区分事实、推断、临时任务状态与技能建议，复用任务栅栏和提交接口，不把模型注入内容算成新观察。
- **可演化策略/技能管理**：后续再定义版本、试用、回退与有效范围。先允许建议，不默认允许修改身份核心、系统协议、工具权限或执行代码。

优先讨论顺序是：先明确交互证据和会话留存，再定义请求上下文与可回查性，然后做离线学习候选和固定场景评测；自动共享、真实传输及能力执行另行确认。这里不创建 M6 或新的接力任务。

### DSH.5 “进化有效”的验收建议

以下是建议的后续测试，不代表本轮已经实现或运行：

1. 用户明确纠正后，下一次回答采用新事实，旧摘要与依赖项失效。
2. 空会话反复开启、检索、压缩，不新增独立证据、不续期、不提高事实可信度。
3. A/B 桌宠同文私人记录不混入目录、提示词、日志恢复或共享资料。
4. 整理过程中发生删除、到期、撤权或切换实例，迟到候选不能提交。
5. 裁剪省略可见，工具 call/result 关系完整，摘要比原输入小且绑定正确版本。
6. 一项技能改善预先定义的目标场景，同时不增加越权、来源错误或其他场景的退化；否则拒绝启用或回退。
7. 执行失败、取消、不确定提交与预算耗尽分别报告，不用生成的解释冒充成功回执。
8. 检索/压缩前后记录用量、延迟与质量；真实端点未测之前不宣称固定成本节省或效果提升。
