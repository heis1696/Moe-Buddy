# Agent 与对外交流网关契约

## C 素材包与播放器施工契约（2026-10-19）

以下为已交付的阶段4/C现行契约，Windows工程及合成范围的证据与限制见[C验收](REVIEW.md#c-阶段验收2026-10-20)。素材是本地呈现数据，不是档案权威、模型输入或授权入口。新模块留在Tauri宿主适配；Animator及ClipPlayer继续使用现有运行层契约，核心不接触文件或解码器。

### 本地包与硬预算

首批包是一个目录，入口为 `manifest.json`，不接受压缩包、URL、HTML、SVG、可执行脚本或插件。清单UTF-8 JSON严格拒绝未知/重复字段及未知版本，字段为 `formatVersion: 1`、`id`、`version`、`label`、`clips`、`actions`、`defaultAction`。id及各Clip/动作ID为1至64字节ASCII字母/数字/下划线/连字符，版本为正JavaScript安全整数；label为1至64个非控制Unicode标量。各目录ID唯一，defaultAction及动作引用必须存在。

- 序列Clip为 `{ id, type: "sequence", frames: [{ path, durationMs }] }`，首版接受8位非交错静态PNG（灰度、RGB、索引色、灰度alpha及RGBA）；其他位深、Adam7及APNG明确报未支持，不冒称完整PNG支持。GIF Clip为 `{ id, type: "gif", path }`，帧时长取文件中的真实延时。动作是 `{ id, label, clip, mode: "once" | "loop" }`；宿主把它编译为现有Animator定义，不导入任意业务绑定、脚本或表达式。GIF内置重复次数不启动另一套循环。
- 清单最多64KiB；每包最多32个Clip、32个动作，每Clip最多256帧、全包最多512帧；单帧宽高各至多512，RGBA每像素4字节。单个编码文件最多8MiB，全包实际读取的编码数据累计最多16MiB（重复引用也计工作量）。每帧时长1至600000毫秒、单Clip总时长至多3600000毫秒；零时长明确拒绝，不猜FPS或静默钳制。
- 单包解码帧累计最多32MiB；旧包和候选同时驻留至多64MiB像素，另设至多8MiB可控解码/合成临时缓冲，编码缓冲也须有界。计数、乘法、累加均在分配/解码前检查，不能先收集全部帧再检查预算。OS解码器内部开销单独说明，不把应用可控像素预算宣称为进程RSS硬上限。
- 资源路径只允许包根下相对路径、正斜线分隔；拒绝空组件、`.`、`..`、反斜线、绝对/盘符/UNC/设备路径、冒号、控制字符和根外解析结果。不跟随包内symlink/junction/reparse重定向；须在实际打开/读取边界复验，不能只对文本做normalize。Windows从本地盘根逐段持有目录句柄，禁止写入/删除共享；包根句柄覆盖整次加载，内部父目录及文件句柄覆盖实际读取，句柄路径直接核对、不重新跟随名称解析。每条绝对目录链最多128个组件，超限在打开前拒绝。素材读取只读、不递归扫描、不中转到业务存档，不自动复制或修改来源文件。
- 格式头、尺寸、帧数、矩形及实际字节内容都须验证，扩展名不证明格式。PNG不支持APNG时明确拒绝。GIF必须正确处理调色板、透明、局部矩形、交错及disposal 0/1/2/3；保留/清背景/恢复上一帧用可断言的像素夹具验证。坏流、未支持语义、截断和超预算保留错误链并明确拒绝，不交付部分包或伪造播放成功。

预算补充：512边长同时约束GIF逻辑画布、局部矩形和每张合成输出。32MiB计全部Clip的完整RGBA帧，不只计算局部图块；64MiB含旧包及唯一候选，不能并发准备第二个候选。8MiB临时额度含合成画布、disposal=3备份、解压/过滤/LZW工作区及向不可变帧转换时的额外副本；当前编码文件缓冲最多8MiB，清单另计64KiB，累积读取工作量仍为16MiB。解析器自身的额外压缩数据副本计入临时额度，所有容量须在创建前有界。

首版GIF合成明确采用透明呈现策略：初始画布全透明；disposal 0/1保留，2将上帧局部矩形清为RGBA全零，3恢复绘制上帧之前的画布。透明下标不覆盖已有像素，其他像素alpha=255；LSD背景色不作为不透明窗底。该策略须在README及独立像素夹具一致声明，不把系统GDI+不同背景结果当作通过。GIF原始延时不按浏览器习惯钳制。

### 播放与资源所有权

原生命中区域清除失败是独立故障锁：保留旧帧/区域及Unknown证据，非恢复命令在副作用前拒绝，不能用播放清掉错误。只允许显式停止/卸载在原生清除实际成功后解除锁；宠物掩码回包、旧暂停入口、后台tick和只读刷新不能解锁。builtin显式暂停/继续和旧TogglePause均核验实际状态与活动票据，停止/卸载后保持empty帧。关闭确认一经受理即失效既有加载候选，同轮取消关闭不会使候选重新有效。

已验证包是不可变资源；播放实例单独持有票据、游标、模式与暂停状态。prepare核对Clip ID、版本、时长和能力，不停止旧通道。advance只消耗注入毫秒并回报下一个边界，按变长帧区间决定画面；前端只绘制权威帧，不用GIF标签、CSS动画、墙钟或requestAnimationFrame再推进动作。

候选加载失败不得改变旧包、旧动作或稳定伙伴身份；完整验证成功后才停止旧通道并发布新包。停止确认失败则保留故障锁，不宣称切换成功。成功停止释放播放持有的帧/票据，已加载目录可保留以供显式重播；卸载、成功替换与宿主退出还须释放旧包的像素、解码器及前端画面缓存。测试分别证明通道引用和包引用归零，不以暂停冒充释放。晚到的旧包帧、旧加载结果和卸载后的回包不得复活旧资源，宿主资源代际与前端异步代际须对应。

本批只选择当前进程的呈现包，不扩展buddies.v1或恢复文件格式，不默认落盘素材路径或绑定。换皮/播放/暂停/卸载不改变PetIdentity、buddiesRevision、人设/模型版本、私密记忆、会话、Key或发送许可。主窗的素材选择意图仍须捕获并在执行/发布时复验B的完整context；宠物窗只获呈现数据，不新增伙伴目录或业务权限。具体IPC见下节，不提供无上下文的文件读取或任意路径取帧接口。

### C 跨端接线契约

本批选择入口采用Tauri已有原生拖放事件：用户将素材包目录或其中的manifest.json拖入主窗素材区域，前端在接收事件时固定完整B context和当前资源代际，明确派发一次加载意图。不新增对话框插件或依赖，也不需要路径编辑表单；不能借素材动作消费buddyCommit或清B管理稿。只在此受控导入命令接收路径；要求本地磁盘绝对路径，拒绝UNC/远程/设备根，不能把D的业务data-dir变成可从前端指定。路径不进入响应、宠物窗、错误正文或档案。测试用临时路径显式调用同一入口，不新增生产测试后门。

- `prototype_material_state` 为main/pet可读的纯呈现查询；返回 `MaterialState`，字段严格为 `revision, resourceGeneration, playbackGeneration, source, pack, actions, actionId, status, loading, decodedBytes, frameCount, error`。前三项为正JS安全整数；source是 `builtin | package | empty`；pack为null或 `{ id, label, version }`，actions为 `{ id, label }[]`，actionId为string或null；status是 `playing | paused | stopped | faulted`，loading为bool，decodedBytes/frameCount为非负有界整数；error为null或固定安全 `{ code, message }`。不含路径、伙伴信息、票据或业务正文。状态变更事件 `prototype://material` 只向main/pet发布同一投影，revision单调，旧查询/事件不得覆盖新状态。
- `prototype_material_command { command, context }` 仅main调用，执行时复验B完整context；command使用 `type` 判别，所有命令必含 `expectedResourceGeneration` 和 `expectedPlaybackGeneration`。类型为 `load { path } | play { actionId } | pause | resume | stop | unload | builtin`，附加字段按该类型严格解析。回复 `{ ok, state, error }`；state为上述MaterialState，error为null或现有安全Failure形状。C错误只处理C意图，不解除B Unknown或改变业务状态。load立即返回已受理/拒绝；最终成功/失败由状态事件或重读体现，loading结束不等于加载成功。失败保留旧包和播放，安全error给出明确原因。
- 首次加载只保留一个后台任务及一个有界结果通道，读取/解码不占用HostWorker循环。后台持有私有加载序号、原始context、资源/播放代际与取消标记，仅返回不可变候选；HostWorker发布前复验所有绑定以及退出/撤权状态。loading期间其他load/play/builtin明确Busy；stop/unload、伙伴切换、撤权和退出使候选失效，不得以新context续用旧请求。候选未结束前不启动第二个加载；取消合作检查点覆盖读取/解码主要循环，迟到结果只释放。退出先失效并收口后台任务，再按既有确认链释放，不能卡住B草稿/退出邮箱或虚报已释放。
- 沿用 `prototype://frame` / `prototype_frame`，`FrameSnapshot` 扩成严格必填 `{ resourceGeneration, playbackGeneration, presentationSequence, source, clipId, frameIndex, width, height, paused, faulted }`。代际/序号均为正JS安全整数；source同上，builtin固定clipId=`idle-four-frame`且320×320，package使用真实Clip及0至255帧索引，empty时clipId/frameIndex为null、width/height为0。停止/卸载/单次结束发布显式empty帧，不能用第0帧冒充仍在播放。资源代际在成功装包、卸载或恢复builtin时推进；播放代际在实际新播放与停止时推进，同包重播也不能复用；presentationSequence在帧/暂停/故障/空状态改变时全局单调推进，不因切包或伙伴切换重置，耗尽拒绝而不回绕。
- `prototype_material_pixels { frame: { resourceGeneration, playbackGeneration, presentationSequence } }` 仅pet调用；只复制与三项完全匹配的当前package帧，返回Tauri原始二进制Response（RGBA，长度恰为当前width×height×4、最多1MiB），其他来源或陈旧请求明确拒绝。不接路径/Clip索引，不给任意资源读取能力。pet最多一个在途取帧、一个最新待处理描述；绘制前再次复验三项及组件代际。无效/卸载回包立即丢弃，不缓存全包或独立计时，不自动重试同一失败令牌。
- 原 `prototype_set_hit_mask` 保留width/height/alpha，并增加必填frame三元组；仅pet可写，宿主在实际原生应用掩码时复验当前三元组，失配不得更新。停止/卸载立即清除旧命中区域；empty清空使用1×1零alpha及对应empty帧三元组，拒绝empty下非零alpha。加载新包和同包重播均不能被迟到掩码覆盖。原pet/tray暂停仍只操作当前呈现，不返回业务context；主窗新素材控制走上述带context入口。
- 前端只保留一张源RGBA、一份在途二进制及必要的当前/待替换Canvas/ImageData；应用可控呈现副本合计上限16MiB，显示backing宽高各至多1024并等比缩放，命中掩码至多256×256。不得为每个Clip/帧按窗口或DPI复制画布。停止/切包/组件释放要清空旧Canvas尺寸并丢弃像素引用；后台及IPC生成使用有界队列，单次二进制最多1MiB。上述是应用可控缓存预算，不声称浏览器/IPC引擎或整个进程RSS硬限。

既有测试猫只作为builtin呈现，正式包使用同一Animator驱动真实SequenceClipPlayer；复用必要的只读帧视图，不开放可变播放器或绕过stop的资源替换。prepare得到的新目标在停止旧播放后必须仍可start，这是现有Animator的实际调用顺序，不允许修改内核顺序掩盖适配错误。

## B 角色档案与实例管理施工契约（2026-10-18）

以下为阶段3/B现行跨端接口，实施与验收状态见REVIEW。A会话契约继续适用，不接受缺字段的旧主窗命令兼容旁路。

- 主快照增加必填 `activeBuddyId: string|null`、`buddiesRevision: number`、`buddies: { id, label, profileRevision, personaRevision, modelRevision }[]`，以及当前受信档案的 `activeBuddyPersona: string|null`。后者用于未配置模型时显示和编辑已有的人设，不返回其他伙伴正文；无活动伙伴或撤权时为null。实例ID为非空ASCII安全标识，最多64字节；最多8个伙伴，显示名最多64个Unicode标量且不允许控制字符。修订是正的JavaScript安全整数，耗尽明确拒绝。撤权后活动ID为null、列表为空；列表不授予私密数据或外传权限。
- `buddiesRevision` 是受信注册表的选择/档案栅栏：创建、切换及已提交的档案/绑定配置变更均推进，A→B→A不得回到旧修订。档案、人设和模型配置分别有版本；人设与模型配置的实际内容和版本必须同属一个受信提交，不能只在界面计数。模型预设选择也纳入对应伙伴的绑定，恢复不由全局最后设置覆盖。
- `prototype_dispatch` 保留 `command`，另增加必填 `context: { expectedBuddyId: string, expectedBuddiesRevision: number }`。所有主窗业务命令，包括关闭/确认/撤权和管理面板操作，均在执行时复验此上下文；缺失、旧修订或另一伙伴明确拒绝为NotExecuted，不改变当前身份。现有会话命令还须复验自己的会话ID/目录修订，伙伴上下文不能替代A的校验。
- `prototype_management_draft_state` 同样携带必填 `context`，并增加必填 `kind: none | general | buddy_create | buddy_rename`；主快照 `managementDraft` 同步增加此字段，回执仍仅 `{ version, dirty }`。`dirty=false`只允许none，`dirty=true`必须是其余三种；每次编辑或种类变化推进版本。受信邮箱更新及最终消费都要绑定伙伴与选择修订，旧同步不能污染另一伙伴或使旧关闭确认有效。只读快照可无上下文；原生窗口/托盘动作由宿主取得当前受信上下文，不允许WebView借窗口命令绕过业务校验。
- 新增 `create_buddy { label, persona, expectedManagementDraftVersion }`、`switch_buddy { id }`、`rename_buddy { label, expectedManagementDraftVersion }`，均经上述context进入。创建/改名表单属于受保护管理草稿；提交只可消费同伙伴、同选择修订、同种类且精确版本的对应dirty表单，不能借保存清掉其他编辑。版本为非负安全整数。提交期间仍保留退出保护，禁止先将邮箱标clean再开始I/O；成功仅清匹配的提交版本，更新编辑保留，失败或Unknown不清稿。切换仍拒绝任何未保存管理稿。新建成功选择新伙伴；新ID由受信注册服务签发，前端不提供ID/路径/继承来源。初始模型未配置且没有凭据/发送许可。人设后续编辑沿用模型配置入口并推进绑定版本，改名仅推进档案版本；本批不提供复制私密经历或删除入口。
- 创建/切换要先确认本地执行与展示已结束、没有待处置存储错误或关闭确认；除上述精确匹配的本次创建表单提交外，不得带着未保存管理编辑切换。Unknown沿用A的合法隔离资格，只隔离旧请求，不解锁存储或管理未知。草稿同步成功后才能切换，失败保留原选择和文本。原实例及其未提交聊天草稿有界保留；关闭聊天只处理当前伙伴当前会话，退出进程保护全部伙伴全部会话以及管理草稿。
- 宿主保持全局单调 `presentationRevision`；伙伴内部的应用修订不得重置全局快照排序。前端所有缓存、预期版本、操作未知锁及异步回填至少按伙伴ID/选择修订隔离；聊天缓存进一步按会话ID隔离。发起时捕获context，不能在回包时用“当前伙伴”替换。新伙伴的模型表单、记忆/诊断视图及API Key输入不能从旧伙伴回填，释放、撤权和显式丢弃后的旧回包无效。
- 外部请求保持原应用私有票据，另外由宿主保存准确的所属实例；拒票不消费另一实例pending，不把结果投递给当前活动伙伴。配置/人设改变仍复验原有来源、版本与许可，不靠新注册表绕过既有业务服务。切换不是取消证明，不能把旧Unknown改成Ready或自动重发。
- 档案存储由共享适配负责有版本的有界元数据、排他写入、预期版本发布和准确I/O处置；旧档案明确绑定 `offline-companion`，新实例身份永不复用。档案含非秘密模型/人设及版本，但不能恢复运行权或接纳任意路径。API Key和发送许可仅属于对应实例的本次进程，不默认复制或恢复；重新打开应用须重新显式配置凭据/许可。
- 注册表不是记忆后端或素材管理器。仍用现有私密身份隔离、原文稳定域和授权复验；原A的全根容量、留存、pending保护及旧格式恢复要求不放宽。换皮、播放/暂停与窗口可见性不得改实例ID；正式素材实现留给4/C。

首批集成后的细化要求：

- ID严格使用首字符ASCII字母/数字，其余字符只允许字母、数字、点、下划线或连字符；名称非空且不含控制字符。人设非空白、最多4096个Unicode标量，允许LF/CR/TAB而拒绝其余控制字符，保留D/A已接受的多行人设；不能让旧合法设置因新增档案校验而无法恢复。
- 注册表编码单帧最多256KiB，发布时current与pending分别有界，不能在大小检查前无界读取。`buddies.v1`成为B档案与非秘密配置的唯一权威；旧settings仅用于明确首次接入，不能在后续启动、配置保存或旧宿主入口中覆盖B绑定。
- 已接入B后注册表缺失必须拒绝，不能据“没有buddies.v1”自动重做迁移、回退修订或遗失伙伴目录。首次接入证据须持久化且有界，既有实例目录/注册痕迹也需复验；坏档、未完成接入及缺失文件保留现场。该要求不宣称能抵御整套存档被恶意一致回滚。恢复的档案版本须满足 `personaRevision ≤ modelRevision ≤ profileRevision ≤ buddiesRevision`；预设目录ID、实际绑定及恢复后可选择ID必须一致。
- 同一宿主持有一个共享存储门面及根写锁，串行复用同一个LocalMemory和全根预算；有界保留已打开的各伙伴应用实例，切换只改变受信选择，不以销毁重建应用丢草稿或重置运行水位。不得把共享锁句柄开放给前端或任意调用者，用同根第二个独立写者绕过排他锁。
- 切换前准备/验证目标，成功发布注册表后再发布活动投影。配置同样先做无副作用预检，以档案的实际发布回执为准推进内存绑定；已发布但内存应用失败须报告准确已提交/未知并封闭不一致运行，不回写旧配置伪造回滚。pending/write/sync/publish失败保留现场；确定未执行与已有副作用必须分开。恢复先确认注册表完整，再按匹配身份加载数据及版本，凭据/发送许可清空。
- 注册表的 `NotPublished/Published/Unknown` 仅描述该文件发布结果，不能单独推断整次操作的 `NotExecuted/Settled/Unknown`；目标准备、来源登记、历史恢复及运行配置可能有独立回执或失败。宿主须保留错误链并复验所有实际副作用，不能将包裹的存储Unknown因注册表未发布而降格为未执行。
- 创建前检查未完成档案发布；准备发生来源/原文副作用后失败，保留一个有界的候选身份、已有回执和待处置状态，并阻止再次签发新身份。不能丢掉候选应用后继续制造不可选择的原文目录直到共享预算耗尽；不自动删档或续发。跨重启也须识别待处置候选，保留现场并拒绝继续创建。
- 候选准备的保证沿用下文F.4/F.5及MEMORY的既有平台边界：必须先完成候选文件sync_all，再开始来源/原文准备；目录同步成功、不可用和实际调用失败分别报告，不能丢弃候选阶段的同步结果。Windows目录同步不可用时按FileSyncedDirectorySyncUnavailable交付，不声称新目录项可抵抗掉电或已实现跨文件掉电事务；实际文件/目录同步失败停止准备并保留现场。进程中断与有界故障恢复是当前验收范围，突然掉电后防重签不在已保证范围。清候选使用独立I/O阶段，不能把已发布后的清理失败描述成“发布未完成”。此处澄清既有保证，不引入新依赖或用不可用的目录同步条件禁用Windows创建。
- 注册表Unknown冻结选择与新业务，但不能封死既有实例的安全处置。提供按已知实例、私有票据及预期草稿版本约束的只读检查、原请求回执收口、撤权和显式退出丢弃窄入口；不能开放任意普通业务访问。退出仍先保护全部伙伴草稿，允许用户取消或明确确认后正常退出，不用整体销毁对象代替确认。
- Unknown期间，已知活动实例的管理草稿元数据同步也属于受限处置：仍复验完整既有context、kind、递增版本及确认水位，不接受正文或改变业务配置。不能因为普通业务被封闭而拒绝该同步，导致前端flush永远失败、取消/确认退出都无法送达；新编辑继续使旧确认失效。
- 首次接入状态的复验覆盖新旧全部公共适配入口：配置读取/保存、应用打开及伙伴门面均检查注册表、onboarded、candidate、实例痕迹与pending。缺档或中断时不得从旧settings回退或创建空memory；兼容入口不能成为绕过B恢复拒绝的路径。
- 旧应用打开也不能仅凭没有settings就判断首次使用：已有chat目录内容或memory.pending即是存档证据。原memory.v1缺失必须拒绝，不能创建替代日志；该检查复用首次接入的同一窄校验。RawLocal本身的独立原文契约不变，桌面恢复夹具需具备真实桌面档案原有的记忆日志。
- `prototype_window` 的主窗 `show_chat | hide_chat | quit` 请求增加必填 `context`（与业务派发同形），排队后在执行时再核验，缺失或陈旧即拒绝。主窗发起上下文不得由宿主补取最新值；WebView退出保留原context直到退出意图实际受理。原生窗口/托盘事件由受信宿主捕获上下文。宠物窗仅保留原有呈现/聚焦入口，`show_chat`只请求聚焦受信主窗，不返回伙伴目录或正文；宠物窗不接收业务派发、hide_chat或quit，不通过新增只读业务接口获取上下文。
- 管理稿丢弃和后续隐藏/退出是不同回执：丢弃已完成但窗口效果失败，回复须含已提交丢弃回执及后续错误和准确disposition。全伙伴Quit最终回复取全部提交后的最新快照，不能返回提前构造的close_result；不依赖事件必达来补齐调用结果。

### B 档案提交回执与编辑协调（2026-10-19）

快照新增必填 `buddyCommit`，为null或 `{ kind, fromBuddyId, fromRevision, toBuddyId, toRevision, managementVersion }`。kind只允许 `create_buddy | switch_buddy | rename_buddy | configure_model | select_preset`；ID遵循伙伴规则，修订是正安全整数，toRevision等于fromRevision加一；managementVersion为非负安全整数。回执只含最近一次已成功档案动作的控制信息，由宿主在持久化和所需运行绑定实际完成后签发；创建/改名使用精确提交版本，其他动作捕获受理时的管理状态版本。回执不含正文、Key、路径或执行票据，不落盘，启动/撤权时为null，不证明其他Unknown已解除。

普通快照修订推进仍不能使旧排队编辑取得新context。当前操作的成功回执若精确匹配发起伙伴/修订、动作、管理版本及仍有效的本地编辑代际，可协调到回执指定的新context并消费相应成功结果；事件先到、调用回复先到或丢失后重读均按同一证据处理。无匹配证据或已有更新编辑时保留文本与退出保护，不清API Key输入或回填旧配置。成功模型保存须正常清除已提交的密码输入并退出脏状态，不要求用户随意再改一个字符才能继续。

伙伴切换意图在首次点击时固定完整context，草稿/管理状态同步的每个等待边界都复验同一context，不能同步完成后重新取较新修订派发。创建/改名的事件和调用回复共用精确提交证据与本地编辑代际；创建成功后的活动身份变化不能先清掉提交后新增的表单。新增稿保留其未提交性质及退出保护，不自动套用到另一伙伴。

创建/改名提交正文、表单快照、编辑信号及管理保护版本还须在首次等待前一同捕获。聊天或管理同步等待后若表单/版本已改变，取消本次提交并保留新稿；不能把旧正文与等待后取得的新版本拼成一份提交。用户再次显式保存时重新捕获当前完整意图。

宿主在自己的成功配置/预设提交后，将匹配旧context的现有管理状态受控绑定到新context，保留尚未消费的dirty/kind/version；不把更新编辑当作已保存，也不放行旧context队列。前端显式点击保存可以在当前获准context下重新同步当前表单作为新的用户意图；这与后台旧队列自动改用新修订不同。创建/改名沿用精确提交版本的消费。故障测试针对当前buddies权威文件及真实提交阶段，不能继续用旧settings文件制造不相关故障。

## A 会话生命周期施工契约（2026-10-18）

以下为阶段2/A 冻结的产品与恢复边界，实现和验收状态以现行计划及 REVIEW 为准。

- 稳定逻辑会话 ID 由受信应用签发，前端只选择已有 ID，不提供归属、文件路径、运行身份或权限。归档后仍能显式选择查看，但不能发送；归档不触发原文回收、删除、续期或长期记忆操作。本阶段不提供解归档、删除会话或自动摘要。
- 主窗新增 `new_session { expectedSessionId, expectedSessionsRevision }`、`switch_session { id, expectedSessionId, expectedSessionsRevision }`、`archive_session { id, expectedSessionId, expectedSessionsRevision }`。生命周期命令在应用层复验当前会话与目录修订；拒绝陈旧命令，不从请求切换受信身份。归档目标限当前会话，不隐式创建下一会话。新建和切换期间若有本地在途执行、未完成展示发布或关闭确认则明确拒绝；已经结束本地处理的 Unknown 允许用户显式新建隔离会话，旧会话保持 Unknown。
- 主快照新增 `activeSessionId: string|null`、`sessionsRevision: number`、`sessions: { id, label, archived, status }[]`，状态沿用 `ready | sending | failed | unknown`。ID 为不超过 64 字节的非空 ASCII 安全标识，目录最多 64 项且无正文；修订为可安全传往 JavaScript 的递增整数。撤权后 ID 为 null、目录为空，不靠目录授予正文查看或发送权。归档当前会话仍保留其选择和原状态。
- `set_draft` 与 `send` 增加必填 `expectedSessionId` 和 `expectedSessionsRevision`，防止排队的旧草稿/发送在切换后进入新会话；原命令其他字段不变。聊天草稿在应用内按会话有界保留，切换不自动丢弃或搬运草稿，草稿不因此获得落盘许可。前端先完成当前草稿同步，再请求生命周期动作；迟到回包按会话/修订及释放、撤权状态复验。
- 草稿权威不能取自会隐藏/卸载清空的展示缓存。生命周期命令先校验聊天面板可见及可接收切换，提交后的展示失败不得声称 NotExecuted。关闭聊天仅处理当前草稿并保留其他会话；退出整个应用须覆盖全部会话草稿及原有管理草稿，确认绑定待丢弃集合的版本和退出意图，新编辑使旧确认失效。退出取消不清稿，确认丢弃仅消费匹配版本；前端丢包后的恢复同时检查会话 ID、目录修订及交互代际，A→B→A 不能复活旧稿。
- 主窗草稿控制投影为 `chatDraft: { revision, discard, sessions }`；`discard` 为最近一次显式丢弃的 `{ revision, sessionIds }` 或 null，`sessions` 最多64项 `{ id, revision, discardedRevision }`，后者保存该会话最近变更修订与最近显式丢弃修订（无丢弃为null）。全部修订为安全整数，无正文、不落盘；撤权后列表为空、discard为null。按会话保留丢弃水位，其他会话的编辑不能使旧回执失效，漏收多次事件也不能复活已丢弃缓存。前端按每份缓存的同步修订及本地编辑代际消费，保留更新未同步正文；不能把普通空快照当作丢弃，不能仅因全局修订前进就跳过会话丢弃水位。
- Unknown 至少区分外部请求未知与持久化/管理副作用未知。本地取消、执行释放和截止等号拒收不证明外部请求取消；已交给外部的请求在缺乏确定证据时保留未知，不自动重发。显式新建只隔离旧会话的发送未知，不能解除存储故障、撤权或记忆/设置的未知锁。普通快照不解除业务 Unknown。
- 主快照另有必填 `sessionIsolationAllowed: boolean`，仅在当前会话存在受信服务验证的未结请求证据、本地处理已结束、没有存储隔离/撤权时为 true。证据可来自本次外部Unknown回执，或当前许可下完整恢复、核对并持久化的历史未结原文；旧v1没有新目录字段不构成永久禁用隔离的理由。历史证据不证明请求曾实际外发，传输状态仍未知。只有Unknown状态标记而无合法请求证据、未恢复存储或存在坏档/pending时不得放行。由应用裁决，前端不得由操作名/错误码推断；它只允许显式另开，不解锁旧会话或全局副作用，命令仍复验全部条件。
- `ExternalRequestTicket` 继续由应用私有签发，复验应用实例、逻辑会话、执行代际与轮次后才消费 pending；拒票不得触发保存、发布或影响另一会话。切换不恢复旧任务，恢复数据不包含执行许可，未知历史不自动变为可发送会话。
- 执行代际轮转必须在受信边界完成：先确认旧本地执行已结束、维护留存并成功封存，再建立独立运行身份和新原文基线；失败不发布半切换，持久化结果不明时保留现场并封闭写入。原文继续使用 RawLocalStore/RawSnapshotV1 的现有授权、期限、坏档及 pending 保护，不拿空运行覆盖既有基线。历史冷存放在适配层，按明确总容量有界管理；恢复只按需加载有界只读投影，不把每次重启的旧片段全部塞回新执行代际。
- 在线发送/检查点及宿主定期维护接入既有 `maintain_retention`；截止等号、回收区背压、撤权清理和部分维护结果按原服务契约报告。轮转不把归档当作回收或删除；留存仍为已授权的正常 30 天、回收 7 天，不新增正文副本、导出或传输范围。
- 容量按 REVIEW 所有者逐项交代：应用与原文额度真实结算；Agent/入口/许可与导入账本随隔离执行代际有界退役，旧句柄不得复活；诊断运行/别名采用显式代际轮转并展示历史缺口。WorkflowRuntime 原本逐轮析构、MemoryTask 原本无累计登记表，不增加无用治理层。LocalMemory 及其幂等日志、来源/版本水位独立保留，达到硬限明确背压，不能用会话轮转清空或假称日志压缩已实现。

### A 持久化分代与容量收口

- `ChatHistory` 扩展为纯注入契约，覆盖加载目录、封存当前代际、创建独立基线、CAS 发布目录、按会话加载有界历史页和有界维护。适配负责文件 I/O，应用保留会话状态与切换裁决。恢复目录只包含稳定会话/存储段标识、修订、归档和结果证据；存储段序号仅用于定位数据，绝不恢复运行身份、票据、执行权、API Key、外传许可或草稿。
- 旧 `chat/raw-local.v1` 作为一个受管理的旧段接入，先用既有授权链恢复、净化和封存；原文件保留，不能复制正文后遗留一个不受维护的旧副本。缺目录仅允许明确首次创建或可验证的旧格式接入；目录缺失但新段已存在、坏目录、未知版本或 pending 必须保留现场并拒绝，不能重建空目录覆盖。单写锁覆盖目录与其段集合。
- 切换/轮转顺序为：复验当前授权及本地执行结束 → 维护 → CAS 封存旧段 → 准备独立新段和运行身份 → CAS 发布目录 → 发布应用切换并释放旧执行代际。原文检查点和目录提交分别持有真实回执，不宣称多文件天然原子；目录发布前崩溃或结果未知须能识别候选/现场，禁止静默丢段、重发或让目录 Ready 掩盖原文未结交互。完整旧/新段证据无法统一时按未知封闭。
- 活跃代际仍使用原有 64 事件/65536 字符、片段及 Agent 限制；在下一轮受理前预留所需额度，达到安全阈值时封存并轮转。反复启动、TTL 新片段和会话切换均不得把旧冷段导入新执行区累计占位。展示只取有界近期投影并明确历史窗口，冷段不是默认模型上下文。诊断可独立轮转，记忆/预设高频操作也不能静默耗尽运行/别名额度。
- 应用依据实际登记回执跟踪本执行代际的片段句柄；达到正常区8片段额度即在下一轮登记前轮转。活跃TTL截止等号后的新片段也计入，不能只按总事件/字符推算；计数仅随成功封存后的代际释放，Agent绑定及原文账本仍由各自服务维护。
- 持久化根的初始工程硬限为 64 个逻辑会话、256 个受管理原文段、16 MiB 原文段及目录总字节；预检同时计入待发布候选、pending 与当前文件的峰值占用，不能只计算最终文件。单段仍受 RawSnapshotV1 和运行时原上限约束。尚未到期的内容不能因满额自动删除；达到根预算明确背压。目录标签有界，未知/归档状态不凭正文到期自动消失。此为分层容量，不承诺无限会话目录或无限留存。
- 256 段是当前受管理段上限，不得变成永不归还的累计生成次数。最终到期且正文已由既有服务清理的冷段可受控退役，须先将不可复用段序号/必要撤销证据持久化到有界目录栅栏，再释放段额度；未到期、未确认提交、未知正文状态或坏档不得退役。退役的旧文件/快照不得重新成为可选活动段，失败保留可识别现场。归档及 Unknown 会话目录本身不因退役删除，正常/回收期限不变。纯内存切换同样不能只保留展示文本而丢弃权威原文及账本来重置容量。
- 退役标记只保存待完成工作的数据，不授予删除权。首次退役和重启续做均须用当前原文许可复验精确域，取得并保持同一RawLocal段锁，核对标记绑定的已净化帧版本/提交回执及当前空正文事实，再按阶段删除。另一合法写者持锁、帧已改变、域/授权变化、坏档或未结pending都保留现场并拒绝；不能在 `open_directory` 尚无当前授权时直接删段。中断后缺失文件只在匹配且明确的已完成删除阶段中接受，不能把任意缺档当成删除成功。
- 现有正常30天/回收7天期限继续由原文服务维护，冷段也不能绕过期限与授权复验。维护有工作量上限及进度，错误和回收区背压如实返回；正常/回收到最终到期的原文清理继续保留必要防重放与来源水位，不能通过重开旧段复活正文。内存模式同样说明保留数据预算，不能靠默认落盘或丢弃未到期原文获得无限运行。
- 未结交互的结果证据与正文显示窗口分开：回收区不展示正文、页大小为零或正文最终到期，都不证明交互成功或取消；旧格式首次纳管须在净化前提取获准控制证据并持久化未知状态。启动/恢复时收紧的期限必须在报告恢复成功之前按原文契约实际提交，不能只做只读投影后封存目录；后来换回较宽策略也不能恢复已收紧期限。
- 未结概要覆盖所有受支持的交互，不能只取最近一条终态；较新Completed不覆盖较早未结。任何会清除这类原文证据的净化/退役之前，先耐久发布无正文的未结概要，发布失败保留原文；后续启动/新段创建失败再恢复也不得变回Ready。读取工作量预算必须包含实际文件读取、解码及重复处理，在正文分配/解码之前裁决，不能先完整preview再把超预算结果排除统计。
- 冷维护的峰值预算按净化后实际编码长度预演，包含回收元数据增长、目录和退役标记；不能拿旧文件尺寸代替候选尺寸。容量阻塞须有明确原因、实际进度和已经取得的回执，不能静默当作普通分页结束。自动分代若已提交，后续发送拒绝必须保留分代回执及准确处置，不声称整次命令 NotExecuted；优先在任何提交前联合检查轮转和本轮预留。
- 历史读取同时限制段数、编码字节、事件和正文窗口，按近期顺序逐段读取，满足窗口即停止；零条请求不读取正文。不能先聚合全部段再截128条，独立控制证据不能为了展示分页重新依赖完整正文扫描。实际授权、版本及期限复验不因页大小省略。
- LocalMemory 的 `CapacityExceeded` 仅在明确日志追加前拒绝的调用点映射为稳定容量错误及 `NotExecuted`，保留原错误链；日志写入不确定仍为 Unknown。聊天分代保留同一个权威记忆后端与水位，不引入日志压缩、旧库迁移或新记忆格式。

持久化目录文件仍命名 `sessions.v1`，内部载荷版本为2，分别记录 `externalUnknown` 和 `recoveredUnsettled`。旧v1目录缺少恢复证据不自动授予隔离资格，须从当前许可下验证的原文建立；v2缺字段拒绝。原文帧及RawSnapshot线格式仍为v1。冷读取使用 `RawLocalStore::open_projection`，打开即按同一预算读帧并返回可复用计划，避免打开时另做一次无预算解码。退役侧边gate版本2包含完整稳定域、授权修订及帧回执；公开续删接口也核对这些字段，guard持有借用的当前访问并在每步复验。旧式无域gate保留并拒绝续做，gate实际编码长度计入根峰值。

## Tauri 宿主 D 接线（2026-10-18）

Tauri 主窗经有界命令队列调用既有 ChatApplication，新增模型配置、记忆搜索/新增/版本化修改/确认删除、预设与诊断入口；宠物窗无业务读取/派发权限，主快照事件不发往宠物窗。网络和文件代码实质提取为共享 moe-desktop-adapters，两个宿主复用 LocalMemory、RawLocalStore 与原 HTTP 传输；核心和应用不依赖宿主或适配 crate。

- 无便携标记时默认数据根沿用 daily，受信进程启动参数 `--data-dir` 优先指定根；Windows 测试包由可执行文件旁的 `moe-buddy.portable`（内容为 `1` 加 LF）选择同目录 data，WebView 缓存置于 data/webview。无效标记拒绝启动，不回退 daily；前端不能通过 IPC 指定业务数据根。坏档、pending 和恢复错误保留现场并拒绝启动，不覆盖为空库。恢复历史只读、不续跑请求；密钥和外传许可不落盘。人设、获准私密记忆和当前会话的发送许可在界面明确列出。
- 主窗“退出应用”先等待正文/管理稿同步，复验完整发起伙伴 context 和同步队列，再提交既有 Quit 邮箱；撤权后仍允许退出。宿主保持全部伙伴全部会话及管理稿确认，窗口 X 保持 CloseChat 语义。无回复显示未确认且不自动重试；不以强制终止绕过草稿保护。
- 模型凭据只保留在宿主进程，`apiKey` 必须为字符串或 null；空串清除，null 仅在端点/模型未变化时保留。请求携带不可变输入，结果绑定原 ExternalRequestTicket 回交，拒票不能消费正确在途请求。业务和传输结果分别表达，诊断不可从模型回复反推已送达。
- 设置保存的窄详细入口保留 `SettingsSaveStage`、`SettingsSaveError` 与 I/O source；旧 String 门面兼容包装。应用配置已改变后，保存前置拒绝不得写成 NotExecuted；确定的内存修改与关闭外传结果为 Settled，写入/发布不确定仍为 Unknown。磁盘记忆 update/delete 的精确 RevisionConflict 在日志追加前拒绝，固定为 `memory_revision_conflict/NotExecuted`，原 PersistenceError/MemoryError 链保留；I/O 和 RecoveryRequired 不因此降为确定失败。
- 管理编辑以递增版本和 dirty 位同步，不发送草稿或凭据正文。关闭/退出确认同时约束编辑版本和具体意图；确认裁决前有界处理已受理的编辑并合并退出升级，旧确认不能丢弃新草稿或授权更强的退出。普通 `confirm_close` 必须携带 `expectedIntent` 字段（含显式 null），值不匹配当前待确认意图即拒绝。
- 宿主发出的 `managementDiscardedVersion` 是具体版本的丢弃回执；事件或响应先到均幂等消费，匹配版本才清本地编辑，较新的编辑保留。此回执不能解除其他 Unknown 操作。撤权、组件释放和交互代际变化都在异步回填前复验；释放先清展示缓存，迟到回包不得写回。

D交付时将会话新建/切换/归档与有界轮转留给阶段A，没有通过删除存档、清计数或重发规避；其后续行为以本文件A契约为准。真实服务、其他平台、IME和多屏验收独立记录，工程验证见 [审核记录](REVIEW.md)。

## 日用桌面请求与恢复接线（2026-10-17）

用户本轮明确授权桌面真实模型与本地保存；不扩大回环 HTTP 白名单、渠道、生产 Hooks、工具或动画范围。原 `OfflineModel` 保持纯离线；真实聊天在应用层统一七阶段工作流 `chat-turn` v1 内推进：受理、准备输入、请求/等待、接收、解析、提交、发布展示结果。线上使用 `prepare_external → dispatch_external`，离线使用 `prepare → infer`，接收后统一 `finish`；每一步由应用层组合器经 `WorkflowRuntime` 实际驱动并调用原有可信入口、会话、Agent、记忆与展示门面，不在聊天内再嵌套 `AgentWorkflow`，也不复制业务校验。发送与结果提交仍复验预设、来源、上下文／会话修订及撤权；应用留在 UI 线程，只有不可变 `ExternalInput` 进入工作线程，窗口以有界单结果通道收取回执。HTTPS／数值回环 HTTP、无自动重试／重定向／代理，60 秒总超时与 128 KiB 响应上限。超时、断连、不可解析成功响应及 5xx 保守未知；认证拒绝明确失败。

每次外部请求在应用内生成不可由宿主构造的 `ExternalRequestTicket`，绑定本轮及对应 `WorkflowRuntime` 实例；`take_external_request` 只交付一次输入与票据，完成必须使用 `complete_external(ticket, outcome, now_ms)`，没有省略票据的旁路。票据在取走当前 pending 之前核验：重复、跨轮、跨实例、迟到及撤权后回调被拒绝，且不执行检查点、展示刷新或发布收尾，不影响正确在途请求（拒票触发的存储失败也不能隔离后续正确请求）。等待期间保持 workflow 执行票据，UI 不阻塞；`chat_progress()` 只读展示七节点状态、`committed`/`published` 与真实 `AgentDelivery` 业务终态 `business_outcome`，流程 `Succeeded`（含业务 `Unknown`）不能单独解读为业务成功或展示已发布。`publish` 节点只在真实展示门面渲染本轮投影后完成：展示失败时节点 `Failed`、`published=false`，提交回执独立保留并返回 `display_failed`（`Settled`）；已登记回复可在重开面板后读取，不重发模型、不重复登记、不倒改已终结流程。解析节点经可注入窄 `ReplyParser` 执行有界纯文本投影，模型原文与展示/表现提议分离；首版不解释标签、脚本或工具语法，不扩大原文落盘范围。失败、取消、Unknown 均以真实 Agent/会话回执收尾。已受理回调的业务、本地保存与展示失败分别保留于主错误链与独立保留错误中，任一未知副作用不冒充 `Settled`。`ExecutionDisposition` 由应用在受理/提交边界记录（受理前拒绝 `NotExecuted`、权威终态 `Settled`、无法确认 `Unknown`），宿主只展示，不按公开错误码推断。

发送前先检查点既有 RawLocalStore，提交结果后再次检查点；失败不发布虚假保存成功。进程关闭在途请求不会恢复重发。原文适配导入把未结交互降为取消，应用因此保守将恢复的取消／未知标为中断未知并禁用发送；恢复只读展示，不恢复旧执行权，也不自动加入新会话模型输入。原文正常期 30 天、回收期 7 天，遵守既有期限收紧和坏档／pending 保留规则；宿主注入 Unix epoch 基准加单调增量。磁盘与网络不是一个事务，已经获得但尚未落盘的回复不能冒称已耐久。

桌面设置只保存端点、模型、人设；API Key 与发送许可不落盘，重启重新输入／确认。文件系统存储不等于加密；此版不安装系统凭据库。实际服务验收仍需真实端点与凭据，回环结果不作替代。

## 产品边界

入口是“桌宠的对外交流入口”，不是透明供应商 API 代理。调用方指定获准桌宠别名后，人设、记忆和能力边界从请求开始参与，不默认先生成裸答案再二次润色。桌面、协议客户端、渠道与 Hooks 使用同一稳定桌宠，但不共享各渠道原文或推导身份。

| 配置 | 职责 |
| --- | --- |
| 上游 API 预设 | 协议/端点/模型/凭据引用和逐用途绑定，与桌宠身份独立。供应商密钥不交给外部调用方。 |
| 桌宠 Agent | 稳定身份、人设、获准记忆和任务/表现策略，普通记忆不能覆盖工具权限。 |
| 对外入口 | 入口凭据、路由别名、认证主体、渠道范围、会话和原回复目标。localhost 也不能替代鉴权。 |

后续兼容方向可从 Chat Completions 与获准别名列表起步，但当前没有 HTTP 端口；Responses、流式、多模态、结构化输出和工具协议不能假称通用兼容。不支持能力显式拒绝。将来支持严格 JSON/代码时，人设也不得破坏结果格式；表现事件独立，不默认每个后台请求都发声。

微信、办公软件属于已确认场景，具体软件/账号形态尚未选定；普通 QQ 账号是期望目标，困难可延期，不暗中替换为官方机器人。平台适配须验证事件、说话者、重试和回复能力；昵称相同不等于同一用户，单向 Webhook 不等于聊天通道。CLI 优先使用其真实支持的 Hooks，不强制绕行 HTTP，也不默认收集终端、环境、凭据、项目文件或隐藏推理。

```text
鉴权/身份/会话隔离 → 原文登记及即时状态 → 人设与获准上下文
→ 离线推理及结果/表现分离 → 原目标回复和终态登记
→ 闲时固定批次与候选（实际提炼/长期提交尚未交付）
```

原始正文不改写；密钥、鉴权头、未展示推理不进入聊天原文。每轮问答不立即提炼。暂存与工作状态是短期职责，治理后的事实才可成为长期记忆；回收是留存状态，不新增归属类型。

## 预设与统一离线入口

### I.2 G0：预设与可信入口契约（已验收）

#### I.2.1 预设

- 稳定 ID、显示名、协议、端点、凭据引用和默认模型独立于桌宠身份。凭据仅保存 opaque 引用，不保存或导出供应商密钥。
- 用途包括聊天、生图、人设访谈、视觉、语音和记忆提炼；只是显式配置绑定，不表示已支持这些协议或能力。缺失绑定、悬空引用都返回明确错误，不跨预设或跨供应商隐式回退。
- 预设变更使用版本检查，失败不改变状态；删除再建不能复用版本造成 ABA。提供只读解析结果，包含实际命中的预设及版本，不生成上游请求或传输授权。
- 端点只允许严格校验的 HTTPS 地址或字面回环 HTTP 地址；拒绝 URL 凭据、查询、fragment、控制字符和含混 authority。端点合法不等于获准联网，不做 DNS 或可用性探测。
- 扩展参数使用显式允许集合及类型/范围校验；不支持任意嵌套 JSON。身份、上下文、模型、messages、tools、stream、headers、端点和鉴权等宿主字段不得被扩展参数覆盖。未审核的参数拒绝，不静默忽略。
- 当前没有供应商密钥保存/导出、协议 payload 合并或自动检查；这些保持后续适配范围，不借配置扩张传输权限。

#### I.2.2 可信入口

- 宿主登记路由别名到完整 `PetIdentity` 的映射；别名不是上游模型名，也不授予访问权。
- 宿主安装入口凭据和显式允许别名，绑定调用主体、渠道、渠道范围和回复目标；外部输入不可自填这些受信字段。凭据与上游密钥分离，Debug/错误不包含 token 或正文。
- 只接受新用户纯文本输入和可选的客户端会话提示。system/developer、工具、多模态、结构化输出及流式等尚未适配的能力必须显式拒绝；不得丢弃后伪称兼容。
- 请求先鉴权，再校验路由许可与输入。客户端会话提示只在已认证主体、凭据、完整桌宠身份、渠道及渠道范围内解释；不同维度不得合并。无会话提示时每次接纳都分配新请求隔离标记，即使文字或客户端请求 ID 相同也不自动合并或幂等。
- 请求证明由服务私有构造，绑定进程运行实例与配置代际；暴露只读访问器。另一运行实例不能接受旧证明；路由、凭据变更或撤销之后必须重新接纳，不允许旧证明继续授权。配置与计数器溢出失败不得发布半更新。
- G0 鉴权是离线、进程内契约，不声称是已部署的密码学安全网络认证；没有随机 token 生成器、监听服务、持久化或生产密钥管理。后续网络适配需单独审查比较方式、密钥熵、TLS、限流与日志。
- 凭据撤销采用精确 token 墓碑并限制累计签发量，默认活跃 256/累计 512；达到累计预算后仍允许撤销，但拒绝新签发，避免无限轮换造成无界内存。运行实例编号溢出拒绝分配；会话隔离键也包含运行实例，不能只靠每实例从 1 开始的请求/凭据编号。
- 凭据管理句柄同样绑定签发运行实例与局部序号；撤销前校验归属。另一实例或重建前的旧句柄不得命中本实例同序号凭据，拒绝时保持 token、墓碑及配置代际不变。

#### I.2.3 G0 验收

- 多预设/逐用途绑定、版本冲突、删除重建、缺失/悬空错误、扩展字段防覆盖、端点拒绝、Debug 脱敏。
- 不同桌宠/工作区/用户/凭据/渠道/群私聊范围隔离；未鉴权、越权别名、伪造宿主角色、不支持能力拒绝。
- 相同文本或客户端请求 ID 不自动去重，无会话提示默认隔离；固定原请求回复目标，撤权/换路由/运行实例切换拒绝旧请求。
- 确认预设和入口凭证不能授予模型传输、记忆读取或工具执行；不修改既有记忆授权或日志格式。

### I.3 G1：会话时效与有界内存暂存（已实现）

- 完成 G0 验收后才实施本批；遵守 [会话设计](GATEWAY.md#会话与暂存)。使用 G0 可信请求，不接网络或模型。
- 宿主注入进程内单调毫秒时间；默认 30 分钟滑动窗口，可显式配置。仅成功登记的新用户事件续期；重试、历史、回复、工具结果和后台事件不续期。恰好到期失效，新交互生成新片段；重启清空活跃状态，不跨运行比较旧时间。
- 原文保持不同来源角色，不改写正文；只在有界内存中暂存，不新增可恢复落盘权限。宿主显式配置会话数、事件数、单条正文及总字符容量；满额返回背压错误，不能静默丢弃未处理证据。
- 可信宿主事件 ID 与客户端重试提示分离；没有可信事件 ID 不依据文本判重。返回实际回复需要登记终态并沿用原回复目标；撤销/撤权立即阻止继续读取或写回。
- 同会话串行、固定事件范围及水位的闲时批次先做离线调度票据；默认至少安静 3 分钟、交互已终结、预算允许才可调度。仅显式确认/跳过推进水位，失败及部分确认可重试，不实际提炼、提交长期记忆或自动共享。
- 验收涵盖截止边界、重复/乱序事件、跨维度隔离、容量拒绝原子性、取消/撤权、旧片段/旧批次拒绝、部分确认与重启。

实现细则与可运行示例见 [运行层 API](../crates/moe-agent-runtime/README.md#g1-会话与暂存)：原文不可原地改写，来源纠正/删除先保守撤销受影响片段，再登记新来源；默认任务期限 60 分钟、批次期限 5 分钟，独立于 30 分钟活跃时效。旧片段不能作为当前上下文，但获准保留的原文仍可按固定票据离线处理；期限内原在途任务只能登记到原片段及回复目标，不复活活跃状态。部分确认仅是 G1 事件级离线调度收口，不代表已经提炼候选或提交长期记忆。

### I.4 G2：统一 Agent 离线链路（已实现）

- 完成 G1 后接入既有授权记忆与请求上下文投影，使用可注入离线模型夹具；人设与获准记忆在推理前参与，不事后二次润色。
- 固定桌宠身份和回复渠道；工具默认不可执行；纯文本结果与表现事件分离，失败/取消/未知不伪造成功。
- 继续尊重实际读取集、来源、版本、取消与工作上下文禁止持久化派生边界；配置变更和迟到结果必须重验。
- 验收跨渠道共用稳定身份但不共享原文/权限，记忆授权拒绝可解释，模型失败无成功回执，撤权/取消拒绝迟到结果，Debug/日志脱敏。

实现为 `crates/moe-agent-runtime/src/agent.rs`，宿主显式绑定 G1 片段及精确来源许可，分配隔离记忆会话 ID；复用核心 `OfflineReasoning` 真实任务与 `RequestContext`，要求人设获准且存在。完整读取集超出渠道许可时整体拒绝，预算省略不洗掉读取依赖。私有任务/结果句柄只支持准备、一次离线推理及最终复验返回，不提供长期提交或工具执行能力。

预设配置证明同时防止改绑 ABA 与同版本注册表替换；G1 仅增加内部捕获/复验方法，不改变原有时效、闲时票据或取消语义。新消息不进入已捕获任务；旧片段到期后的期限内任务仍可回原片段/目标，不成为新片段上下文。最终登记容量失败不发布成功或回复。详细边界、可运行夹具和不可伪造句柄回归见 [运行层 API](../crates/moe-agent-runtime/README.md#g2-统一离线-agent)。

## 程序流程执行层

流程只编排业务节点，不接管 G0 入口、G1 会话或记忆权威。通用实现已迁到独立零依赖 [moe-workflow-core](../crates/moe-workflow-core/README.md)，不依赖 Agent、记忆、GUI 或 I/O；运行层重导出原有 `Workflow*` 路径，并保留 `agent_workflow.rs` 中的离线包装器。应用层的 `services/turn.rs` 定义实际聊天七阶段。运行层兼容入口见 [流程 API](../crates/moe-agent-runtime/README.md#程序流程执行层)。

- 受信代码先构造不可变定义并校验重复/缺失/循环，实例固定定义版本。节点前置必须全部成功；同一实例按首个就绪节点的声明顺序受控推进，不接受任意跳转或模型生成流程。实例之间互不阻塞，不是并行调度器。
- 节点执行由宿主负责，受信宿主持有绑定具体实例/节点执行的私有票据并回交结果。重复、跨协调器、取消后或迟到票据不推进状态；Failed/Unknown/Cancelled 都停止，不自动重跑未知副作用。
- `AgentWorkflow` 的 `prepare/infer/finish` 原样复用 G2 方法和 `MemoryContextAccess`，每步仍验证当前许可、来源、版本与时间，后端错误链不降级。任务与结果不向包装器外开放，顺序不符先拒绝，不能绕过终验取正文。
- `infer` 完成表示已有待裁决结果，不声称模型成功。模型失败/未知/取消经 `finish` 原账本登记后才反映对应流程终态；Agent 方法报错则停止流程且不伪造会话终态，未结交互由宿主显式处置。此第一版不开放自动或手动重试节点，原 G2 直连 API 仍保留自身背压语义。
- 包装器准备后取消须先获得 G1 授权取消回执，再停止流程并丢弃任务/结果；取消授权失败不改流程。准备前取消仅阻止该流程继续。取消不撤销已发生操作，进度成功也不证明记忆提交、消息送达或工具执行。
- 通用内核查询仅返回定义/版本、节点状态及下一就绪节点元数据，快照不可回写。内核不接诊断、模型或渠道；应用层可按既有许可调用这些服务并记录节点观察。此次接入不扩大查看、外传、落盘及导出许可，真实模型服务/RAG 质量门与外部渠道状态不变。
- 应用层 `moe-chat-app` 在现有门面之上新增唯一 `chat-turn` 组合器，使用本流程内核推进受理、准备输入、请求/等待、接收、解析、提交与发布七节点。`commit` 只保留真实 `AgentRuntime::finish` 回执；`publish` 在业务阶段后开始，但由应用层以私有待发布状态/票据延后到真实展示门面渲染后收尾（离线同样在 `dispatch` 内完成），GUI 不进入流程内核，展示失败时节点 `Failed` 且 `published=false`。离线七步同步完成；线上在请求/等待节点保留 workflow 执行票据并返回宿主，完成票据核验后继续接收至发布，再由应用层取得展示结果完成 `publish`。该组合器不形成第二套嵌套流程，也不把流程成功当作业务回执或展示成功；`ChatTurnProgress.business_outcome` 单独暴露真实业务终态，`AgentWorkflow` 的公开兼容接口保持不变。等待进度只经应用只读快照暴露，不开放改阶段入口。

## 会话与暂存

聊天失败的确定性以实际证据区分：解析或版本复验失败后取得权威取消回执，保留 Failed/send_cancelled，允许用户显式发起新轮次；不自动重发旧请求。没有终态证据、模型结果为 Unknown 或存储副作用未确认时仍隔离为 Unknown。新 Send 在受理前拒绝，不得利用上一轮 committed 标记触发存档检查点。应用收到的 ModelOutcome 不携带独立网络传输回执，因此外部诊断保持 TransportState::Unknown，不由正文或 Failed/Cancelled 反推 Written/Failed/Cancelled。

### S.2 暂存区与工作区

#### S.2.1 原文暂存区

保留实际收到的消息、实际发出的回复、必要工具回执以及完成/失败/取消状态；另附可信的桌宠、渠道、会话、说话者、事件标识与时间。正文不摘要、不改写，流式事件保持顺序，模型输出不能被标成用户的新证据。

「原封不动」针对交互正文，不包括上游 API 密钥、鉴权头或未向用户展示的内部推理。历史重传和同一请求重试不能重复登记为新交互；去重需要真实事件标识，不能仅以文本相同判断。兼容客户端缺少可靠会话标识时默认请求隔离，不根据内容相似猜测合并。

原文留存期限、跨重启恢复、容量与清理策略和会话活跃时效独立；本次不擅自确定无限留存、具体磁盘保留时长或扩大已有落盘授权。容量不足时明确背压，不静默丢弃未处理原文，也不在聊天主链路强制提炼。

#### S.2.2 即时会话工作区

从已验证的接入事件确定性更新会话状态，并按授权与预算引用近期原文。这个过程不调用模型做语义拆解，不把暂存正文修改为摘要。

建议会话状态字段包括稳定桌宠身份、入口/渠道身份、外部会话、经过验证的说话者、会话片段代际、最后一次有效用户交互时间与活跃截止时间。内部会话键至少区分桌宠、渠道账号、群/私聊、外部会话及读取主体；群成员不自动合并为同一主人。

「当前请求来自 QQ」来自本次请求的可信元数据，不靠记忆猜测；「这段时间我们在这个 QQ 会话聊天」是有时效的工作区视图，不是可覆盖工具权限或核心人设的权威记忆写入。

### S.3 会话时效默认规则

以下数值是本项目拟采用的产品默认值，不是 QQ 平台限制或已验证的最优参数；后续允许宿主配置，但不允许模型自行修改。

| 项目 | 默认规则 |
| --- | --- |
| 连续对话窗口 | 最后一次有效用户交互之后 30 分钟，滑动续期。 |
| 续期触发 | 新的、通过接入校验并成功登记的真实用户交互。 |
| 不续期的事件 | 重试、重传历史、桌宠自身发言、工具后台回调、摘要、整理、检索命中和系统心跳。 |
| 到期判断 | 到达截止时间即失效；读取时判断，不要求后台定时器恰好触发。 |
| 到期后的新消息 | 创建新的会话片段代际，不自动复活旧片段或注入旧原文。 |
| 重启 | 不直接恢复「现在仍在 QQ 聊天」的活跃判断；收到新的有效交互才建立新的活跃状态。原文能否恢复另按留存授权处理。 |

示例：10:00、10:12、10:25 分别有新的有效 QQ 交互，窗口依次延至 10:30、10:42、10:55。10:55 起旧片段不再作为当前活跃对话；10:56 的新消息开启新片段。旧原文是否还在暂存、是否已完成整理，均不改变上述判断。

运行时以受信宿主注入的单调时间判断窗口，接入顺序与源消息时间分开保存；模型提供的时间、乱序旧消息和重试不能任意延长活跃窗口。重启后不得直接比较旧进程单调计时值。

会话读取、旧摘要再利用、模型回复和工具长任务不能给这个窗口续命。到期不代表强制取消已经获准的在途任务：任务仍受自己的期限、取消及授权栅栏约束，结果按原请求目标返回，不能改投最新聊天渠道。

### S.4 多入口与隐私

活跃状态按会话独立保存，不建立唯一的「用户当前只能在 QQ」全局开关。用户同时在 QQ 和桌面发言时，两个会话可以各自活跃，回复目标始终取自对应请求。

桌面和 QQ 的片段不因时间接近就合并。同一用户跨渠道身份必须经过可信绑定，群聊、私聊及不同群之间也不自动搬运原文或私密经历。受信宿主可以在既有授权范围内提供跨渠道的低信息量场景提示，但不存在默认跨渠道全文读取。

会话撤销、来源删除/撤权、权限收紧时立即失效，不等待 30 分钟；已交付快照不可追回仍沿用现行边界。

### S.5 闲时整理与活跃窗口分开

建议默认在某会话最后一次有效用户交互后至少安静 3 分钟、该批次相关交互已终结且前台资源/整理预算允许时，才进入可调度状态。3 分钟只是最低安静间隔，不承诺恰好在第 3 分钟执行；不必等待 30 分钟活跃窗口结束。

同一会话的整理任务串行，不同会话受全局并发与预算约束。任务固定一个已完成的事件区间和版本水位；新消息可以继续追加，不进入该在途批次。批次只有在全部预期提交或明确跳过都得到确认后才推进已处理水位，部分提交重试使用逐候选幂等，不能重复制造记忆。

提炼只生成候选：私密事实/经历仍通过服务提交，通用知识候选仍经过独立共享发布审查。原文纠正、撤权、删除或取消后，旧批次不能回写；模型发言、旧摘要和注入上下文不能循环制造新用户证据。

处理成功不自动删除原文；会话活跃到期也不自动删除原文。反过来，旧原文仍被保留也不意味着可以继续作为当前上下文。留存、读取有效性、整理水位和物理清理是四个独立状态。

## 原文生命周期

### G3.2 显式配置与时间

- 正常留存时长、回收留存时长及回收区容量均为宿主必填正值，无内置 24 小时或 7 天默认值。两者仍是候选产品值，不影响用合成配置推进本批。
- 正常区沿用显式会话/事件/单条正文/总字符限制；回收区独立限制片段数、事件数和总字符。任何统计、期限、ID 或代际运算溢出必须明确失败，不发布半更新。
- 全部时间由可信宿主注入当前运行内的单调毫秒值；拒绝倒退，不从渠道原始时间、正文或系统时钟取得权威时间。不同运行的时间不比较；重启后恢复真实期限是 G4 的验收项。
- 首次成功登记原文的受信时间固定为 `created_at`，初始正常截止为 `created_at + normal_ms`，总留存硬截止为 `created_at + normal_ms + recycle_ms`，先检查计算再发布片段。
- 新消息、回复、读取、整理确认、重复删除都不延长既有片段的原文期限。自然到期的逻辑回收时间是原正常截止，而不是维护任务实际运行时间；迟到维护不得重算一个新的完整回收窗口。
- 首次进入回收区将最终截止固定为“既有硬截止”与“逻辑回收时间加回收时长”的较早值。恢复后正常截止可设为 `min(now + normal_ms, 最终截止)`；重复删除/恢复不得延长最终截止。
- 边界统一使用 `now >= deadline` 即失效。活跃 TTL、任务期限、正常留存、回收留存是四个独立概念；只到活跃 TTL 不触发原文回收或提前取消期限内任务。

### G3.3 状态转换与容量

```text
正常暂存 --正常留存到期/获准软删除--> 回收区
回收区 --显式恢复且未到最终截止--> 正常暂存（新生命周期代际）
正常暂存/回收区 --最终到期/获准清空/撤权清理--> 清理
```

- 每次实际生命周期转换推进不可复用的代际/版本。片段和原始事件 ID 不因回收/恢复改变；清理后的 ID、句柄及配置证明不得命中后来创建的内容。
- 显式软删除先完成权限、版本、期限和回收容量检查；失败保持原文、状态、两区统计、水位、票据与截止时间不变。不能为了完成软删除驱逐另一条可恢复记录。
- 正常到期即禁止使用，不依赖维护函数或定时器。若回收区已满，允许保持“逻辑到期、待转移”的原区计费状态并明确背压；不得继续向 Agent 提供，也不得无界扩大回收区或静默清除尚在恢复期内的原文。
- 提供显式受信维护入口，使到期片段转移、最终到期内容移除并释放容量。维护须可重复调用；多片段失败边界需文档说明，不得声称不存在的全局事务。单片段转换必须原子。
- 清理移除受管理正文、重试正文副本和批次缓存，释放对应区域片段/事件/字符容量；不留无界正文墓碑。单调签发 ID 不回退、不复用，仍需耗尽检查。
- 当前运行的撤权防重放不依赖可选宿主事件 ID：清理后原 `TrustedRequest` 不能重新登记成活跃交互；所有接纳宿主事件 ID 的入口复验同一隔离域内撤销栅栏。另按完整 `RequestIsolation` 保留接入序号及来源顺序的最大水位，每隔离域最多一条且不保存正文；登记时与尚存片段水位合并，任一顺序不超过已知最大值仍为历史消息，不续活跃期或获得回复执行权，不用全局水位误伤其它会话。请求序号、来源 ID 和隔离域水位账本各以正常区全局事件数为累计上限，超出时清理照常完成，但本协调器永久拒绝新用户/关联事件接纳（`ReplayProtectionExhausted`）；不得静默忘记撤销或水位后继续放行。既有片段查看/恢复/终态登记及维护清理仍按原闸门执行，恢复不清空该栅栏；不承诺跨重启防重放。
- 原文、来源角色、渠道原始时间和已确认处理水位保持保真；审计元数据与正文分离。本批只描述真实存在的“未处理/部分确认/已确认”等状态，不把批次确认伪称为长期记忆已提交。

### G3.4 独立本机管理能力

- 本机主人管理与入口调用、记忆读取、模型传输、共享、工具权限分别授权。仅持入口 token 或 `TrustedRequest` 不能取得原文查看、恢复或清空权限；普通远程路径不暴露能力签发。
- 由受信宿主在已完成本机主人校验后，显式安装最小管理能力。能力私有构造，绑定签发协调器/运行实例、完整桌宠身份与原隔离域、精确片段范围及权限集合；默认无权限，不提供通配全部私密记忆的捷径。
- 查看、软删除、恢复、清空分别裁决；权限可拆分，能力自身支持撤销或不可复用授权证明。能力和管理操作使用当前权威入口配置检查撤权，不接受历史配置克隆替代当前状态。
- 能力签发、撤销、过期/配置变化和重复使用的语义必须写清；异实例、跨宠、跨用户/工作区/凭据/渠道/范围的能力均拒绝且不改变状态。能力签发及撤销记录必须有界，不新增无限增长的管理账本。
- 管理读取返回只读快照，不输出供应商凭据或桌宠其它私密记忆；快照、能力、错误及状态 Debug 不输出正文、token 或凭据引用。
- 这是离线宿主能力契约，不是已实现的 OS 登录认证、密码学 capability 或本机 GUI。宿主根接口不得直接作为模型工具、Hook 或远程 API 开放。

### G3.5 恢复与撤权

- 恢复要求当前有效的独立能力及预期生命周期版本，重新检查原入口身份/隔离域、配置/凭据及片段撤销状态；缺失、到期、已清理或已撤权均拒绝。不能通过重新签发管理能力复活已不可逆清理内容。
- G1 的 `HostEventId` 不是记忆核心的 `SourceRef`。本批不为恢复新建记忆来源，不恢复已撤销的核心来源；若涉及 G2 既有记忆使用，仍由核心的完整来源/版本复验裁决。
- 恢复原文不恢复活跃截止、旧交互执行权、旧批次或旧 Agent 任务。未完成交互必须不可再由旧句柄输出；终态/取消等控制元数据可独立于原文保存。恢复不自动回复、不重放工具、不自动共享或调用模型。
- 保留原始事件身份、已确认前缀及必要幂等记录；重复恢复应返回明确幂等结果或版本冲突，不推进水位、不重复登记事件、不重复整理已确认项。
- 如需再次处理未确认内容，必须显式签发新批次并重新通过当前隔离、权限、版本、期限和并发检查。恢复本身不是调度许可；新用户交互仍按 G1 规则进入新的非复活片段。
- 恢复前检查正常区全部容量；容量不足原子失败，回收区内容、原截止及水位不变。不得部分恢复或挤掉其它原文。
- 撤权不等于软删除。已撤销片段及权威入口授权失效的内容不得借回收区继续被查看/恢复；启用 G3 的维护/撤销路径应移除其受管理原文。逻辑拒绝须即时，内存释放时机与维护要求如实说明。

### G3.6 G1/G2 全链复验

- 生命周期与逻辑期限检查覆盖所有正常读取、用户/关联事件登记、交互完成、批次签发/读取/确认，以及 G2 绑定、准备、推理前和最终登记；不能只给管理界面隐藏内容。
- 回收/到期立即使旧在途票据与推理任务失效并释放批次并发占额；恢复之后也不能重新有效。未到原文期限时，保持 G2 原有“片段活跃 TTL 到期但原交互期限内可回原目标”的行为。
- G2 推理前拒绝时回调调用次数为零；已得到结果后发生回收/清理/撤权，`finish` 必须拒绝，不返回正文、表现事件或成功交付。
- 已交付出去的快照、模型输入或平台消息无法追溯追回。清理仅覆盖受管理在线数据；不承诺 RAM 安全擦除、磁盘安全擦除、备份清理、撤回外部副本或永久删除后的跨重启去重。
- 清理会话原文不调用长期事实删除/共享撤回；用户要求忘记事实必须继续走核心管理及派生失效链路，不得用回收区替代。

## 运行快照

### R.1 定位与不变量

- 本契约是 `SessionRuntime` 的纯内存扩展：导出产出结构化快照与字节序列，导入接收结构化快照；运行层不访问文件、网络或系统时钟，所有时间由受信宿主注入。
- 快照是**不带权限证明的数据**：不含 `TrustedRequest`、入口 token、凭据句柄、管理能力、批次票据、Agent 任务或任何可执行授权。快照内的校验和、修订号、代际数字均不授予许可；恢复必须由当前运行实例重新鉴权。
- 未启用留存（未用 `SessionRuntime::with_retention`）时四个持久化入口全部返回 `RetentionNotConfigured`，G1–G3 行为与内存占用不变。`RawSnapshotV1::sweep_expired`（§R.8）是快照值上的纯函数，不触碰运行状态、不要求留存配置。
- 依赖方向不变：本模块只被外层存储适配调用；`moe-raw-local`（本批外层适配）据本文的签名与 v1 线格式持久化字节，不反向影响运行层。

### R.2 稳定域与当前授权映射

#### R.2.1 稳定域 `RawDomainKey`

稳定域是跨重启可比对的完整隔离键，精确涵盖六元组，缺一不可：

| 分量 | 类型 | 来源 |
| --- | --- | --- |
| 桌宠全身份 | `PetIdentity`（工作区 + 用户 + 稳定实例） | 路由绑定 |
| 调用主体 | `CallerSubject` | 入口凭据 |
| 渠道 | `ChannelId` | 入口凭据 |
| 渠道范围 | `ChannelScope` | 入口凭据 |
| **稳定凭据归属** | `String`（identifier 规则校验） | **受信宿主权威显式声明**（§R.2.1.1） |
| 会话 hint | `String`（identifier 规则校验） | 宿主适配器 |

```rust
pub struct RawDomainKey { /* 私有字段 */ }

impl RawDomainKey {
    pub fn new(
        identity: PetIdentity,
        subject: CallerSubject,
        channel: ChannelId,
        scope: ChannelScope,
        credential: String,
        hint: String,
    ) -> Result<Self, GatewayError>;

    pub fn from_request(
        ingress: &TrustedIngress,
        request: &TrustedRequest,
    ) -> Result<Self, GatewayError>;

    pub fn identity(&self) -> &PetIdentity;
    pub fn subject(&self) -> &CallerSubject;
    pub fn channel(&self) -> &ChannelId;
    pub fn scope(&self) -> &ChannelScope;
    pub fn credential(&self) -> &str;
    pub fn hint(&self) -> &str;
}
```

- `RawDomainKey` 实现 `Clone、PartialEq、Eq、PartialOrd、Ord、Hash`；`Debug` 输出身份/主体/渠道/范围/凭据归属并隐去 hint（`hint: REDACTED`）。
- **无 hint 明确拒绝**：`RequestIsolation::Fresh`（无会话提示）的请求没有稳定归属，`from_request` 返回 `InvalidInput("request has no stable session hint")`，不得凭运行内序号推测稳定域；导出与导入均先走本检查。
- **凭据归属缺失明确拒绝**：当前请求的已认证 `CredentialId` 未被宿主绑定稳定归属时，`from_request` 返回 `InvalidInput("credential has no stable attribution")`；该凭据名下的片段不属于任何稳定域，导出与导入均不触达。
- 运行内 `RequestIsolation::Hinted` 中的 `run_instance` 与 `CredentialId` 是本运行局部句柄，**不进入**稳定域；进入稳定域的是宿主为该句柄显式声明的稳定归属。同一稳定归属在不同运行可对应不同凭据句柄（轮换续用），同一运行内不同凭据句柄（不同归属）即使主体/渠道/范围/hint 全同也是**不同稳定域**。

#### R.2.1.1 稳定凭据归属与授权修订绑定（`TrustedIngress` 新增）

```rust
impl TrustedIngress {
    pub fn bind_stable_credential(
        &mut self,
        credential: CredentialId,
        attribution: impl Into<String>,
    ) -> Result<(), GatewayError>;

    pub fn bind_stable_credential_revision(
        &mut self,
        credential: CredentialId,
        attribution: impl Into<String>,
        revision: u64,
    ) -> Result<(), GatewayError>;

    pub fn credential_attribution(&self, credential: CredentialId) -> Option<&str>;

    pub fn stable_credential_revision(&self, credential: CredentialId) -> Option<u64>;
}
```

- 归属由**受信宿主权威**在凭据安装后显式声明，运行层从不从 token、`run_instance`、凭据局部序号或旧 ingress generation 推导。运行层无法验证宿主所给字符串的业务稳定性（例如渠道账号 ID），但保证：未绑定即无稳定域、绑定一经存在即为可比对的历史事实。
- **授权修订**与归属一同绑定：`bind_stable_credential` 以该归属当前修订绑定（新归属为初始修订 1），等价于 `bind_stable_credential_revision(credential, attribution, 当前修订)`——既有调用兼容。宿主宣告授权撤销并换发新授权时，必须对同归属显式绑定**更高**修订；旧修订随之退役，此后旧修订不能被重新绑定（含换新凭据、凭据局部序号巧合相等或重签历史许可的情形），当前权威无法确认修订关系时拒绝。绑定规则（任一违反即 `InvalidInput`/`ForeignRequest`，不产生半状态）：
  1. 凭据必须属于本运行实例且当前在册（跨实例 `ForeignRequest`，未知凭据 `InvalidInput`）。
  2. 归属字符串按 identifier 规则校验；修订号必须为正。
  3. 在册凭据的归属串不可改写：对已绑定凭据重报相同归属按修订规则处理（相等幂等成功、更高即推进并退役旧修订、更低拒绝）；报不同归属拒绝——运行中改标签即洗白通道。
  4. 一条归属同时最多绑定一张在册凭据（1:1）：第二张在册凭据报相同归属拒绝。**因此同一入口内两张有效凭据必然落在不同稳定域**，正文与水位双向隔离。
  5. 修订只前进：任何绑定不得低于该归属当前修订或已退役水位；`stable_credential_revision` 对已撤销凭据继续返回其历史修订，供域比对与快照修订闸门使用，不恢复任何准入权。
- `revoke_credential` 释放该归属（可由宿主绑定到轮换后的新凭据，修订不变），但 `credential_attribution`/`stable_credential_revision` 对已撤销凭据**继续返回原归属与修订**：撤销把凭据标记为"归属及其修订的历史持有者"，供清理栅栏与旧片段在导出时归入正确稳定域；这不恢复任何准入权（已撤销凭据的请求在 `validate` 即拒绝）。**凭据轮换（撤销+重绑同归属同修订）不是授权撤销**；授权撤销以显式推进修订表达。
- 绑定与解绑不推进配置代际：归属/修订声明不吊销、不改写任何既有准入或权限，只在持久化入口投影域与快照修订闸门时参与比对；普通 G0–G3 请求行为不变。

#### R.2.2 当前授权映射（恢复的鉴权链）

重开后的运行实例按以下顺序重新鉴权，任一步失败即拒绝且不改变状态：

1. **留存已启用**：`with_retention` 构造，否则 `RetentionNotConfigured`。
2. **当前请求复验**：`SessionRuntime::check` 复用 G1 闸门——`TrustedRequest::validate`（异实例 `ForeignRequest`、配置代际落后/凭据撤销 `Revoked`）、入口运行实例一致、时间不回退。
3. **当前请求稳定投影**：`RawDomainKey::from_request(&ingress, &当前请求)` 必须等于快照 `domain`，否则 `ForeignRequest`。投影要求当前已认证 `CredentialId` 的稳定归属已绑定且等于快照域内归属——映射由"宿主声明 + 当前认证"共同决定，快照内的域字符串、归属串或任何档内数字本身都不构成映射。撤销后轮换：宿主把原归属绑定到新凭据即可重新投影同一域，但旧片段的原授权代际检查（第 5 步）不因此豁免。
4. **授权修订一致**：快照内保存的 `authorization_revision` 必须等于当前凭据归属绑定的修订号（`stable_credential_revision`），否则 `Revoked`。已撤销的旧修订不能凭相同局部数字的新凭据或重签历史许可恢复；无法确认映射关系的更新修订同样拒绝。档内修订号只用于一致性比对，不是授权。
5. **独立历史许可**：受信宿主在本机主人校验并核对此前授权仍有效后，显式安装 `RawHistoryGrant`（见 §R.3）；导入要求在册、未撤销、同入口运行实例且精确绑定该域。`install_raw_history_grant` 另要求域内归属当前有在册凭据持有（映射缺失即拒绝，`InvalidInput`）。权威服务无法确认旧授权仍有效时宿主不得安装，导入即失败封闭。
6. **不被档内数字洗白**：快照内保存的代际号、生命周期版本、校验和与凭据归属描述只用于一致性预检，不作为授权；导出侧拒绝任何原授权代际落后于当前权威配置的在域片段（`Revoked`），已撤销历史只能以栅栏形式进入快照（§R.6.3）。

#### R.2.3 撤销的两类语义（导出必须区分）

- **能力撤销**（`revoke_session`、`purge_fragment`、清空、管理能力撤销）：片段正文即时移除，清理账本保留宿主事件 ID、**稳定片段键**、来源顺序水位等稳定栅栏；同代际再导出只能得到无正文快照。重新签发管理能力不能复活正文（旧 `SessionId` 已 `StaleHandle`/异协调器 `ForeignRequest`），跨重启恢复也不能把它当可导入片段（快照中它只以栅栏存在；携带同键"存活"片段的旧快照在首次导入即被片段键栅栏拒绝，事件没有宿主事件 ID 也不能借此复活）。**撤销历史许可（`revoke_raw_history_grant`）只撤销该句柄，不删除任何正文**——正文仍按 G3 生命周期留在域内，由管理查看/软删除/清空或受信维护另行处置。
- **历史授权撤销**（配置代际推进后原片段授权落后，或宿主推进稳定归属的授权修订）：片段仍在域内但导出整体拒绝（`Revoked`），只有受信 `maintain_retention` 撤权清理移除正文并留下栅栏后才可导出；新凭据绑定原归属、重签能力或重启都不能把这类片段洗成可恢复历史，旧修订的快照导入同样被修订闸门拒绝。
- 运行层导出路径对上述两类都做显式检查：在域片段 `revoked` 标记置位即拒绝（防御性契约，正常留存流程撤销即清理，不应出现该状态），授权代际落后即拒绝；二者都不得半更新后返回部分快照。

#### R.2.4 跨重启绑定结果

导入成功的片段绑定**当前运行实例**：`RequestIsolation` 取当前导入请求的完整隔离（含新运行实例号与凭据句柄），授权代际取当前请求代际，`SessionId` 由受信服务新签发。此后入口凭据重装、配置升版或 `maintain_retention` 撤权清理均按 G3 既有规则处理这些片段，不享受任何豁免。

### R.3 API 与准确签名

```rust
pub const RAW_SNAPSHOT_MAX_TOTAL_BYTES: usize = 16_777_216;

pub struct RawHistoryGrant { /* 私有字段 */ }
impl Clone for RawHistoryGrant {}
impl fmt::Debug for RawHistoryGrant {} // 输出 "RawHistoryGrant(REDACTED)"

pub struct RawSnapshotV1 { /* 私有字段 */ }
impl Clone for RawSnapshotV1 {}
```

### R.4 时间模型

- 持久化使用受信宿主注入的 **Unix epoch 毫秒**单一时间轴；运行层不读取系统时钟，也无法自行验证宿主是否真的使用 epoch 毫秒。启用持久化的宿主必须从构造 `SessionRuntime` 起在同一时间轴上注入全部 `now_ms`；未启用持久化时保留 G1–G3 的进程内单调毫秒契约，两者不混用。
- 导出：`committed_at_ms >= access.now_ms` 必须成立。快照保存提交时间与每片段 `created_at、normal_deadline、hard_deadline、final_deadline（已固定时）`，全部为原运行时间轴上的绝对值。
- 导入（重开）：`now_ms < snapshot.committed_at_ms` 返回 `ClockWentBackwards`，失败封闭；运行内既有 `last_now_ms` 回退检查不变。`sweep_expired` 同样要求 `now_ms >= snapshot.committed_at_ms`，否则 `ClockWentBackwards`，输入不被改动。
- **收紧政策，不续期**：导入、读取/维护与 `sweep_expired` 对每片段取收紧结果，并共享同一**有效生命周期算法**——
  - `eff_normal = min(原 normal_deadline, created_at + 当前 normal_ms)`
  - `eff_hard = min(原 hard_deadline, created_at + 当前 normal_ms + 当前 recycle_ms)`
  - `eff_final = 原 final_deadline.map(|f| min(f, eff_hard))`
  - **有效最终截止**：已固定时取 `eff_final`；尚未固定时按 `min(eff_normal + 当前 recycle_ms, eff_hard)` 推算——即"原（收紧后）正常截止 + 当前回收时长"。由此，收紧政策（例：旧 50/50、新 100/10）下 `now` 一超过 `原 normal + 新 recycle` 即对导入、管理读取、导出与净化**即时拒绝**，不再等到（可能更晚的）硬截止；自然回收仍按原正常截止计算逻辑回收点，不按迟到维护或恢复时刻重给完整回收窗口。
  - 当前政策候选上界在 `checked_add` 溢出时视为"该上界不收紧"，最终值仍不超过档内原值；**有效最终截止推算加法溢出即失败封闭**（导入拒绝、净化整单失败、读取返回 `IdentifierExhausted`），不用饱和运算悄悄放宽期限。
- 正常区逻辑到期（`now >= eff_normal`）沿用 G3：维持入口以存储的有效正常截止作为逻辑回收时间；恢复后的正常截止不超过既有最终截止；`now >= 有效最终截止`（含等号）即对查看、恢复、维护、快照维护与全部使用路径拒绝正文。
- 渠道原始时间（`source_timestamp_ms`）与事件登记时间（`received_ms`）原样保真，不参与期限计算，不能延长任何期限。

### R.5 v1 线格式（`moe-raw-snapshot` v1，字节精确）

> 修订说明：v1 仍在 G4 批次内收敛，无已发布字节兼容负担。首次修订在内容区加入稳定凭据归属字段；本闭环审查修订再加入 `authorization_revision` 与稳定片段键撤销栅栏两个字段，并把提交时间纳入校验和覆盖范围。

- 全部整数为**小端**定长；字符串为 `u32 字节长度 + UTF-8 字节`；可选标量为 `u8 标志（0=无，1=有）+ 值`；计数为 `u32`。
- `content_checksum` 为 **FNV-1a 32 位**（offset basis `0x811C9DC5`、素数 `0x01000193`），覆盖 `[16, len)`——**提交时间与内容区一并纳入完整性校验**，不含 magic 与版本。它**只检测意外损坏，不作内容同一性或真实性证明**：32 位非密码学摘要存在可构造碰撞，重复导入与 CAS 改用规范内容的 SHA-256 指纹（§R.6.4，提交时间独立排除），不比较 FNV 校验和。

### R.6 恢复算法（`import_raw_snapshot`）

#### R.6.1 完整预检（全部通过前不改动任何状态）

1. **鉴权闸门（复用 `validate_raw_history_access`）**：留存已启用；`check(&access)` 复验当前请求、运行实例与时间；`RawDomainKey::from_request(&ingress, 当前请求)` 等于快照域（§R.2.2 第 3 步含凭据归属解析）；`RawHistoryGrant` 在册、未撤销、同入口运行实例且域精确匹配。文件适配在读取/净化前调用同一闸门。
2. **授权修订闸门**：快照 `authorization_revision` 必须等于当前凭据归属绑定的修订号，否则 `Revoked`（§R.2.2 第 4 步）。
3. `now_ms >= snapshot.committed_at_ms`，否则 `ClockWentBackwards`。
4. **结构与 16MiB 预算**：`validate_content` 语义校验（§R.5 解码校验清单，解码与导入共享同一实现）；按结构计算内容区字节数，连同头部不超过 `RAW_SNAPSHOT_MAX_TOTAL_BYTES`——结构化导入不绕过线格式预算。
5. 域内无活动片段冲突：本域已存在不属于既导入记录的片段（含完全未导入过却有在域片段）返回 `InvalidInput`；导入不与运行内已登记片段混合。
6. CAS（§R.6.4，规范内容 SHA-256 指纹比较）与导入账本容量：记录条数上限 64 域；保留首导入内容区字节数的累计接纳预算，总和不得超过 `RAW_SNAPSHOT_MAX_TOTAL_BYTES`，超限在发布前整体拒绝（`CapacityExceeded`），不静默淘汰记录。账本只持有指纹、稳定域、片段键、首提交时间与计费字节数，不持有正文；该预算不是实际常驻正文大小。
7. **栅栏冲突（域级）**：快照内存活片段的稳定片段键或存活事件宿主 ID 命中当前稳定域已撤销栅栏（跨凭据轮换的同域隔离记录一并计入）时整体拒绝（`InvalidInput`）——首次导入旧快照不能凭"事件无宿主 ID"复活已撤销正文（§R.2.3）。幂等重放（第 6 步判定 duplicate）不受此步影响，不复活已清理片段也不新增事件。
8. 容量预算：片段键快照内唯一（语义校验已含）；每片段事件数 ≤ `events_per_session`；正文 ≤ `body_chars`；正常区片段/事件/字符并入 `limits`，回收区片段/事件/字符并入 `retention` 回收配额；任何溢出或超限 `CapacityExceeded`。
9. 期限与到期：按 §R.4 收紧并推算**有效最终截止**（推算溢出即 `IdentifierExhausted` 失败封闭）；任一片段 `now >= 有效最终截止` 返回 `RawExpired`（最终截止等号不可导入），整单拒绝、不部分导入。存量的部分到期快照应先经 §R.8 的 `sweep_expired` 净化（文件适配可先原子提交净化快照再导入）。
10. **栅栏账本累计预算预演**：新增撤销宿主事件 ID 与新增撤销片段键按全部隔离域累计，连同隔离域条目数一起以正常区全局事件数为上限；放不下时在发布前**整体拒绝**（`CapacityExceeded`），不静默丢弃栅栏后放行内容。一旦账本已耗尽（`replay_protection_exhausted`），不再继续增长；快照携带的耗尽标志照常并入。
11. 计数器：`session_sequence` 增量 `checked_add` 预演，溢出 `IdentifierExhausted`。**档内片段键与生命周期版本不折入全局序号/代际计数**（§R.6.2/§R.7）：一个域的 `u64::MAX` 键或 `u64::MAX` 版本不毒化其它域的导出与转移，全局计数只按必要增量推进。

#### R.6.2 原子发布

预检通过后一次性发布：新 `SessionId` 顺序签发；片段 `isolation`/授权代际取当前请求；`active_until_ms = None`、`last_user_ms = None`、`batch = None`、`revision = 0`；生命周期按收紧后值与档内版本重建（档内版本只保存在该片段上，不推进全局代际）；事件按原序号、角色、正文、渠道时间、来源顺序、客户端提示、宿主事件 ID、确认标记重建，父事件序号保真；用户类事件（`User/UserHistory`）一律补 `History` 型登记元数据并将未终结者置为 `Cancelled`，同时挂接**惰性交互记录**（请求序号固定为 0，任何新请求都不可能命中），使一致重传可命中幂等重复路径，而终结/追加/取消/推理全部被既有闸门拒绝。导入完成后推进 `session_sequence` 与 `last_now_ms` 并写入无正文的导入记录（含首导入计费字节数）；`raw_key_sequence` 与 `lifecycle_generation` 不因导入折入档内极值（§R.6.1 第 11 步）；`replay_protection_exhausted` 只能置位不能清除。

#### R.6.3 清理栅栏与耗尽状态

- 快照按**完整稳定域**携带栅栏：已撤销宿主事件 ID 集合 + **已撤销稳定片段键集合** + 来源顺序最高水位 + 耗尽标志，与正文同一快照密封，不使用全局水位，也不只依赖可选 `HostEventId`——片段键栅栏保证事件没有宿主 ID 的已清理片段同样不能被旧快照复活。
- 导入将栅栏并入**当前请求隔离域**的清理账本（与 G3 清理同一数据结构，合并去重、水位取最大），使重启后的新登记继续拒绝已撤销宿主事件 ID（`Revoked`）、旧来源顺序只按 `UserHistory` 处理不续活跃期；冲突裁决见 §R.6.1 第 7 步。
- 运行局部请求序号栅栏不导出、不导入：旧 `TrustedRequest` 因绑定旧运行实例在结构上无法跨重启重放，跨重启防重放由宿主事件 ID、稳定片段键与来源顺序水位这些稳定栅栏承担。
- 账本累计预算沿用 G3（宿主事件 ID 与隔离域条目各以正常区全局事件数为上限，片段键并入同一累计口径）：放不下时**整体拒绝**（§R.6.1 第 10 步）；耗尽后账本不再增长，清空、恢复或重签能力不能重置已耗尽或已撤销状态。
- 当前运行已耗尽时，任何非幂等的新导入在分配/克隆/发布前由 `check_replay_budget` 拒绝（`ReplayProtectionExhausted`），不依赖清理时因预算不足未能保存的具体键/事件栅栏。尚未耗尽的新运行可以首次恢复携带耗尽标志的最新快照，并永久置位；此后只允许已经在册、精确内容相等的无新增幂等回执（§R.6.4），已清理片段不重建。

#### R.6.4 重复导入与 CAS（规范内容指纹）

- 每域首导入只保存**规范内容的 SHA-256 指纹**、完整稳定域、已导入片段键集合、首提交时间和首导入内容区字节数；不克隆或持有结构化快照、事件正文或其可逆编码。记录上限 64 域，累计接纳预算仍按 §R.6.1 第 6 步执行，不因清理而释放防重放元数据。
- 指纹复用 v1 内容区的确定性编码，覆盖域、授权修订、耗尽标志、撤销宿主事件 ID 序列、撤销片段键序列、来源顺序水位、全部片段键/区/期限/版本/水位/事件正文与元数据；排除头部 `committed_at_ms`。使用评审后的 `sha2`，不自制密码学实现，不以 FNV32 或默认集合哈希判重。
- 指纹相同才返回 `duplicate = true`，不制造事件、不推进身份计数、不重置水位或耗尽状态；回执按记录键集合解析当前仍存活的句柄，已清理片段不出现也不复活。指纹不同返回 `VersionConflict`，无论提交时间先后，不能在已导入/登记状态上叠写。
- 此处依赖 SHA-256 的抗碰撞假设，不再宣称持有全文后逐字段比较或数学上零碰撞；该指纹不持久化为新的正文档案，不证明授权、来源真实性或抗恶意文件篡改。编码计算会临时分配受 16MiB 上限约束的缓冲，返回后释放，未承诺安全内存擦除。
- 幂等重放同样要求 §R.6.1 第 1–5 步成立（当前鉴权、修订一致、时间、无活动片段冲突），快照本身不因曾经导入过而免检。
- 成功的幂等回执会将运行内防回拨时间水位 `last_now_ms` 推进到本次注入时刻，后续操作不能再使用更早时间；这是时间检查的一致性，不改变快照字节、事件/栅栏账本、确认水位或身份计数，也不重建已清理正文。失败路径不推进该水位。

#### R.6.5 导入结果的权利边界

导入不产生：活跃会话（`read_active` 返回 `SessionExpired`）、可完结/可追加交互（惰性交互记录对任何新请求返回 `ForeignRequest` 或 `InteractionClosed`）、Agent 绑定与执行（`bind_session` 走 `read_active` 同样拒绝）。导入的未确认历史**并非永久禁止新批次**：历史只允许在当前完整闸门下显式开新批次——受信宿主的新用户事件按现行规则登记并滑动续期后，`issue_idle_batch` 才可能就绪；导入本身不签发任何批次、任务或结果（导入片段 `last_user_ms` 为空、无活跃会话，故导入后立即签发返回 `NotReady`），旧批次/交互/Agent 任务或结果不可复用，不因新消息或重开获得执行权，新处理不代表长期提交。旧运行实例的 `SessionId/InteractionId/BatchTicket/ManagementCapability/TrustedRequest` 句柄在新实例内一律 `ForeignRequest/StaleHandle`，不被复制或复活。

### R.7 导出规则

- 域由当前请求投影（含当前已认证凭据的稳定归属解析与授权修订解析）；仅导出稳定域精确相等的片段（含正常区、回收区、逻辑到期待转移者），其他域不受影响。同一入口内归属不同的两张有效凭据互不可见：正文、片段键与清理栅栏（含水位与片段键栅栏）双向隔离。
- 导出分三阶段，任一失败不产生半更新：先对域内全部片段做完整校验——`revoked` 置位拒绝（`Revoked`，§R.2.3）、原授权代际落后于当前权威配置拒绝（`Revoked`，先 `maintain_retention` 撤权清理后再导出）、已达有效最终截止拒绝（`RawExpired`，先维护/清空）——两类内容不得借导出洗成可恢复历史；再在本地状态构建快照并**预演编码**；全部通过后才一次性提交：新片段键写入会话、`raw_key_sequence` 推进到最后一个分配候选。**编码超限（`CapacityExceeded`）或键候选耗尽（`IdentifierExhausted`）时键与序号都不先行发布**，重试不消耗键空间。
- 新键一次性预分配：候选自 `raw_key_sequence + 1` 起步，跳过本稳定域已用的片段键（在域片段、导入记录与清理栅栏中的键）——**已撤销键不复用**；档内极端键值不折入全局序号，一个域导入 `u64::MAX` 键不会耗尽其它域的键空间，同域新键以最小未用候选分配。既导入片段沿用其键；键是域内唯一的不透明序号，不是授权，也不跨域比较。
- 栅栏区收集本稳定域全部清理账本条目（按各条目原凭据的归属解析归域，凭据撤销后仍可归入原域），合并去重（宿主事件 ID、稳定片段键）、水位取最大，耗尽标志如实携带；运行局部 `cleaned_requests` 不导出（§R.6.3）。
- `encode` 产出的字节由外层适配持久化；运行层不落盘、不建临时文件。重复导出不重掷片段键：同状态两次导出的编码字节逐字节相同。

### R.8 快照过期维护与收紧（`RawSnapshotV1::sweep_expired`）

```rust
pub fn sweep_expired(&self, now_ms: u64, retention: &RawRetention)
    -> Result<RawSnapshotSweep, GatewayError>;
```

供文件适配在导入前净化过期快照：无 I/O、不触碰任何运行状态，输入快照不被改动；先拒绝 `now_ms < committed_at_ms`（`ClockWentBackwards`），再对全部片段按 §R.4 收紧期限并推算**有效最终截止**做全量预检（含全部 `checked_add`，推算溢出整单失败 `IdentifierExhausted`），然后构建净化后的新快照。对每片段判定：

- `now >= 有效最终截止`（未固定时按原正常截止 + 当前回收时长推算并封顶硬截止，等号即过期）：**移除**。片段全部正文与事件不再出现在结果中；其**稳定片段键**、宿主事件 ID（按片段内顺序去重）与事件来源顺序最大值一并并入结果的撤销栅栏与水位——清理不回退任何栅栏，也不只收集可选宿主事件 ID。
- 正常区且 `now >= eff_normal` 但未到有效最终截止：**转移**为回收区，最终截止固定为该有效最终截止——自然回收按原（收紧后）正常截止计算逻辑回收点，不按维护时刻重给完整回收窗口；转移出的片段必然仍处于恢复期内，不会转入已最终到期片段；生命周期版本 `checked_add(1)`，溢出整单失败 `IdentifierExhausted`。
- 其余片段**保留原文并固化收紧期限**：正文、事件及生命周期版本不改写；正常截止、硬截止和已固定最终截止全部写入有效收紧值。转移分支同样保存收紧后的正常/硬截止，最终截止固定为逻辑计算值。不重给时长；后续以宽松政策重开，也不能放宽这些已落盘期限。

保证与边界：

- 维护不发执行权：结果是仍不带权限证明的快照，导入仍走 §R.2.2 完整鉴权链；不重置耗尽标志、不解除撤销栅栏、不放宽任何档内期限。
- `removed`/`transferred`/`retained` 与结果快照一致；全部片段移除时结果为仅含栅栏的零片段快照，仍可正常导入（§R.6）。
- 本接口不替代导入预检：结构损坏、域冲突、容量不足等仍在导入时失败封闭；`sweep_expired` 只按期限净化正文（语义校验与解码共享，坏档在解码即拒）。
- 典型文件适配流程：载入字节 → `decode` → `sweep_expired(可信当前时刻, 当前政策)` → 原子提交净化快照 → `import_raw_snapshot`；适配在载入与净化前对当前请求调用 `validate_raw_history_access` 完成鉴权。

### R.9 保证与限制（如实声明）

- 本批交付：无 I/O 的导出/导入契约、稳定域（含受信宿主声明的稳定凭据归属及授权修订）与当前授权映射、能力撤销/历史授权撤销的导出栅栏（宿主事件 ID、稳定片段键、来源顺序水位、耗尽标志）、稳定片段键撤销栅栏的首次导入裁决、导入/读取/维护/净化共享的有效生命周期算法、Unix epoch 毫秒时间与收紧规则（提交时间纳入完整性校验）、完整预检后原子导入、新历史句柄、重复导入幂等与规范内容指纹 CAS、导入记录条数与累计接纳预算、栅栏账本累计预算（放不下整体拒绝）、有界 v1 编解码（双向预算前置，语义坏档解码即拒）、快照过期维护 `sweep_expired`（固化保留与转移片段的有效期限）、导出编码预检（编码失败不发布键）。
- 不承诺：文件锁、崩溃原子性、断电耐久、坏档保留策略（`moe-raw-local` 步骤 3 交付）；防恶意整份旧档替换（快照可被整份伪造，鉴权在当前授权链；从未被当前权威栅栏记录过的旧正文快照无法被运行层单独识别为过期——适配必须持久化并呈现**最新**快照与栅栏）；跨运行去重；加密或物理擦除。
- 已知限制：宿主谎报时间轴无法被运行层发现；宿主所报稳定凭据归属的业务稳定性（是否真是跨重启同一逻辑凭据）及其授权修订语义（何时算撤销并换发）同样无法被运行层验证，运行层只保证"未声明即拒绝、声明即精确比对、在册凭据归属不可中途改写、一条归属同时只属一张在册凭据、修订只前进且已退役修订不可重绑"；导入记录仅存无正文的规范内容指纹与稳定键元数据（上限 64 域，仍按首导入内容字节累计 16MiB 接纳预算），判等依赖 SHA-256 抗碰撞假设；导出不包含运行局部请求序号栅栏。

## 本地原文存储

### F.1 边界与启用

- `moe-raw-local` 的运行依赖仅为 workspace 路径 `moe-agent-runtime` 与 Rust 标准库；测试另以路径 dev-dependency 使用 `moe-memory-core` 构造合成身份。适配不依赖宿主、GUI、模型或持久化实现，长期记忆日志格式不变。
- 调用方显式选择 `CreateNew` 或 `OpenExisting`，提供受信目录、当前 `TrustedIngress`/`TrustedRequest`、精确 `RawDomainKey`、当前历史许可与受信 Unix epoch 毫秒。适配通过 `RawDomainKey::from_request(&ingress, &request)` 重新计算域并逐字段比较；不从路径、快照或凭据序号推断归属。缺 hint、稳定凭据归属或当前许可时拒绝。
- API 为 `RawLocalAccess::new(runtime, ingress, request, grant, bound_domain, now_ms)`、`RawLocalStore::open(root, mode, access)`、`store.checkpoint(access, expected_revision)` 与 `store.restore(access, retention, expected_revision)`。每次操作都构造新 access 并复验；`OpenMode` 只含 `CreateNew`/`OpenExisting`。
- 不构造 Store、不调用其显式开库方法时没有原文文件 I/O。启用后只访问选定根目录下的三个固定名称，不遍历父目录或其他域：`raw-local.v1`（唯一当前快照）、`raw-local.lock`（固定锁）、`raw-local.pending`（单次提交临时帧）。目录本身由可信宿主选定；路径不得来自消息或模型输入。
- 独立 `raw-local.lock` 由 `File::try_lock` 跨进程排他占用；锁句柄在 Store 生命周期内持有。锁文件永不删除、不自动破锁。一个根目录只承载一个显式稳定域，重开时帧内域必须与当前请求及 Store 绑定域完全相等。
- Store API 不把运行时历史访问许可变成路径或档案权限。所有触碰已有原文的打开、读取、导出、净化、检查点和恢复阶段，均以 `SessionRuntime::validate_raw_history_access(SessionAccess::new(...), grant, domain)` 对当前入口和精确域重新鉴权；快照修订号、完整性校验和以及旧句柄均不授予访问权。CreateNew 仅在初始快照提交成功后固定该次 `RawHistoryGrant` 私有句柄；OpenExisting 不建立运行基线，检查点返回 `BaselineNotRestored`。
- 每次检查点既验证本次 access，也用当前 `SessionRuntime` 重新验证 Store 固定的 grant。该私有句柄把 Store 绑定到成功创建或恢复该基线的运行实例；新建空运行即使持有同域新 grant 并通过 CAS，也不能覆盖已有档案。

### F.2 独立 v1 帧格式

所有整数为 little-endian；帧无可选字段、扩展尾部或隐式 padding。文件长度上限为运行层 `RAW_SNAPSHOT_MAX_TOTAL_BYTES` 加 44 字节，长度先由文件元数据和已分配的有界缓冲检查，之后才解码。

| 偏移 | 长度 | 字段 | v1 规则 |
| --- | ---: | --- | --- |
| 0 | 8 | magic | ASCII `MOERLOC1` |
| 8 | 4 | frame version | 仅 `1` |
| 12 | 8 | CAS revision | 初始空快照为 `1`，每次成功检查点严格加一；溢出拒绝 |
| 20 | 8 | committed epoch ms | 宿主注入的 Unix epoch 毫秒；不得读取系统时钟 |
| 28 | 8 | payload length | 精确等于后续运行层 payload 字节数 |
| 36 | N | payload | `RawSnapshotV1::encode()` 的完整字节 |
| 36+N | 8 | checksum | FNV-1a 64，覆盖偏移 0..36 及全部 payload，不含 checksum 字段 |

总长度必须精确等于 `44 + N`；短帧、附加字节、错误长度、未知 magic/version、校验失败、超预算或运行层 `RawSnapshotV1::decode` 拒绝的 payload 均为坏档。不得忽略、截断、覆盖或回退到空库。解码后还必须确认 payload 的 `domain()` 等于绑定域。该校验仅发现意外损坏，不提供认证、加密或恶意篡改保护。

运行层 payload 保持其自身 `moe-raw-snapshot` v1 格式和语义；适配不复制/重写字段，不保存授权、token、密钥、会话执行权或新私有快照格式。外层 CAS revision 与 epoch、payload（其中含运行层提交时间、完整域、正文、期限、确认前缀及撤销/顺序/耗尽栅栏）整体纳入 checksum。

### F.3 创建、打开及状态

- `CreateNew` 在授权后获取锁；仅当固定锁文件、快照和 pending 均不存在时创建。锁文件使用 `create_new` 建立且之后永不删除，因此中断在首次快照前也不会被当成新空库重建。用当前运行层导出生成初始快照并以 revision 1 提交；遇到既有档案、pending 或无法确认的状态就拒绝，绝不覆盖。提交成功后固定该 access 的 grant 作为检查点基线。
- `OpenExisting` 在授权后获取锁，只读取精确当前文件。缺失返回 `NotFound`；pending 存在、坏档或未知版本均保留原文件并失败封闭；不自动删除 pending、不自动恢复其候选提交，也不创建空库。成功打开只验证档案并记录 revision/time，不代表当前运行已恢复；必须先成功调用 restore，才能检查点。
- Store 记录已验证的内存 revision 与最近持久化 epoch。调用方必须显式提供期望 revision（CAS）及宿主时间。`now_ms < committed_epoch_ms` 为时钟回拨并拒绝；提交时间不倒退，revision 使用 checked arithmetic。Store 进入 poisoned 状态后拒绝全部读写/恢复，须释放并重新打开以核对明确落盘状态。
- `CommitReceipt` 明示 revision、epoch 与耐久等级：目录同步成功为 `FileAndDirectorySynced`；目标平台没有可用目录同步时为 `FileSyncedDirectorySyncUnavailable`。后者只确认临时文件 `sync_all` 与原子替换调用成功，不声称目录项已抵抗断电。
- 没有自动备份、历史帧、永久审计正文或后台扫描。成功原子替换后，适配管理范围内只有当前帧包含正文；清理后的帧包含净化正文和必要控制栅栏，不保留旧全文副本。

### F.4 检查点与故障契约

恢复净化会把保留/转移片段的有效正常截止、硬截止及已固定最终截止一并提交；恢复成功后直接关闭也已固化更严格政策，无需额外检查点。重复导入账本改为无正文的规范内容 SHA-256 指纹及稳定键元数据，详见 [运行层契约 §R.6.4](GATEWAY.md#r64-重复导入与-cas规范内容指纹)；文件 v1 格式及提交顺序不变。

检查点只表示该次显式检查点的快照已提交；不把此前内存中的 G3 操作冒称已持久化。先鉴权、精确域/CAS/时间验证、运行层完整导出和编码预算检查，再构造完整有界帧。随后按以下次序执行：

1. 在同目录以 `create_new` 创建固定 `raw-local.pending`，写入完整帧并调用文件 `sync_all()`。
2. 使用同目录原子替换将 pending 发布为 `raw-local.v1`；不先删除当前帧。
3. 在支持的平台同步父目录；仅在此完成后更新内存 revision/epoch 并返回耐久回执。

发布前且确认未触及当前帧的校验/CAS/容量/编码失败，不改变已提交状态。pending 创建之后的写入、文件同步、替换或目录同步失败一律 poison，返回含故障阶段的 `CommitOutcomeUnknown`；保留能保留的当前/pending 文件，不发布内存 revision 或成功回执。若替换已发生但目录同步失败，磁盘可见的新帧与未确认的断电耐久性明确视为“提交结果未知”，重开依据当前文件校验，不谎称旧帧仍在或新帧已耐久。进程中断留下 pending 时，后续打开明确拒绝并保留现场；本版不提供恢复接口。

帧完整校验、运行层预算/语义验证与授权都在任何新句柄导入前完成。历史恢复顺序固定为：当前许可复验 → 读取及验证帧 → 域/CAS 时间检查 → 再次鉴权 → `sweep_expired(now_ms, retention)` → 对净化结果原子提交正文和栅栏 → 再次鉴权 → `import_raw_snapshot` 创建新历史句柄。任何一步失败都不导入未净化正文；重复导入依赖运行层精确幂等规则，不复制事件。只有导入成功后，Store 才固定本次 grant 作为运行基线；授权句柄撤销后，单独重新签发许可不会重绑 Store，须以新许可成功恢复后才可再次检查点。OpenExisting 冷开不得凭当前许可与 CAS 覆盖档案。恢复不续期、不恢复旧执行权。检查点/净化提交成功与运行层导入成功是两个不同结果，不合并成跨层事务回执。

### F.5 平台保证与威胁边界

- `File::sync_all()` 对文件生效；仅可实际支持并测试的平台尝试同步目录。Windows MSVC 目录同步能力不可用时明确跳过，不声称替换目录项已抵抗断电；文件同步和文件系统原子替换也不等同于普遍的掉电事务保证。目录同步失败则提交状态未知并 poison。
- 本 crate 的验收目标为仓库固定的 Windows x86_64 MSVC Rust 1.99.0；其它平台保证须分别实测后补记。标准库文件锁依赖底层 OS/文件系统语义，不通过删除锁文件规避占用。
- 非密码学 checksum 不抵御有意伪造；不防止攻击者整体回滚旧档，不实现 OS 主人认证、加密、RAM/磁盘安全擦除，也无法追回外部备份、文件系统快照、硬件缓存或已返回给调用方的正文。
- `raw-local.pending` 或损坏的 `raw-local.v1` 会保留并阻止打开。需要人工/未来显式恢复流程核对；本 crate 不自行选择旧/新版本。不会静默丢坏档、清除栅栏或破锁。

### F.6 验证范围

使用只含合成身份、凭据和原文的临时目录。覆盖显式创建/打开、真实父子进程冷启动正常/回收恢复、确认水位、旧句柄失效、跨进程锁、时间回拨与截止等号、坏档/长度/未知版本/半写、CAS/容量/注入故障原子性、净化后旧全文无适配副本、精确域越权/重新鉴权拒绝及重复恢复不复制。运行层集成行为缺陷不在本批写范围内；若阻碍验证，记录具体失败与对应运行层接口，不修改运行层。

## 可见运行日志

### L.1 目标与边界

本模块让获准查看者回答三个问题：后台正在做什么、哪里出错、一次运行经历了哪些步骤。它是诊断与展示设施，不是新的记忆类别、聊天原文库或执行账本。2026-10-13 经用户明确启动，首批纯内存服务已实现；本节保留完整目标契约，已实现范围及限制见本节末尾，公开 Rust API 以 [agent-runtime README](../crates/moe-agent-runtime/README.md#可见运行日志首批纯内存服务) 与 Rustdoc 为准。

- 首批仅在现有 agent-runtime 中实现标准库纯内存契约与回归，不增加 crate、依赖、HTTP 端口或 GUI 框架，不改变 R4 施工批次，也不恢复 G6–G8。
- 现有 memory-local 的追加日志承担命令持久化与重放，可能含记忆正文，不能直接当作用户可见日志读取。原文文件、运行快照、模型上下文和工具输出也不是本模块的数据源。
- 默认关闭；只有受信宿主显式配置采集策略后，才在内存中记录最小诊断元数据。采集许可不等于查看许可；查看、落盘、导出、删除和云传输分别授权，未配置就拒绝对应动作。
- 离线夹具可用合成身份和显式测试策略验证全部内存契约；不能据此宣称生产日志、桌面查看器或真实模型/渠道已经接通。

### L.2 信息分类与事件结构

类别与严重度正交；“后台消息”不等于聊天内容，“错误”也不自动等于整个任务失败。

| 类别 | 展示内容 | 典型事件 |
| --- | --- | --- |
| `Background` | 后台服务状态、阶段变化与受控提示 | 启动、等待、完成初始化、后端不可用。 |
| `Error` | 固定错误码、发生阶段、影响与安全建议 | 授权失败、版本冲突、模型不可用、写入结果不确定。 |
| `Run` | 单次运行的阶段、耗时和结果时间线 | 已受理、上下文准备、推理结束、终态登记、输出回执。 |

严重度采用 `Trace / Debug / Info / Warn / Error`；正常取消通常为 `Info`，未知结果或降级为 `Warn`，明确失败为 `Error`。崩溃用固定 `process.crashed` 事件和 `Error` 表达，不假设总能捕获崩溃。开发级别只控制详细程度，不能绕过脱敏与权限。

`LogEvent` 在完成安全投影后不可变，仅包含下列白名单字段；不开放任意 `String` 正文、任意键值属性或任意 JSON 扩展。

| 字段 | 约束 |
| --- | --- |
| `schema_version`、`event_id` | v1 模式；内部以受信宿主提供的进程日志代际、精确域和域内递增序号去重，重启不复用。对外只返回绑定获准视图的 opaque 事件别名，不输出原始序号。未知模式拒绝解析，不尝试显示原始内容。 |
| `occurred_at_ms`、`elapsed_ms` | 宿主注入的可选墙钟时间和单调耗时；无墙钟显示“时间不可用”。排序使用序号，时钟回拨不改写顺序或产生负耗时。 |
| `scope` | 经鉴权绑定的稳定桌宠实例域，或独立授权的宿主诊断域；不从显示名、当前活动角色或模型字段推导。宿主域不是“所有桌宠”。 |
| `run_id`、`step` | 宿主生成的运行关联标识和固定阶段枚举；无运行的服务消息不伪造运行 ID。外部请求 ID 不能直接成为受信关联 ID。 |
| `source`、`kind`、`level`、`event_code` | 固定来源枚举、类别、严重度和稳定事件码，例如 `agent.prepare.started`；不得让调用方自填模块路径或事件码。 |
| `message_key`、`safe_args` | 本地化模板和有界的枚举、计数、耗时参数；显示文本由模板生成，不接受模型回复、供应商错误正文或自由文本插值。 |
| `error_code`、`retry_hint` | 可选白名单错误码与“需人工确认 / 可显式重试 / 禁止重试”提示；提示不执行重试，结果未知时不得建议自动重发。 |
| `operation_state`、`transport_state`、`evidence_ref` | 分离的业务/传输观察状态与可选内部回执关联；无实际回执就没有已确认成功。关联不是授权票据，不能序列化活权限或直接跳转读取账本。 |
| `redaction` | 标明仅元数据、字段已省略或事件被拒绝；不保存被省略值。 |

桌宠实例、会话、运行和回执标识的展示使用域内 opaque 别名；真实身份仅供受信服务绑定与校验，不直接导出。不用正文或凭据的哈希充当安全别名。身份未核验的请求只能产生不含目标、账号和会话标识的固定宿主安全事件，不能猜测归属后写进某个桌宠日志。

### L.3 分层与可信接线

```text
已认证宿主调用既有服务 → 接收真实返回值或回执 → 类型化诊断事件
                                                  ↓
                                  可信归属校验、白名单安全投影
                                                  ↓
                                有界内存缓冲 / 日志健康状态
                                                  ↓
                                每次读取重新鉴权 → 只读查看器
```

- 首个实现候选放在现有 agent-runtime 的独立诊断子模块，使用标准库纯契约、策略和有界内存服务；memory-core 不依赖它，memory-local/search 不反向依赖运行层。
- 宿主在既有调用边界映射事件，不为记录日志而改写核心算法。logger 不直接访问文件、网络、系统时钟或全局活动角色；时间、代际、运行身份和许可由受信宿主注入。
- `LogEmitter` 由受信服务为精确域和运行创建，模型、Hook 输入和普通查询调用方不能构造或反序列化它。公开枚举只表示诊断数据，不构成受信身份。新事件只接受封闭类型，未知字段、控制字符和超长参数拒绝。
- `LogAccess` 由授权服务创建，绑定主体、实例/宿主域、许可类别、最高详细度、授权版本和有效期；服务对每次读取复验当前许可，不只校验查询参数。首版查看许可仅支持域、类别和详细度粒度，运行 ID 只是域内筛选条件，不授予或细分权限。重启不恢复活许可。
- 文件、终端与将来桌面壳属于宿主适配边界。首个内存实现不新建空适配 crate；若以后需要跨宿主持久化，再单独评审适配归属、依赖和磁盘格式。

首批可映射点如下；现有代码尚未产生这些诊断事件，不为尚未接通的能力虚构“已执行”记录。

| 现有边界 | 可记录的安全事件 | 不得推导的事实 |
| --- | --- | --- |
| `TrustedIngress` / 会话入口 | 受理、重复请求、受控拒绝。 | 外部字段声称的身份或跨域原文可见性。 |
| `AgentRuntime::prepare / infer / finish` | 阶段开始、阶段返回、已登记的 `TerminalState`。 | `Completed` 不代表输出已送达，也不证明工具运行。 |
| `moe-chat-app` 外部完成回调 | 业务阶段与已登记 `TerminalState`；无传输回执时传输状态只记 `Unknown`（离线请求记有据的 `NotAttempted`）。 | `ModelOutcome::Text/Failed/Cancelled` 是业务结果，不证明请求已写出、写出前失败或远端取消；不从正文推断传输状态。 |
| 记忆门面调用返回值 | 检索阶段、获准计数、健康门拒绝、受信提交回执状态。 | 记忆正文、匹配片段或仅凭调用成功推断持久化。 |
| `HookRuntime` / `write_claude_context` | 准备输出、写出尝试、实际 `HookReceipt::outcome`。 | `Written` 仅证明宿主输出传输完成，不证明 CLI 消费或外部动作完成。 |
| 宿主生命周期 | 开始、正常退出、可捕获故障。 | 无尾记录不代表成功或已取消；断电时不保证写出退出事件。 |

`write_claude_context` 的 `Err` 不等于传输 `Failed`：部分写出或 flush 失败可能已登记 `Unknown`，写出后的回执登记也可能因授权失效失败。只采信与本次调用精确关联的真实回执；无法取得回执时保持“未知/未确认”，不能按返回错误或账本最后一条记录猜测，也不能自动重发。后续取得受信回执后才更新观察状态，不覆盖原错误事件。

运行列表是这些事件的有界派生视图，不成为新的权威状态。`operation_state` 可投影为进行中、完成、失败、取消、未知；`transport_state` 独立显示未尝试、已写出、失败、取消、未知。没有终态证据显示“未确认”，重启截断显示“中断/未知”；日志缺口不能把进行中自动判为失败或成功。重放日志、点击条目或导入文件均不得提交记忆、恢复许可或触发工具。

### L.4 权限与脱敏

- 查询域由 `LogAccess` 与当前授权共同限定；共享知识库可读、桌宠换皮或拥有某个别名均不授予日志权。按获准实例隔离，禁止默认跨宠聚合、按名称合并或提供未授权存在性探测。
- 权限过滤先于检索、排序、分页、计数和运行摘要；未授权条目不能影响可见总数、搜索建议、丢失计数或导出结果。运行摘要只由当前许可允许的事件投影，不复用更高权限摘要。无日志与无权限使用不同界面状态，但拒绝信息不透露目标是否存在。
- 不收集聊天/记忆正文、模型请求和回复、隐藏推理、工具参数与输出、Header、token、凭据引用、完整 URL、文件路径、环境变量或原始堆栈。错误通过明确的类型匹配映射到安全错误码，不直接使用第三方 `Display / Debug / to_string`。
- 安全投影必须发生在内存缓冲、运行摘要、文件、终端和 UI 之前；未知错误降为固定 `error.unclassified`，不得退回原始错误字符串。脱敏失败拒收并增加域内固定计数，不先保存再遮盖。
- 查看器只消费已投影 DTO，按纯文本渲染；不执行 Markdown/HTML/ANSI、不自动打开链接或路径。`Debug` 与模块自己的错误也不得泄露原始内容。
- 授权撤销、版本改变或许可到期使既有 cursor 和后续读取失效。缓存展示采用宿主显式配置的有界查看租约，租约不能超过许可剩余有效期；服务复验成功后才允许续租，暂停滚动不暂停到期检查。宿主注入单调时间，查看器在显示及交互前检查租约；缺少租约配置或不能判定有效性时不展示缓存。
- 收到撤权/变更通知、读取拒绝、租约到期或检测到断连/无法复验时，查看器隐藏并丢弃相应域的列表、详情、摘要和索引，重新授权前不恢复展示。不依赖一定存在的推送通知：未及时检测到的撤权最迟在当前租约到期时停止展示，不承诺无通知情况下即时清屏。已被用户复制的内容不可召回，不能承诺物理擦除或撤销已交付副本。

### L.5 内存、查询与故障语义

首个版本用同步的有界环形缓冲与 cursor 拉取，不引入异步运行时或无限订阅队列。下表描述接口意图；首批 Rust API 使用调用方提供的有界输出切片，名称与具体限制见 README：

| 接口意图 | 输入与结果 |
| --- | --- |
| `emit` | 受信 `LogEmitter`、类型化事件、注入时间；返回已接收/已省略/容量拒收，不回传敏感正文。 |
| `query` | `LogAccess`、有界过滤条件、页大小与可选 cursor；返回已授权安全条目、下一 cursor 与本域缺口提示。 |
| `list_runs / inspect_run` | 相同访问上下文；只投影获准事件，并标记证据不完整，不直接读取原文或业务内部集合。 |
| `health` | 相同访问上下文；返回获准域与类别/详细度内的采集开关、缓冲状态与损失计数，不暴露其他域或高权限类别的活动。 |

- 过滤支持类别、级别、来源、域内运行 ID、时间范围和模板生成安全文本；搜索词长度、扫描量、页大小均有硬上限。查看权限不隐含全文/原始错误访问权。
- cursor 是服务生成的不透明封闭句柄，绑定进程代际、主体、授权版本、域、过滤条件、分页方向及读取高水位；不能单独授予读取权，也不暴露全局序号或未授权偏移。分页和尾随高水位只由获准分区推进，不使用同域总体水位。首版仅支持进程内句柄，不序列化；追加事件不移动历史页高水位，实时尾随另取新高水位，同一事件别名不重复展示。
- 环形淘汰或读取落后只在当前许可允许的分区存在相关历史损失时返回 `Gap`，注明缺口后才继续，不静默假装连续；隐藏分区的淘汰不能触发缺口或降级。跨代际或授权变化要求重新查询。不按内部序号差估算丢失量，只有能按当前许可精确计算时才显示数量，否则显示“数量未知”；数量未知不是放行未授权缺口提示的理由。
- 容量策略必须同时限制事件数、实际分配字节、单条大小、域数、运行摘要数、别名映射、cursor 和并发查询；索引、字符串容量和健康计数槽位也计入预算，不能只计算序列化字节。标识和计数溢出不得绕回。生产配置由宿主显式提供，缺配置拒绝启用。
- 合成夹具可显式设置最多 2048 条、合计 4 MiB、单条 2 KiB、每页 100 条与 128 个运行摘要；这些只是回归边界示例，不是批准生产采集、保留时长或后台轮询频率。
- 容量隔离单元为“精确域 × 类别 × 详细度”的固定分区；事件、索引、运行摘要、别名、损失计数和健康槽位均按相同边界计费，不能用同域共享池抵消隔离。查询及 cursor 的预算还须绑定获准查看上下文，不能被其他上下文按需占满。启用策略时预先划分全部上限，全局上限为分区预算之和；隐藏分区不得借用、抢占或挤掉可见分区预算。若将来新增运行级/字段级权限，必须先扩展隔离标签与投影规则，否则不支持该策略。
- `Trace / Debug` 在各自分区内按策略省略，旧事件只能在本分区内淘汰；错误和终态的有限预留也不得跨分区挤占。重复告警只在同一分区按固定码和有限窗口合并，保留内部首次/末次序号与次数，对外仍需权限投影。只改变同域不可见事件，不得改变可见分页、缺口、摘要或健康结果；不承诺永不丢失，也不把本设计当作消除操作系统调度/硬件计时侧信道的保证。
- 诊断写入失败不能改变实际业务返回值、撤销已成功提交、把未知改成成功或诱发自动重试。业务账本/安全审计所需的强制持久化不由本模块替代；需要这类闸门时另设权威服务。
- 日志故障通过独立固定容量健康槽位汇报，不递归写同一 logger；不得回退为向 stdout/stderr 打印原始错误。CLI Hooks 的 stdout 是协议输出，禁止混入诊断；stderr 也只在另获许可时输出安全文本。

### L.6 查看器交互规范

这里只规定只读组件与交互，不交付 GUI、绑定桌面框架或重做宠物窗口。宿主完成查看授权后才能挂载查看器。

| 区域 | 内容与行为 |
| --- | --- |
| 顶部状态与筛选 | 显示明确的当前获准实例/宿主域、采集与连接状态；提供类别、级别、来源、运行和安全文本筛选，无默认“所有桌宠”。 |
| 三个视图 | “后台消息”显示 `Background`；“错误日志”显示 `Error` 及其他类别的 `Warn / Error`；“运行记录”显示按运行分组的阶段、耗时、业务与传输双状态。所有视图复用同一数据源和授权。 |
| 日志列表 | 时间、级别文字标签、来源、安全摘要、域内运行别名；新条目只在处于底部且开启“跟随最新”时自动滚动，暂停滚动不停止有界采集。 |
| 详情面板 | 展示固定字段、错误码、安全建议与证据是否完整；允许跳转到同域运行时间线，不展开原文、密钥、原始堆栈或账本。 |
| 运行时间线 | 区分“处理完成”和“已写出”；未知/中断/缺口保持可见。收到乱序时间戳按内部服务顺序展示，耗时不可用就明确标注。 |
| 操作 | 可获准复制单条安全摘要；“清空当前视图”只清本地显示缓存，不删除服务缓冲或磁盘文件，后续查询可能重新出现。不存在“重试执行”或隐式写操作。 |

必须分别覆盖加载中、已授权但无记录、无查看权限、采集未开启、采集降级、历史缺口、已断开、许可到期和许可已撤销状态；不能用一个“暂无日志”掩盖故障。未来桌面查看器采用可虚拟化列表，沿用宿主字体/间距体系；级别用文字与图形而非仅靠颜色区分，筛选、暂停、行选择与详情关闭均能键盘操作，保留可见焦点。实时更新不抢焦点、不逐条触发读屏播报；只提供可控的新增数量提示。

虚拟化仅限制渲染节点，不能代替内存预算。宿主须为查看端另行配置条目数、实际分配字节、已加载页数、运行摘要、详情、别名和去重索引的硬上限，所有 DTO 与索引容量共同计费；缺配置不挂载查看器。持续尾随、翻页和暂停滚动均遵守上限，达到阈值按明确窗口规则淘汰最旧页及其索引/详情引用，不能为保持选中项而无限保留。暂停位置被淘汰时显示“本地历史已淘汰”，区分服务端 `Gap`，不冒充删除服务记录；重新加载仍需鉴权并受相同预算约束。

### L.7 可选持久化与导出边界

首个版本只在内存中工作，退出后不保留诊断。文件/导出接口默认不存在或返回 `NotConfigured`，不能因为已启用采集或用户点击按钮而自动获取权限。

后续若明确批准本地文件适配，写入的也只能是同一安全投影；可评审逐行 JSON 模式，但不能修改或复用 memory-local journal、G4 原文格式及运行快照。文件根、允许实例域、单文件/总容量、轮转、保留期限、读写许可与平台耐久限制须单独确定；不默认启用天数、压缩备份、自动上传或正文调试档。文件系统权限不等于加密，哈希不等于防篡改或权威执行证明。

导出与复制属于独立交付动作：重新鉴权并确认精确域、过滤范围、条数/大小和目标，只交付安全 DTO；不得顺带打包原文、快照、配置或凭据。磁盘清理需要独立删除许可与明确根/域；清屏不删除记录，删除日志也不删除记忆或业务账本，且不承诺召回外部副本。

### L.9 首批内存实现与限制

- `crates/moe-agent-runtime/src/diagnostics.rs` 提供 `DiagnosticsService`、`DiagnosticsConfig`、`LogEmitter`、`LogAccess`、`RunHandle` 与 `LogCursor`；默认关闭。启用必须提供非零且跨重启不复用的宿主进程代际、精确域、采集级别、查看主体/版本/期限及全部预算。重新配置清空旧诊断并使全部旧句柄失效，不能通过版本改回恢复许可；没有从文件恢复活许可的入口。
- 固定类别、来源、阶段、事件/错误码和安全模板在入缓冲前确定，无自由正文、第三方错误文本或任意属性。公开 opaque 别名不实现 `Hash`，避免自定义 Hasher 抽取私有域/主体偏移；服务实例使用 checked 唯一标识而非可复用裸地址。真实身份与内部顺序不通过 DTO、错误或 `Debug` 输出。
- 容量按精确域×类别×详细度预分区；事件环槽可复用，运行登记和每查看授权的别名映射是重配置前的累计额度，到限明确拒收/拒读，不承诺无限尾随。cursor 额度独立于其他主体，查询同步串行且仅支持并发预算 1；实际 `Vec::capacity`、固定结构及保守分配开销计费，不声称测量平台分配器元数据或操作系统峰值。
- `query_into` 支持类别、级别、来源、事件码、单调时间半开区间、1–96 UTF-8 字节安全模板/事件码搜索及正反向分页；搜索拒绝控制字符、ASCII 大小写不敏感，不匹配原始内容。cursor 固定获准分区高水位并绑定所有过滤条件，追加不改变历史快照，淘汰显式返回 `Gap::Possible` 而不猜测缺失数量。跨分区排序按受理顺序，内部顺序由有界分区序号在 u128 中求和生成，不增加能被隐藏分区耗尽的共享序号预算，也不对外暴露它。
- `list_runs_into` 与 `inspect_run_alias_into` 只使用当前许可内的事件及别名；业务/传输分别采用各自最新证据，没有回执即未知。可见分区的淘汰、拒收或省略均保守标记证据不完整，可能连带影响同域其他可见运行，但隐藏分区不影响该状态。运行别名可跨获准分区关联且仅在原授权视图中解析；所有读取错误清空输出切片，不发布占位别名。
- 本批没有重复告警合并、优先级预留、查看端缓存租约/缓存管理、GUI、文件、终端、导出或业务边界采集；不把合成事件当作真实 Agent、Hook 或模型执行。DTO 交付不保证既有副本即时清除，后续查看器仍须独立实现 L.4/L.6 的租约及内存上限。验证证据由 [审核记录](REVIEW.md#可见运行日志首批内存交付2026-10-13) 维护。

## Hooks 适配

### G5.1 事件、角色与数据边界

- 首个 CLI 子集为同步 command 类型的 `UserPromptSubmit`。只处理显式获准的 `session_id`、`hook_event_name`、`prompt`，其余字段仅做有界语法检查并丢弃；不打开 transcript、项目文件，不扫描终端、环境或隐藏推理。
- 事件名不能证明 prompt 是人类发言。Claude Code 2.1.286 的同一入口也可接收外部通知，且 stdin 没有可信角色标志。因此输入固定为 **UnverifiedPrompt**，不登记为 G1 用户事件，不送入 G2 用户推理入口，不转成长期证据。JSON 中的 role、owner、权限、取消或回复目标都不授信。
- 输出仅为 **InjectedContext**，不是用户发言、可见助手回复、工具回执或 CLI 已消费证明。只允许已登记且版本仍有效的受信宿主上下文，不接受模型任意自填回复正文。
- 稳定桌宠全身份、调用主体、凭据、渠道/范围及固定回复目标沿用可信入口裁决。CLI session_id 必须匹配宿主显式登记的预期值，只是与可信绑定共同使用的关联键；不能独立认证、绑定身份或去重。缺少逐事件 ID 时不按相同文本自动合并。
- 获准观察 prompt、返回上下文和允许该上下文用于 Claude 模型输入为独立许可，默认拒绝。上下文由宿主显式审核、登记来源及修订；本批不自动读记忆、不调用模型、不发网络请求、不写原文或快照，不继承全部用户查看或共享权。

### G5.2 受信服务与生命周期

- Hook 服务仅存在于运行层内存。宿主登记有界绑定及上下文，提供单调时间和期限；调用端只传 CLI 事件。绑定与调用句柄私有构造并绑定服务实例，累计签发量有界，序号耗尽拒绝。
- 每次接纳及准备输出复验当前入口凭据/配置代际、完整绑定、许可、上下文修订、期限及取消状态。授权或上下文更改使旧调用失效，不因改回旧值复活。
- 回复固定到原调用的目标和 CLI session，不改投最新会话。准备输出不是交付；宿主写出前须再次核验，写失败或状态不明不得报告 CLI 已消费。写后账本至多证明宿主输出传输完成。
- 失败、取消、超时、重复完成、跨服务句柄、撤权和迟到结果有独立回归。CLI 的取消不自动等于本服务撤权；服务取消也不能召回已交出的上下文快照或停止外部模型。
- Hooks 不借用 G4 文件格式，不增加原文落盘授权。Windows 目录断电耐久、坏档保档拒绝、外部备份与恶意有效整档回滚的既有限制保持不变。

### G5.3 实际 CLI 契约核验

- 本机 `claude --version` 为 **2.1.286 (Claude Code)**。独立只读核验包 @anthropic-ai/claude-code 的 package.json 和 bin/claude.exe；未启动真实对话或安装 Hook。
- 可执行文件共 245092000 字节，SHA256 `0b6ecec8edef1ce3069682f696c894d1553239faa6b84e56e167a3ced88fa333`。输入构造字节区间 `[211014181, 211014849)`，SHA256 `96fe342a62b9375846427d4003c3eebbbed2e83db59f07fff829dce1a1c7df68`。偏移是本机该版本的 0 起字节偏移，不适用于其它版本。
- 官方参考：[Hooks reference](https://code.claude.com/docs/en/hooks)。滚动文档不是本机版本保证：本版不适用要求 >=2.1.295 的 onFailure:block。升级 CLI 后需重新核验，不声称覆盖所有版本。
- stdin 是 UTF-8 JSON 加换行后关闭。基础字段包括 session_id、transcript_path、cwd、permission_mode、hook_event_name、prompt；条件字段可能有 scratchpad_dir、prompt_id、agent_type、session_title。本适配不要求非必要字段，也不将缺字段当作人类来源证明。
- 同步输出仅使用 exit 0 与单个 JSON 对象的 hookSpecificOutput.hookEventName=UserPromptSubmit / additionalContext 字符串。本版消费分支在 bin/claude.exe 字节位置 207860420、211023948；不得把 additionalContext 放到顶层或输出普通聊天正文。
