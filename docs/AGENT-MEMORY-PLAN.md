## 设计原则

- 项目目标是有稳定身份、人设、关系与记忆的陪伴 Agent，不是固定时间触发动作的脚本；当前离线底座仍不代表自主 Agent 已完成。
- 归属仅 private/shared：private 按稳定桌宠实例隔离，shared 是获准共阅的资料、知识、经验和能力说明。长短期是生命周期，暂存/回收是职责或状态，卡片/向量/图谱是可重建视图，不另增大类。
- 换皮不换身份；复制不默认继承私人经历。用户、平台账号、渠道会话、桌宠实例分别绑定，不按昵称或相同文字合并。
- 模型只提议，可信服务负责归属、来源、用途、版本、取消与提交。共享可读不等于可写；工具说明不授予执行权。
- 人设锚点、正式协议与工具权限受保护，不能通过普通记忆覆盖。事实、观察、推断、虚构和权威状态分别表达。
- 原文不改写；注入记忆、模型回复、工具输出与用户新证据保留不同角色，不能循环提炼成自证事实。摘要不取代权威来源。
- 私密内容及其派生不能自动洗入共享。普通发布与正式能力/协议资料是独立入口，低风险规则未定即拒绝自动发布。
- 授权先于检索排序和预算；来源纠正、遗忘、撤权、取消与版本变化须联动派生视图及迟到结果。未知结果不得冒充成功或盲目重发。
- 默认不扩大用户查看、模型传输、落盘、删除与备份范围。在线清理不等于物理擦除，也不能召回已交付副本。

## 架构与接口

```text
moe-workflow-core ← moe-agent-runtime ← moe-chat-app ← 桌面宿主
moe-memory-core   ← moe-agent-runtime
moe-memory-core   ← moe-memory-local ← moe-memory-search ← 宿主注入
moe-ui-core       ← moe-chat-app
moe-agent-runtime ← moe-raw-local / moe-cli-hooks ← 宿主
```

- 依赖单向，核心/运行层不访问文件、网络或系统时钟；时间、身份、来源及许可由宿主注入。只暴露门面、命令和只读快照，不开放内部可变集合。
- 核心零第三方依赖；memory-local 仅依赖核心。运行层的 sha2 仅计算无正文导入指纹；CLI 边界使用 serde/serde_json，均不因此授予网络或模型权限。
- 公开接口以 [workflow-core](../crates/moe-workflow-core/README.md)、[memory-core](../crates/moe-memory-core/README.md)、[memory-local](../crates/moe-memory-local/README.md)、[agent-runtime](../crates/moe-agent-runtime/README.md)、[cli-hooks](../crates/moe-cli-hooks/README.md) 与生成的 Rustdoc 为准。raw-local 的公开 API 由 Rustdoc 及 [文件契约](GATEWAY.md#本地原文存储) 说明。
- `AgentServices` 经核心 `MemoryContextAccess` 窄契约支持内存、LocalMemory 与显式注入的 SearchMemory；默认关键词不变，后端健康错误原样保留，完整读取/查询/实际发送来源均受会话许可约束。此为离线最小接线，不是生产闭环；夹具公开、职责集中和全局失效等整理项见 [审核意见](REVIEW.md#3-分级整理意见)。
- RAG 属于记忆系统内部扩展，不另建业务系统或记忆大类。已新增唯一 `moe-memory-search` 适配 crate，实现 OpenAI-compatible 在线 Embedding、Cohere v2 可选 rerank 和纯精确扫描；R2 已实现索引生命周期与混合召回，R3 已完成持久化健康门和离线 Agent 注入；R4 离线质量工程/基准已实施，本地模型与真实完整质量评估仍未验证。核心继续负责授权、版本与上下文；适配层依赖评审和精确版本见其 README，不让 Agent 反向依赖它。在线计算不要求云端存储记忆，不因配置 API Key 自动获得外传权。实施边界、依赖评审、窄接口与验收见 [RAG 方案](MEMORY.md#rag-检索扩展分批施工)。
- 不迁入旧项目 UI、动画、依赖或存档；桌面壳与渲染方案另定，不因采用 Rust 自动选定 GUI 框架。
- [可见运行日志](GATEWAY.md#可见运行日志) 经用户明确启动，已实现 agent-runtime 内的首批纯内存契约：默认关闭、独立采集/查看许可、分区硬预算、安全事件、快照分页与运行双状态投影；不同于记忆持久化日志。尚未接业务采集、缓存查看租约、桌面查看器、文件或导出，不授予额外查看/落盘/导出权，不改变 R4 或 G6–G8 的既有边界。

## 程序流程执行层

定位：只为程序标准化执行顺序和节点前后依赖，不扩成全能工作流平台、任务调度系统或 Agent 决策系统。节点决定具体业务行为，流程层只决定哪些步骤已满足前置条件、允许推进及是否停止。

- 流程由受信程序代码定义，以有实际业务含义的步骤为节点，不把每个小函数节点化，也不接受模型生成的任意可执行流程。运行实例绑定固定的定义版本，修改定义不改写在途实例。
- 第一版只做顺序与前置依赖校验、受控推进、失败停止、取消和只读进度查询。缺失/重复节点及循环依赖在启动前拒绝；前置节点未成功，不得越过执行后继。不同实例相互独立，不为统一顺序把全系统串行化。
- 内核不直接调用模型、网络、文件或工具；业务/宿主执行节点并交回结果。流程状态只反映编排进度，不替代记忆提交、消息送达或工具执行的权威回执；取消不承诺撤销已发生的操作，未知副作用结果不自动重跑。
- 只暴露定义、启动、受控推进/结果提交、取消、查询等必要门面，不开放内部集合、任意改状态或跳节点入口。结果须绑定具体实例和节点执行，重复或迟到结果不能推进错误的步骤。
- 记忆的权限、来源、版本、提交和失效仍由记忆系统裁决；Agent 的人设、决策与推理仍由 Agent 层负责。首个接入目标是包装既有离线 Agent 的 prepare/infer/finish 链，不复制或绕过其校验，不反向侵入记忆核心。
- 暂不引入并行调度、复杂分支/循环、自动重试、跨重启续跑、分布式执行、脚本/表达式引擎或可视化编辑器；需要时按具体业务另定。运行日志只接收必要进度事件，不借此新增正文查看、落盘或导出权限。
- 首版在 `moe-agent-runtime` 中交付内核和离线 Agent 包装器；2026-10-18 按用户授权将通用内核迁到独立零依赖 `moe-workflow-core`，运行层保留兼容重导出。实际聊天由应用层定义七阶段并复用已有业务门面；受信代码定义、不可变版本、执行票据与确定性顺序不变。公开入口见 [流程基础库](../crates/moe-workflow-core/README.md) 和 [运行层兼容接口](../crates/moe-agent-runtime/README.md#程序流程执行层)，跨接口语义见 [聊天流程接线](GATEWAY.md#程序流程执行层)，验收集中在 REVIEW；不自动启动其他暂停阶段。

### 流程基础库与呈现接口收口（2026-10-18，已交付）

用户明确要求流程控制成为多种上层功能可复用的底层能力，并连同此前呈现接入审查的问题开始施工。当前授权为下述三个交付块，按同一集成结果审核；不将流程系统变成模型决策、平台 I/O 或 GUI 的状态所有者。

1. **通用流程内核下沉。** 将现有纯标准库 WorkflowDefinition/Runtime/票据/进度实现实质迁移到独立 `moe-workflow-core`，零第三方依赖，也不依赖记忆、Agent、宿主或 UI。保留原 `moe_agent_runtime::Workflow*` 重导出，避免迁移迫使既有调用者改路径。业务流程定义和具体节点实现留在应用/运行组合层；不增加全局调度器、脚本、任意节点跳转、自动重试或跨重启执行。用两个独立的非 GUI 合成流程验证复用与在途隔离，不为证明复用启动新的产品功能。

## 动画编排与可视化工作台（A1 工作树审核通过，尚未集成）

用户提出的下一系统需求：参考 Unity Animator 的图式编排，动画绑定桌宠状态但不能固定为“一状态一组动画”；动作应能组合 `start / loop / end` 等阶段，并预留可视化、拖拽、连线的无限画布工作台。用户进一步确认：动画机的播放节点只对接统一 `AnimationClip`，不解释片段内部的动画类型；首版支持序列帧与 GIF，后续可扩展其他类型。2026-10-13 用户明确要求按本计划开始施工，本轮从 A0 契约定稿开始，后续 A1 仅实现纯 Rust 编排内核与无头回归。下列方向保留为设计背景，施工以本节末尾的首版冻结契约为准；没有批准素材文件格式、实际呈现端、GUI 技术或新增依赖，不迁入旧项目动画实现。

### 建议分层与状态含义

- 业务状态/意图描述桌宠在做什么，动画播放状态描述动作播到了哪里；二者不能混成一个全局枚举。行为服务仍拥有业务状态，动画只消费获准状态快照、参数与触发事件，不因动画结束就擅自完成工具任务、记忆提交或其他业务。
- 状态绑定层把状态/参数/事件映射到逻辑动作及候选变体；一个状态可对应多个动作方案，同一方案也可被多个状态复用。持续状态变化与一次性触发分开，重复同步相同状态不反复重播起手；显式重播走触发接口。
- 动画编排内核负责动作图、片段播放模式、条件转换、优先级、退出与抢占；渲染/素材适配负责实际呈现和资源处理。内核不绑定 GUI、引擎或系统时钟，时间由宿主注入，播放时序需有唯一权威；多宠各有独立运行实例。
- 与已完成程序流程执行层分开：业务流程校验前后依赖且禁止环；动画图需要合法循环及持续播放，不能直接套用其 DAG 校验，也不把循环、混合或抢占塞回流程内核。未来只在宿主业务边界连接两者，不互相接管状态。

### 统一 AnimationClip 边界（本轮方向已确认）

- 区分业务状态与动画图节点：业务状态仍绑定动作图/候选方案；图内每个播放节点只引用一个 `AnimationClip`，组合动作由节点和转换构成，不退回“一业务状态一片段”。
- `AnimationClip` 表示可复用、不可变的动画资产契约；动画机只认识受控片段引用与格式无关的播放元信息，不直接接触 GIF 字节、纹理集合、骨骼数据或原始资源路径。不要在动画机内加入随格式增长的分支或要求所有后端输出像素帧。
- 建议以 Rust `ClipPlayer` trait 作为播放后端接口，各类型适配实现负责解释片段并呈现；加载/解码与实际播放是不同职责，但首版可以放在同一个适配模块，不提前拆成多套空 crate 或通用插件平台。普通素材内容不能构造执行脚本。
- 公共播放契约建议覆盖准备/元信息、开始、宿主时间步推进、暂停/恢复、停止及只读结果；以具体播放实例关联完成、循环边界或失败，不让 Animator 理解格式细节。准确接口与暂停政策在施工前定稿，不承诺所有后端都支持跳转或混合。
- 资产与播放实例分离：帧索引、游标、速度、暂停、循环次数及本次播放标识属于实例，不写回共享 Clip。多个桌宠使用同一片段也必须独立播放；后端回报仍需绑定实例、定义版本及本次播放。
- 播放时序只设一个权威：建议播放实例按宿主注入时间步推进游标并产生边界事件，动画机仅消费结果和裁决转换，不再自己推进另一套帧时钟；后端不得同时依赖墙钟自走。退出/抢占/重复事件不能造成两个播放实例同时控制同一主体通道。
- 首版建议将序列帧与 GIF 的解码结果归一为逐帧时长明确的序列表示，复用一个序列播放实现；GIF 解码负责透明、局部图块及 disposal 合成，不只拆图或强制统一 FPS。GIF 内置重复信息最多作为导入提示/默认配置，最终本次循环模式由播放参数统一裁决，不能与动作图各自独立循环。
- 非法资源、未支持类型或能力不满足须在适当边界明确报错，不能默默跳过并报告动作成功。工作台播放节点保存 Clip 引用与元信息，资源属性面板及预览复用相应适配，不在编辑器里另写一套播放规则。以上后端细则为建议；零帧时长策略、资源预算、资源封装及首个呈现端仍需定稿。

### 建议动作图与首版边界

```text
休息状态/意图 -> 选定一个睡眠动作方案
                start（Clip A：躺下，单次）
                  -> loop（Clip B：睡眠，循环）
                       --正常退出请求--> end（Clip C：起身，单次）
                                          -> 退出/重评估绑定
```

- `start / loop / end` 是常用动作模板，不是三个必填槽或新的硬编码上限；允许无起手/无收尾、单次动作及多段衔接，后续复杂动作沿用节点与边模型扩展。
- 首版建议提供片段节点、单次/循环模式、完成/参数/触发条件与确定性转换顺序。资源引用、默认入口、端点、条件类型与循环的时间推进要可校验；有时序的合法循环可运行，无等待/无时间推进的即时转换环不能卡死一帧。
- 明确正常退出与强制抢占：正常退出可等待循环边界并播放收尾；高优先级抢占按定义直接切换或收尾，不承诺所有情况下都播完 end。起手/收尾期间的新请求同样遵守策略，同优先级冲突须确定性裁决，不能靠渲染帧率决定。
- 第一版建议先落实单个主体播放通道；多层、表情/身体叠加与混合树保留扩展方向，不提前承诺骨骼混合或任意素材间无缝过渡。首版素材范围已确认序列帧/GIF；具体封装格式、首个真实呈现适配、暂停/恢复和热切换的政策仍待确认。
- 封装建议只公开定义校验、创建实例、同步参数/触发动作、推进、停止及只读查询；素材通过受控引用，不以文件路径、自由脚本或模型文本充当执行指令。旧播放/加载回报必须绑定具体实例、定义版本与本次播放，不能推进已换动作的实例。

### 工作台预留：编辑定义，不直接改运行状态

- 分离可执行动画定义与编辑器布局：稳定节点/边 ID、片段引用、参数及条件属于运行定义；坐标、分组、缩放、选中项和视口属于编辑布局。移动节点或缩放画布不能改变运行含义；“无限画布”指可平移缩放的工作区域，不是无上限加载节点或分配内存。
- 预留节点目录/属性描述、带类型的连接端口、草稿编辑命令与图诊断结果。新增/删除节点、连线、改参数、复制及撤销/重做只编辑草稿；同一内核校验器供程序配置与将来的编辑器使用，不允许 UI 绕过验证。
- 预览使用独立、无业务副作用的实例，支持注入合成参数/事件及只读播放高亮；校验通过后发布不可变版本，在途实例不因拖拽或草稿编辑被改写。是否支持热切换、何时生效另定，不让编辑器任意覆盖执行状态。
- 画布外壳可以为其他图式工具复用，但动画图、程序流程图各自保留语义、节点类型与校验器；不为预留工作台先建通用脚本引擎。实际 UI 技术与图编辑库未选型，编辑器实现不在本轮范围。
- 将来界面至少覆盖空图引导、资源加载、坏引用/非法连线诊断、运行/暂停高亮、撤销重做和键盘选择/连线等替代操作；颜色不作为唯一状态提示。本轮不定视觉风格或设计令牌。

### 首版冻结契约（A0，2026-10-13）

本契约只裁定可离线实现的编排语义，不替用户选择桌面壳、素材许可或文件/网络政策。A1 放在现有 `moe-agent-runtime` 的独立动画模块内，不依赖或改造 `WorkflowRuntime`，不新增 crate、第三方依赖、I/O、墙钟、后台线程或全局活动桌宠。以下类型名是实现职责，不要求为了逐字匹配而增加重复包装；实际公开签名以 A1 的 README/Rustdoc 与回归为准。

#### 定义、校验与资产

- `AnimationClip` 是受信宿主登记的不可变片段描述：不透明 Clip ID、非零资产版本及正整数毫秒总时长。A1 不接受原始路径、GIF 字节或格式枚举；元信息不是已经加载或成功呈现的证明，实际后端仍须核对资产与能力。零总时长拒绝；A2 导入逐帧资源时同样拒绝零帧时长，不静默补帧或猜 FPS。
- `AnimationDefinition` 持有非零定义版本、Clip 目录、动作图、参数/触发声明及状态绑定。ID 在各自目录内唯一，引用必须存在；启动时捕获已校验的不可变定义，编辑或发布新版本不热改在途实例。宿主分别持有每个桌宠的实例，不能通过全局选中角色替换归属。
- 每个动作有稳定 ID、明确入口、优先级、抢占策略及可选收尾入口；播放节点有稳定 ID、一个 Clip 引用和 `Once / Loop` 模式。节点可转换到其他节点或显式 `Finish`；没有 `start / loop / end` 必填槽，也不为结束引入空片段。
- 普通边的条件仅有 `Completed`、`LoopBoundary`、布尔参数相等与命名触发；按边优先级降序、声明顺序升序选唯一胜者。`Completed` 只用于单次节点，`LoopBoundary` 只用于循环节点；首版不支持任意表达式、脚本、概率或混合树。单次节点无命中边时自然结束；循环节点无命中边时继续本次播放。
- 参数/触发边可以在不消耗时间的命令边界转换；校验器拒绝由这些即时边构成的任何有向环，包括不可达环。Clip 正时长且只有播放边界条件的环合法，不套用业务流程的 DAG 规则。拒绝缺失/重复 ID、坏入口/端点、未声明或类型不匹配的条件，以及不能从普通入口或收尾入口到达的节点。
- 收尾入口若存在，其可达子图只允许单次节点及每节点至多一条 `Completed` 后继，不含即时条件、循环或回到普通循环的边，最终必须到 `Finish` 或自然结束。这样正常退出不依赖未来参数/触发才能完成；普通动作可以无起手、无循环、无收尾，也可有任意数量的合法中间节点。
- A1 的硬上限为每定义 128 个 Clip、128 个动作、合计 128 个节点/512 条边、128 条状态绑定、64 个布尔参数和 64 个触发声明；各有名 ID 为非空、最多 128 字节的 ASCII 字母/数字/下划线/连字符。定义容量、计数与毫秒累加均显式检查，超限返回错误，不截断。实例最多保留一个候选动作和每个已声明触发的一份待消费标记，不维护无界事件历史。

#### 状态绑定、退出与抢占

- `AnimationBinding` 将受信业务状态 ID 与可选布尔参数条件映射到动作；同一状态可有多个候选，同一动作可供不同状态复用。候选按绑定优先级降序、声明顺序升序选择，不随机、不按渲染帧率决胜；没有匹配项表示请求当前动作正常退出，而不是非法业务状态。
- `sync_state` 更新持久状态，`set_parameter` 更新已声明布尔参数，`trigger` 是明确的一次性命令。重复状态、相同参数值和仍选中相同动作不会重播；参数变化可以重选变体。单次动作自然结束后不因下一次相同状态同步自动重启，只有选中动作发生变化或显式重播请求才新建播放。
- 状态仲裁以最近一次同步的“业务状态 ID、解析出的动作 ID 或无匹配”二元组为基准；二元组不变的同步或参数更新不参与候选替换，因此不能取消已接受的显式动作请求。二元组真正变化才用新状态意图替换唯一候选，包括覆盖显式候选或以无匹配清空候选；若新目标仍是当前动作且尚未进入收尾，撤销尚未发生的正常退出而不重播。已经进入收尾不可倒退，只能继续原链并保留最新后继。候选一旦启动即消费；显式动作自然结束且没有候选时进入空闲，不隐式恢复先前状态动作。
- 业务状态撤销/改选不能被旧动作优先级无限阻挡：它产生正常退出请求，并只保存最新选中的后继动作。正常退出在当前单次完成或循环边界发生；存在收尾则进入收尾，没有收尾则结束。已处于收尾时，任何正常退出、同优先级显式请求或 `AfterExit` 请求都只更新后继，继续原收尾链，不重新进入收尾入口、不截断中间收尾节点；有效 `Immediate` 抢占除外。自然结束或收尾完成后才启动仍有效的后继。
- 显式动作请求低于当前动作优先级时返回可区分的拒绝结果，不改正在播放或排队的动作；同优先级采用最新被接受请求替换候选并正常退出。高优先级动作按新动作声明的 `Immediate / AfterExit` 策略，分别立即抢占或等待正常退出。起手、循环、收尾期间采用同一规则；持续状态改选选中了更高优先级动作时也可按此策略抢占。
- `stop` 是独立的强制停止命令，不播放收尾、不完成业务，不承诺撤销已发生的显示或业务副作用；重复成功停止幂等。确认停止成功时清空当前播放、候选、待消费触发、未消耗时间及暂停/退出/故障标记，播放序号不回退；保留参数和最近状态二元组，因此重复同步旧状态不会自行重启。命令裁决顺序为强制停止、有效立即抢占、正常退出边界、普通边；普通边仍遵循定义内确定性排序，收尾中的正常退出已被消费，不再拦截收尾 `Completed` 边。
- 触发只作用于接收时的当前动作：同名未消费触发合并，只有选中该触发边才消费；未命中可保留到本动作下一命令边界。动作结束/替换时清空旧触发，未知参数或触发返回错误且不修改实例。新动作不能消费前一动作遗留的触发。

#### 播放后端、时间与错误

- `ClipPlayer` 是唯一播放后端边界，覆盖准备/能力核对、开始、按宿主注入毫秒步长推进、暂停/恢复、停止与只读进度。A1 只使用测试目录中的合成后端；内核不解码或绘制，不要求后端输出像素帧，不把合成后端导出为产品能力。
- `Animator` 独占一个主体通道及其后端；同一时刻至多一份实际播放。准备新 Clip 失败不能停止旧播放；开始新播放前必须取得旧播放的停止确认。停止失败或结果未知时进入故障锁定，不启动新动作或自动重发开始/推进；只允许显式再次停止以确认通道清空，成功后才可重新接受动作。
- 每次开始分配不可由调用者构造的播放票据，绑定 Animator 实例、定义版本、Clip 资产版本及单调播放序号；后端只回传本次收到的票据。与当前播放不匹配的跨播放重复/迟到结果，以及错误实例/版本/片段的结果，必须在接受其进度前拒绝；序号耗尽报错而不复用。后端方法同步返回本次调用结果，首版不开放额外的任意外部事件提交入口。票据不包含逐操作序号，不能单独识别同一循环播放内格式合法的旧推进结果重放；此范围由受信同步后端正确响应当前调用的契约保障，不宣称具备操作级防重放能力。
- 后端是唯一游标/边界时间权威，不能按墙钟自走；内核只将注入时间交给它，并消费下一完成/循环边界。推进结果须给出实际消耗毫秒数及至多一个边界；无边界时须消耗全部所给时间，边界必须消耗正时间且不能超过所给步长，循环边界不能冒充单次完成。非法结果故障锁定，不伪造动作成功。
- 同一连续编排内发生节点转换、收尾或候选接替时，剩余时间继续交给后继播放，不能直接丢弃或在两处重复计时。每次公开推进最多执行 128 次节点转换/边界处理，达到预算时返回可区分的 `Yielded` 进度并保留未消耗时间；宿主可用零增量推进继续排空。新增时间先检查待处理毫秒累加溢出，溢出拒绝且不修改实例。有限预算同时防止合法高速循环占满一帧，不将大步长截断伪装成完成。
- 时间余量只属于当前连续编排，不是全局时间存款：强制停止确认成功、无候选的自然/收尾终止，以及故障后的显式停止确认成功，均清零旧余量、候选和触发；空闲时注入的时间不存储。之后的新请求从零余量开始，`advance(0)` 不能播放停止前的旧时间。故障锁定期间不消费余量或执行候选，只有确认停止后才清理并接受新请求。节点/收尾/候选接替及未终止连续编排中的有效抢占保留余量；命令在下一处理边界生效，不承诺按墙钟回溯重排已处理时间。
- 暂停冻结后端游标及待处理时间，不积累暂停期间注入的时间；暂停时正增量推进明确拒绝，零增量仅查询，不消费旧债。状态/参数/触发仍可更新待处理意图；显式动作请求也按同一优先级及候选仲裁规则受理或拒绝，被接受时只排队，即使是 `Immediate` 也不转换、停止或启动 Clip。恢复后从原位置继续，先处理排队的有效立即抢占，再按正常边界规则处理退出；恢复本身不注入新时间。强制停止不受暂停限制，停止后清除暂停标记；暂停/恢复重复成功调用幂等，能力不满足明确报错。
- 定义/命令校验错误发生在副作用前且不改实例；开始、推进、暂停/恢复等后端错误保留原错误类型与错误链，并进入上述故障锁定。故障不等于业务失败回执、取消不等于回滚；只有确认停止解除通道占用后才可重新开始，不自动重试未知执行。只读快照报告版本、动作/节点、播放票据身份、暂停/故障/退出状态及剩余时间，不提供内部可变集合。

## UI 管理与呈现框架（U1 已交付离线范围，2026-10-14）

用户已要求按本文施工 UI 管理与呈现框架。本轮已冻结并交付 U1：标准库起步的纯 Rust 调用中心、控制器/视图组合、生命周期与有界驱动；不选择 GUI，不把无头框架记为真实界面完成，不自动启动动画 A3、U2 或其他暂停阶段。既有五套底座按记忆、API 预设、程序流程、动画编排、诊断日志计数，UI 是新增的第六套独立底座。

### 分层与 Rust 组织

| 组成 | 负责 | 不负责 |
| --- | --- | --- |
| `UiManager` 调用中心 | 面板注册、实例身份、生命周期、可见性、逻辑焦点、只读查询及统一释放。 | 记忆查询规则、预设保存、模型请求、业务事务、图编辑语义。 |
| `UiController` 控制器 | 面板用例、交互状态、调用注入的业务门面、整理展示数据与处理类型化事件。 | 绘制控件、直接访问全局面板表、替业务服务裁决权限。 |
| `UiView` 视图 | 控件、布局、输入采集、展示模型与发出交互事件；管理后端特有的视图资源。 | 访问业务存储、直接发送模型请求、持有业务服务或改权威业务状态。 |
| `UiPanel<C, V>` 面板组合 | 持有一个控制器与一个视图，按统一边界驱动、转交事件及清理。 | 再造业务服务、任意状态修改接口或通用脚本引擎。 |

Rust 不照搬可继承的 Unity 基类树：采用 trait 契约与结构体组合。控制器声明关联类型 `Model`、`Event`，视图声明同名关联类型以及后端 `Context`；组合要求视图与控制器的 `Model/Event` 完全一致。视图只借用展示模型，不能获得控制器内部状态的可变引用；临时控件交互状态可留在视图，需跨隐藏保留或参与业务判断的草稿由控制器持有。

分层关系如下，U1 公共边界按本节冻结契约实现，完整签名由 crate README/Rustdoc 维护：

```text
受信宿主 / UI 事件循环
    └─ UiManager
        └─ UiPanel<Controller, View>
            ├─ Controller → 注入的窄业务门面 → 既有五套底座
            └─ View → 当前 GUI 后端的 Context

View 发出 Event → Controller 更新 Model → 下一轮 View 呈现
Controller 发出面板导航命令 → UiManager 在安全边界处理
```

- 中心需要统一存放不同面板时，仅在内部使用满足 dyn compatibility 的 `ErasedPanel` 门面；类型化组合先验证匹配，再擦除存储。它不成为外部业务接口，不暴露 `Any` 强转、任意 JSON 消息或内部可变面板集合。
- UI 内核独立为有实质实现的 `moe-ui-core`，仅依赖标准库，不反向依赖记忆、Agent 或 GUI。具体控制器与视图在宿主及适配层组合；本轮不新增第三方依赖。
- 采用单宿主拥有的中心并显式注入访问入口，不使用全局静态单例或服务定位器。当前 GUI 框架、Web/native 方案及操作系统窗口策略均未选定。
- 语言依据为 Rust Book §18.2 的 trait object 组合方式及 Rust Reference 的 dyn compatibility 规则；不能直接把任意带泛型方法或未约束关联类型的 trait 装进统一 `dyn` 容器。

### 调用中心与身份

中心管理的是逻辑面板，不等于操作系统窗口管理器；一个逻辑面板可由宿主呈现在同一窗口的页签、区域或独立窗口，实际方案由适配层决定。

| 建议接口 | 语义 |
| --- | --- |
| `register` | 注册受信面板描述与构造工厂，返回类型化注册入口；不扫描脚本、目录或自动装载插件。 |
| `open` | 按注册入口与作用域按需创建并显示；已有可见实例时复用，已有隐藏实例时恢复，不清空草稿或重新初始化。 |
| `get`、`list`、`contains` | 返回存在性及只读生命周期摘要，不返回视图/控制器可变引用、原始聊天、记忆正文或 API Key。 |
| `show`、`hide` | 显示/隐藏已有实例；不存在时明确返回未找到，不暗中创建。隐藏不等于销毁。 |
| `focus` | 请求已有可见面板获得逻辑输入焦点；不暗中打开或显示，不冒充操作系统已前置。 |
| `close` | 请求允许关闭后释放实例；可能返回需确认，不把用户取消当关闭成功。关闭不是仅隐藏。 |
| 宿主清理入口 | 退出、所属桌宠删除或受信上下文撤销时强制失效并释放；不伪装成业务撤销或事务回滚。 |

- `PanelKey` 由面板种类和作用域组成。首版每个 key 只允许一个实例；应用级面板与桌宠级面板区分，同一种面板可以分别属于桌宠 A 与 B。作用域绑定稳定身份，不随全局选中宠物改变；标识仅用于定位，不授予权限。
- 首版不支持同 key 任意多开，不加通用窗口分组、持久布局或跨进程服务。确有多开需求再增加实例维度，而不是把任意字符串当临时身份。
- `PanelHandle` 由当前中心签发并绑定本次实例。关闭后重开产生新句柄；旧句柄不得命中新实例或转为按 key 猜测路由，中心不永久保留所有已关闭实例。
- 面板特有入参通过注册入口的类型化 `OpenArgs` 交付，不能设计万能字符串字典。已有实例收到新的入参时由控制器明确处理，不默认把新入参覆盖成重置；没有入参的普通重复打开保持原状态。中心内部类型擦除不取消入口的编译期类型检查。
- 相同面板重复 `open` 不隐式抢焦点；宿主确需打开并聚焦时显式组合两步。查询展示的是逻辑状态，不保证操作系统已经绘制像素。

### 生命周期、焦点与草稿

首版只保留 `Visible`、`Hidden` 两种存活可见性；未创建/已销毁由实例不存在表达。业务加载态是控制器模型中的 `Loading/Ready/Empty/Error`，不与面板生命周期混成一个全局状态机。准备或清理失败单独返回错误并记录必要健康状态，不把失败强写成已显示/已关闭。

```text
不存在 ─ open ─→ Visible ⇄ Hidden
                    │        │
                    └─ close ┴─→ 不存在
```

- 首次打开：创建控制器与视图、核验上下文、完成宿主侧挂载与显示约定，再登记可用实例。构造失败不留下半注册实例；后续挂载失败须走清理，清理亦失败时保留最小失败记录供宿主继续释放，不自动报告成功。
- 隐藏：暂停仅服务于可见界面的订阅/刷新，失效在途展示加载；保留允许保留的草稿与本地交互状态。显示后重新核验授权与数据时效，按需刷新，不能把旧缓存视为长期许可。
- 关闭：控制器先决定是否需要处理未保存草稿。需要确认时返回可区分结果，由宿主交互并在确认后显式继续；不能默认丢弃或自动保存。允许关闭后，失效展示任务、取消订阅、释放视图资源及控制器。重复关闭旧句柄返回未找到/已失效，不影响重开的新面板。
- 强制清理可绕过草稿确认，但仅用于明确的宿主生命周期，不能借关闭按钮扩大删除范围。首版关闭即释放，不另加 keep-alive 策略、自动缓存池、LRU 或 GC；需要保留就使用 `hide`。
- 隐藏或关闭当前焦点面板时，中心清除该焦点，宿主负责把输入焦点移交至仍可见的合理目标；不留下不可见控件接收快捷键。键盘可完成聚焦与关闭，后端保留清晰焦点指示；加载、空、失败及可重试状态不得只靠颜色区分。

### 事件、异步与既有系统边界

- 中心、控制器与视图在宿主 UI 事件线程串行驱动，不给每个控件套 `Arc<Mutex<_>>`。工作线程只经宿主的有界命令/结果通道提交消息，不直接操作 GUI 或面板可变引用；UI 内核不选择异步运行时或启动线程。
- 一次驱动分开处理：交付已就绪业务结果与既有输入、更新模型、展示并收集新事件、处理事件、最后应用面板导航命令。新展示模型最迟下一轮呈现；回调不能递归调用中心修改正在遍历的面板集合，也不反复驱动直到队列清空。宿主明确每轮事件/导航预算及剩余命令语义，不能静默丢失保存、删除等关键意图。
- 可见性变化、关闭、作用域切换或刷新替换会失效对应 UI 加载票据。返回结果至少核对面板实例与本轮加载序号，旧请求不得覆盖新刷新，也不得复活已关闭面板；以面板专属的类型化事件交回结果，不开放通用反射消息总线。
- UI 加载票据只防止陈旧展示，不能替代业务服务的来源、权限、版本与提交复验。关闭面板不等于撤销已经提交的保存、模型调用或工具执行；是否继续业务任务由所属服务和宿主明确决定。
- 所有权限在业务服务收口。UI 不直接修改记忆容器、预设仓库或动画运行实例；隐藏按钮、作用域名称、持有面板句柄都不等于授权。撤权或所属身份失效后清空敏感展示缓存，不以保留草稿为由保留不再允许查看的正文。
- 视图模型仅包含当前展示需要的数据，API Key 默认只显示脱敏信息，不放入中心查询、通用事件、日志或可复用展示快照；敏感编辑值也不能进入诊断正文。真实日志查看仍须满足其已有授权和缓存失效契约，不因创建日志面板默认获准查看。
- 普通单面板错误保留阶段、具体错误及 source，宿主可继续驱动其他面板；不吞错误、不自动无限重开或重试业务副作用，也不承诺捕获 panic/进程崩溃。诊断接线仅在获准且启用时发送既有安全事件，日志失败不改变面板业务结果；UI 不依赖诊断服务才能运行。
- 程序流程层不接管每次点击或绘制；动画机不承担按钮/面板生命周期。未来无限画布只是一个具体面板，其控制器管理编辑草稿，视图管理画布交互，调用既有图校验与发布接口；不把图编辑规则塞进 UI 核心，不借此启动 A3。

### U1 冻结契约

- `UiManager<Context>` 由单宿主持有；`UiController` 关联 `OpenArgs/Model/Event`，`UiView` 关联 `Model/Event/Context`，`UiPanel<C, V>` 编译期约束模型和事件一致。`register` 接收受信描述与工厂，工厂同时接收中心生成的不可变 `&PanelKey` 与类型化入参，返回与 `OpenArgs/Event` 绑定的类型化入口。控制器据实际 key 固定作用域，不以可变入参或全局选择代替归属；普通修订不能改绑定。中心内部可做安全类型擦除，但公共 API 不提供 `Any`、反射或可变面板引用；回调不能获取中心可变引用。完整具体签名在 crate README/Rustdoc 随实现维护。
- `PanelKey` 区分应用级与稳定桌宠身份作用域。首次 `open` 需要类型化入参；重复普通打开不重建、不重置草稿、不抢焦点，新入参交原控制器。`show/hide/focus/close/get/contains` 只按中心签发的实例句柄定位，跨中心、错误注册入口和已释放句柄均拒绝，不能退回按 key 路由。中心身份由独占令牌保证，不依赖全局单例、时钟或调用者不重复的整数。
- 宿主显式配置非零注册容量、同时存活实例容量、输入/导航队列容量与每轮事件/导航预算。尚未成功释放的资源计入容量；释放完成即归还额度，计数溢出明确报错。查询只返回有界生命周期/健康摘要，不含模型、入参、事件或凭据。不保留历史累计实例、事件或无限失败列表。
- 工厂失败不登记实例。挂载/首次显示失败必须清理；清理也失败则保留可枚举、可由宿主重试释放的失败记录和资源，不冒称已显示/已关闭。回调报错保留阶段及原始 `Error::source` 链，单面板失败不阻断其他面板；失败清理记录不可渲染、聚焦或接收事件。不承诺捕获 panic。 同一 `PanelKey` 在失败释放记录中仍保留资源占用；创建前返回含 key/重试编号的 `PendingReleaseForKey`，释放成功后才允许重开，其他 key 不受影响。
- 隐藏保留允许保留的草稿，清焦点并失效加载；恢复重走控制器核验/刷新边界。关闭确认绑定实例及当前交互版本；后续事件、新入参或加载结果改变控制器后，旧确认不得丢弃新草稿。未确认/取消不释放；强制清理标明宿主退出、身份删除或上下文撤销等原因，不伪造业务回滚。撤权时宿主必须立即移除敏感展示并清理缓存。
- 加载票据绑定中心、实例与最新加载序号。新加载、可见性改变、关闭/释放使旧票据失效；入队及实际分发前均复验，隐藏面板不接收展示输入/结果。队满将未接纳的类型化原始负载交还调用者，视图采集和控制器导航同样显式反馈背压，不静默丢失保存/删除意图。 序号前进或耗尽时立即移除已失效的票据化负载，普通输入和当前有效结果不被清除；失效加载不再占据队列或阻止普通关闭。
- `drive` 串行交付既有输入/结果、更新模型、渲染并收集输入、在剩余预算内处理新输入，最后执行导航。回调只提交受控导航，不递归修改中心；事件/导航有每轮硬预算，剩余项保留至后续轮，不循环驱动到队空，执行前复验实例/票据。报告与队列有界；公共查询不能泄露业务正文。
- 输入预算跨注册和同注册的不同实例轮转，持久保存下一实例位置；一个持续失败或持续补充输入的实例不能无限饿死其他可见实例。完整渲染阶段先于新输入分发；仅输入/导航的执行有硬预算，不承诺限制受信回调内部的执行耗时。
- 新入参修订在调用控制器之前保守失效旧加载票据和关闭确认，即使回调返回错误也不恢复旧票据。修订已成功而导航队满时不改报业务失败；导航拒绝经原命令返回值由控制器保留，仅重交未接纳的导航，不重复执行已经成功的业务修订。
- 每个资源释放步骤独立追踪完成状态：卸载失败即使控制器释放成功也仍保留资源/容量，重试不重复已成功的控制器释放。恢复挂载后的卸载失败须隔离至待释放记录，不得重新挂载或继续交互。作用域撤权须在资源卸载前独立清除该作用域的存活实例和既有待释放记录中的敏感缓存，包括内核持有的已接纳输入与加载结果负载，不因先前清理失败而遗漏；所有失败保留可检查的具体错误链。
- U1 不接业务门面、诊断采集、查看缓存租约、真实 GUI、文件、网络、时钟、线程或异步运行时。无头测试视图只留测试目录，不导出合成面板冒充产品。U2 需另行明确启动、选定真实宿主/面板/依赖；动画 A2/A3、G6–G8 与 R1/R4 真实门状态不变。

交付状态：原型已实现并完成 Windows 限定验收；当前集成副本的前端检查、宿主回归和 Rust 全链门通过，真实 Tauri/WebView2 聊天、关闭取消、托盘事件、宠物隐藏/恢复与正常退出通过。逐像素穿透、身体点击、拖动及实际帧变化有 120 DPI 真窗证据；真实 IME、混合 DPI、托盘图标点击/菜单弹出及非 Windows 平台尚未验收。原型可用于后续选型，尚不宣布全平台迁移门通过，详细证据与短时资源基线见 [原型审核](REVIEW.md#tauri-选型原型交付2026-10-17)。

- 宿主职责：透明无边框宠物窗 `pet`、聊天窗 `main`、托盘显示/隐藏/暂停/退出、Windows 光标命中与穿透、DPI/位置适配和资源释放。逐像素命中使用有界 alpha 网格，不能用宠物矩形冒充；穿透时依然须可靠检测光标重新进入。隐藏停止绘制并降低活动，退出停止工作线程和计时驱动。
- 业务接入：复用 `ChatApplication` 离线模式，提供草稿、发送、聊天关闭确认/取消与撤权；取消关闭不称为取消模型请求。该类型含 `Rc/RefCell`，由固定线程持有，通过有界队列处理命令，不使用 `unsafe impl Send/Sync`，不为 Tauri 修改核心依赖或公开内部状态。错误只返回安全码与固定消息，业务失败后的实际快照仍须刷新。
- 动画接入：Rust `Animator` 与一个内置序列帧 `ClipPlayer` 适配拥有时序与暂停状态，宿主注入单调时间；前端只按帧索引呈现预生成画面。禁止前后端同时自行推进动画时钟。每帧保持相同轮廓以便首版复用单一 alpha 网格；正式可变轮廓、GIF 及外部资源包不在原型合同内。
- 前端职责：Vue 呈现聊天、明确的离线标识、发送/错误/撤权状态与关闭确认；中文组合输入不触发发送，Shift+Enter 换行。宠物窗使用缓存 Canvas 帧，提供点击打开聊天与拖动，DPR 改变后正确重绘；不自行生成聊天回复或复制业务权限规则。
- IPC 冻结：`prototype_snapshot()` 与 `prototype_dispatch({ command })` 返回 `{ snapshot, error }`；snapshot 为 `{ revision, presentationRevision, mode, revoked, chat: { draft, messages: [{ role, text }], status, failure }, closeConfirmation, closeIntent }`，error 为 null 或 `{ code, message, disposition }`；closeIntent 为 close_chat/quit_application/null。command 使用 `kind` 标签：`set_draft` 带 text、`send`、`hide_chat`、`close_chat`、`confirm_close` 带 discard、`revoke`，读取及派发均仅 main 窗可调用；来源拒绝仅返回安全错误，不附聊天快照。事件 `prototype://snapshot` 使用同一返回结构且只定向发送 main。前端严格使用冻结结构，不增加裸快照兼容分支。IPC 等待业务结果不得阻塞窗口线程，宿主执行失败/队列满与未确认完成明确区分。
- 窗口与绘制 IPC：`prototype_window({ command })` 接受 `show_chat`、`hide_chat`、`show_pet`、`hide_pet`、`toggle_pause`、`start_dragging`、`quit`。main/pet 可请求显示/隐藏与暂停，拖动仅 pet，quit 仅 main；原生托盘复用相同操作。显示宠物必须真正恢复 pet 窗，不借隐藏聊天冒充。关闭主窗按业务关闭确认处置，确认后隐藏主窗；退出另保留退出意图，取消保留草稿且取消退出，确认后完成进程退出。隐藏中的确认须恢复可见入口；撤权清场后仍可关闭/退出。`prototype_set_hit_mask({ width, height, alpha })` 仅 pet 可调用，单通道 alpha 整数数组，宽高各不超过 256、长度严格匹配。`prototype_frame()` 及事件 `prototype://frame` 返回 `{ frameIndex, paused, faulted }`；帧数、帧长及总时长来自 Rust/TypeScript 共用素材描述，当前夹具为四帧、每帧 200ms。两个窗口只载入同包静态资源，以窗口 label 选择页面；不加载远程页面、不开放通用文件/命令执行或 HTTP 权限。只授予必要事件监听及解除权限，释放失败不能静默伪装已释放。
- 依赖评审：宿主新增 Tauri 2 稳定版（已查 2.12.4）及 tauri-build 2 稳定版（2.7.3），MIT/Apache-2.0、最低 Rust 1.90，满足仓库 1.99；启用必要窗口/托盘能力，序列化与代际随机数复用已有版本。前端采用 Vue 3.5.44、Tauri API 2.12.4/CLI 2.12.3、Vite 8.3.4、plugin-vue 6.0.10、TypeScript 5.9.3、vue-tsc 3.3.13 的兼容稳定组合，直接版本固定并纳入锁文件。现有 Node 22.23.2 满足 Vite/plugin-vue 所需 22.12 以上版本；不采用查询返回的 Tauri 3 alpha 或无必要升级其他依赖。最终锁文件保留原有全部依赖版本，新增 299 个包身份（包含同名不同版本）；serde/core/derive 维持原有 1.0.229。
- 验收：前端类型/构建与针对性测试、宿主 IPC 来源/预算、实际聊天链、关闭取消、撤权清场、alpha/DPI 换算及暂停释放回归，再执行仓库全链门。真窗检查透明边缘、背景穿透和身体交互、托盘、拖动、IME 与实际帧变化，记录 CPU/内存基线。缺真实多屏或其他系统时逐项标为未验证，不以模拟几何替代真机验收。跨端正式迁移须依据原型结果另行决定。

### 跨端选型建议

原有验证宿主只支持 Windows，图形经 GDI `RoundRect`、`Ellipse`、`LineTo` 绘制，字体请求 ClearType；字体平滑不等于几何图形抗锯齿。源码能说明锯齿的可能来源，本轮没有像素对照定位用户看到的具体瑕疵。新原型使用 WebView 呈现；内置像素合成猫只作为播放/命中夹具，不据此宣称全部素材锯齿已解决。跨端问题应在宿主与呈现层解决，业务语言继续使用 Rust。

在尚未明确手机或网页为首批目标时，按 Windows 优先、兼顾 macOS/Linux 评估：

| 候选 | 适合本项目的部分 | 代价与取舍 |
| --- | --- | --- |
| **Tauri 2 + Vue 3 + TypeScript（领队建议）** | Rust 宿主调用已有应用门面；Web UI 适合聊天、管理表单及后续动画图编辑器，宠物播放可独立使用 Canvas/WebGL 适配。 | 新增前端构建工具链；系统 WebView 不同，透明合成、输入法、DPI、穿透及分发均需逐平台验收。Vue 是组件组织的工程选择，React 也可实现同样能力，不是抗锯齿或桌宠能力的决定因素。 |
| Flutter + Rust | 桌面与移动 UI 共用路线清晰，自绘组件风格一致。 | 新增 Dart 与 Rust 绑定；桌宠窗口、穿透、托盘仍需原生插件或适配。若移动端成为同等优先目标，应重新比较该路线。 |
| Rust 原生跨端 UI（如 Slint） | 界面与业务可更多使用 Rust，避免引入 TypeScript。 | 须评估复杂画布编辑器、组件生态、平台窗口能力和所选依赖许可；不能只因现有业务是 Rust 就直接选定。 |

建议的责任分工：Vue/TypeScript 只处理呈现与用户输入；受限命令、事件与快照适配把它接到 Rust 应用；已有记忆、身份、授权、预设、会话与业务回执继续由 Rust 服务裁决。`moe-ui-core` 仍管理逻辑面板，不承担操作系统窗口。序列帧/GIF 的实际渲染单独实现 `ClipPlayer` 适配，现有 Animator 保持动作仲裁权；不在前端复制第二套业务或动画状态机。

窗口初始化与 GDI 绘制不能直接复用到跨端宿主。现有网络、持久化适配可按职责提取复用，仅平台路径、事件循环与宿主装配需要相应调整；不重写已有记忆和原文存储。宿主命令要验证窗口/实例归属、业务许可和版本，前端传入 petId 或拥有 IPC 权限不等于获得业务授权；凭据不进入通用快照与日志。

官方能力核验与原型门：

- Tauri 的 [窗口配置](https://v2.tauri.app/reference/config/#windowconfig) 有透明背景，[窗口 API](https://v2.tauri.app/reference/javascript/api/namespacewindow/#setignorecursorevents) 提供整窗忽略鼠标事件；这不是已经交付逐像素命中。原型必须证明透明处可穿透、身体和菜单可操作，并能在鼠标离开/重新进入、拖拽和弹层期间可靠恢复命中。
- [系统托盘](https://v2.tauri.app/learn/system-tray/) 通过 `tray-icon` feature 提供，官方说明 Linux 不发出该页所列托盘鼠标事件；不能把 Windows 的左键/悬停行为照搬为全部平台合同。[WebView 版本说明](https://v2.tauri.app/reference/webview-versions/) 明确 Windows 使用 WebView2，macOS 使用 WKWebView，Linux 使用 WebKitGTK；前端相同不代表呈现与系统能力相同。
- 获批后首个原型只验证 Windows：透明边缘、逐像素穿透与交互、多屏混合 DPI、中文 IME、托盘隐藏/重开/退出、序列帧播放、空闲降帧和资源释放；接一条现有应用聊天/取消/撤权链。可用合成资源与离线模型，不依赖真实用户存档或云凭据。登记内存、GPU 和闲置 CPU 基线，再约定产品预算。
- Windows 原型通过后再逐项确定 macOS、Linux X11/Wayland 支持矩阵；未验证能力保持待定。手机和网页可复用部分界面及契约，但桌面悬浮、托盘和全局穿透没有直接等价语义，Rust 业务在网页端的服务/WASM 承载也需另定。各平台构建、依赖许可、安装包、签名及升级路径随目标平台评审，不由 UI 框架自动解决。

### D 阶段接口与分工

- 已将旧桌面宿主真实 `storage` / `transport` 实现及其针对性测试迁至 `crates/moe-desktop-adapters`，两个宿主复用；不是另造记忆格式或聊天引擎。只使用已锁定的现有依赖版本，不增加第三方依赖种类。核心、运行与应用不得反向依赖这个 I/O crate。旧 Win32 入口仅调整导入，不继续扩展其 UI。
- 共享适配保留 `storage::root/open_application/load_settings/save_settings` 与 `transport::start/Reply` 的现有签名，并提供 `storage::open_application_at(root: &Path, generation: u64, now: u64)`、`load_settings_at(root: &Path)`、`save_settings_at(root: &Path, settings: &ModelSettings)`；返回类型与无 `_at` 版本相同，`open_application_at` 同样读取设置但强制恢复为未获准外传。显式路径允许宿主选择数据根和测试使用合成临时档案，不授予前端任意文件访问。默认沿用已有 daily 数据根和留存政策；启动/恢复失败明确拒绝，不降级覆盖为空档。
- Tauri HostWorker 是应用唯一所有者。系统 epoch 与单调增量由宿主注入；网络只拿不可变输入和本次凭据，通过有界回交加原 `ExternalRequestTicket` 完成。等待时窗口和托盘继续响应；退出不谎称在途外部操作取消。原有 closeIntent、presentationRevision、三态 disposition、快照主窗专属及动画进度门保持。
- 共用原 `prototype_dispatch({ command })` 和原 envelope；所有新增业务命令只允许 `main`，在宿主校验类型/字节/来源后排入原有有界队列。新增命令：`open_panel { panel }`、`hide_panel { panel }`（panel 为 `presets | memory | diagnostics`）；`configure_model { endpoint, model, persona, allowTransmission, apiKey }`；`select_preset { id }`；`remember { text }`；`search_memories { query }`；`update_memory { id, revision, text }`；`delete_memory { id, revision }`；`refresh_memories`；`refresh_diagnostics`。对应既有 Action / configure_model，不能绕过应用门面。字段采用以上确切大小写，内层 Rust serde 显式匹配。
