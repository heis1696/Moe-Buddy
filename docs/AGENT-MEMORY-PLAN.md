> 日期：2026-10-10。用户已确定使用 Rust，并授权开始封装实现。M0–M5 已实现；M4 验证结果见 §10，M5 离线链路及验证见 §11，后续上下文精进验收见 §12。未接真实模型，记忆底座不代表完整 Agent 已交付。
> 历史确认依据：`docs/archive/pet-assistant/docs/AGENT-MEMORY-DISCUSSION.md:349`。候选规格：`docs/archive/pet-assistant/docs/AGENT-MEMORY-SPEC.md:1`。归档路径约定见 `docs/archive/pet-assistant/README.md:1`。

## 1. 已确认原则

- **private / shared 两类归属**：private 是各桌宠独有的身份、用户认知、关系与经历；shared 是获准共同查阅的资料、知识、经验和能力说明。
- **稳定实例身份**：不以外观包或显示名充当 owner；换皮不换身份，复制不默认继承私人经历。
- **归属、生命周期与内容性质分开**：长短期不新增大类；用户陈述、观察、推断、虚构和权威状态不可混为一个可信度分数。
- **模型提议，服务提交**：来源、权限、版本、取消和持久化都通过后才生效，不能靠模型自填 owner 或自称权威。
- **核心受保护**：人设锚点、正式协议与工具权限不接受普通记忆覆盖；记忆里的工具说明不授予执行权。
- **派生视图可重建**：实体卡片、摘要和索引不能反向制造证据；纠正或删除来源时联动失效，迟到任务不得复活内容。
- **共享发布有闸门**：规则明确的低风险经验可以自动发布；含私事或规则未定的候选不默认放行。

## 2. 新仓库与旧方案的差别

Moe Buddy 从空仓库开始，不先搬旧 UI、固定触发器、动画栈或生产 memory-service，也不复制旧项目 package.json 和依赖树。

旧草案中的“保留旧入口、兼容旧档、逐步切换生产权威写入”不再是首版前置工作。未来如需导入旧存档，另开明确范围，先解决归属、证据、敏感度与恢复策略，不能直接把旧数据绑定当前桌宠。

记忆与 Agent 核心采用 Rust，使用 Cargo workspace；先做自己的薄契约，暂不绑定 LangChain、Letta、Mem0、向量库或图数据库。Rust 的内存安全与类型检查不能替代来源、运行时权限、版本和取消校验。

首个持久化适配优先考虑本地版本化文件，序列化依赖和格式在 M1 明确。跨平台原子替换、写盘顺序、失败恢复必须实现并验证，不能仅因使用 Rust 或 rename 就宣称具备事务保证。

核心不依赖桌面壳；当前不选择 Tauri、原生 GUI 或其他渲染方案，也不把旧 Electron/Node 的依赖规则带入新核心。后续宿主通过明确接口使用核心。

## 3. 分批施工

### M0：纯契约、策略与隔离夹具（已完成）

- 已建立最小 Cargo workspace，固定 Rust 1.99.0，不安装 GUI、模型或数据库依赖。
- 仅有 `crates/moe-memory-core` 一个库 crate，封装身份、来源、内容候选、版本、回执、纯策略与内存存储。完整提议/审批工作流和运行代际尚未实现，不能据普通写入方法宣称模型可以直接提交。
- crate 根仅导出公开门面与输入/只读快照类型；内部模块和存储集合私有。宿主绑定实例后，CRUD 输入不能更改 owner、scope 或保护等级。
- 时间逐次由受信宿主注入，ID 由服务内的确定性单调计数器分配；此时不承诺跨重启稳定。模型不接触来源登记或绑定身份的根入口。
- 已验证跨宠/跨用户/跨工作区隔离、同文不碰撞、受保护类别拒绝、共享只读与私密来源不能洗入共享夹具。
- 已有预期版本检查、源版本失效、过期过滤、普通敏感度禁止降级、删除后迟到更新拒绝与默认 Debug 正文脱敏；这些不是 M3 全生命周期交付。

验收：编译、格式、Clippy 与测试通过；不接生产模型、不迁移数据、不引入持久化后端。接口与可运行示例见 `crates/moe-memory-core/README.md:1`。双实例夹具不意味着已交付多宠窗口。

### M1：来源与版本化持久化（已完成）

在核心之外建立 Rust 运行与存储适配，核心只暴露必要接口；具体 crate 划分按该批需求决定。建立单写入协调、来源依赖、版本比较、操作幂等与回执；权威写盘成功后再发布。覆盖磁盘失败、坏档、重启、乱序提交和重复操作，不能静默丢档或假报成功。

### M2：授权读取与实体视图（已完成）

区分当前会话工作上下文与长期记录，二者都受归属和用途约束。先授权过滤，再相关性和预算选择；身份视图受保护，实体卡片只聚合获准且有效的来源。缓存依赖记录/来源/策略版本，失败可退回条目级检索。

### M3：纠正、遗忘与取消闭环（已完成）

定义替代、有效期、过期、归档与删除的不同语义；处理派生闭包、在途任务、撤权和恢复。检索不可见不代表物理清理完成，备份和外部副本边界要如实报告。

### M4：共享资料与受控发布（已完成）

实现普通共享经验候选与正式能力/协议资料的不同入口。发布根据实际读取集、来源与权限裁决；不能由模型漏报来源洗成共享内容。低风险规则未定时，不启用自动发布。

### M5：最小对话接线与端到端验证（已完成，仅离线夹具）

接入受信运行身份、获准上下文和模型候选，验证读取、提议、提交、纠正与共享的最小链路。模型或索引失败仍需可解释降级，不宣称执行成功。桌宠 UI、持续行动循环、任意工具执行与旧档导入另定范围。

现以 OfflineFixture 合成候选完成上述链路，宿主审查后注入实际提交时间并立即提交，索引降级保留真实读取集，模型失败无候选/无成功回执。原始证据纠正独立于模型派生，历史回执只确认不执行。端点/传输未定，不默认联网，不以 OfflineReasoning 冒充 ModelTransmission。详见 `docs/MEMORY-M5.md:1`。

## 4. 首批边界与后续决策

M0–M5 按批次完成，不借记忆施工扩大模型、共享、UI 或存档迁移权限。用户随后授权精进记忆系统，本批仅推进「获准上下文装配与受控压缩」：复用真实任务读取集，优先保留身份及正式资料的预算，对摘要保留原始来源并复验取消/版本；不创建 M6，不改变既有持久化格式。具体契约见 `docs/MEMORY-CONTEXT.md:1`。

本批以核心接口、本地适配、离线回归和文档为完整边界；不实现会话原文留存、长期学习晋升、技能执行、自改代码或自动共享。没有明确获批的后继施工阶段，实际模型端点/传输、行动层、UI 与存档迁移仍需另定范围。

待明确：允许的模型端点与传输用途、用户查看范围、可演化人设字段、保留/备份策略、低风险共享规则。离线契约和夹具可以先做，但这些政策未定时不得扩大相关权限。

本次精进的完整验收另记 §12，不将本批上下文压缩记作长期学习或技能自进化。

记忆底座是 Agent 的必要基础，不代表自主目标、计划、工具调用和反馈循环已经交付。先把“记得对、拿得对、改得对、忘得掉”做成可验证的契约，再讨论行动层。
